    Design an In-Memory File System

    15 sections · 1,958 words

    LLD Design Problems, problem 16 of 20.

    The Ask

    Build

    • A tree of nodes rooted at /.
    • Two kinds: a File (bytes, a size) and a Directory (named children).
    • mkdir(path) — makes the missing parents too.
    • writeFile(path, s) creates or appends; readFile(path) returns content.
    • ls(path): a file gives its name, a dir gives child names sorted.
    • rm(path), mv(src, dst), find(dir, name).
    • Paths: split on /, handle ., .., a trailing slash, absolute vs relative.

    Skip

    • Real disk blocks, inodes, a block allocator.
    • POSIX permission bits and ACLs.
    • Symlinks and hard links.
    • Concurrency and locking.
    • Persistence to disk, mmap.

    Our Model

    One root, all in memory. A FileSystem facade holds a Composite tree of FsNodes: a File carries bytes, a Directory carries a sorted map of children. A Path is split once and folded from the root.

    Actors and classes

    • Shell — fs: FileSystem, cwd: Directory; run("mkdir /a/b"), run("ls /a") call fs.mkdir(abs(cwd, arg)). cwd only matters for a relative path.
    • FsNode (abstract) — name: String, parent: Directory; isDir(): boolean, size(): long, path(): String (walks parent to /), accept(FsVisitor v).
    • File — data: StringBuilder; read(): String, append(String s), size(): long (data.length()).
    • Directory — children: TreeMap<String, FsNode>; child(name): FsNode, link(n), unlink(name), names(): List<String> (keys already sorted).
    • Path (value) — raw: String, absolute: boolean, parts: List<String>. Split on /, drop "" and .; .. stays a part, popped on the walk.
    • Resolver — walk(Directory from, Path p): FsNode; parent(Path): Directory (for create ops). . stays on cur, .. sets cur = cur.parent ?? root, else cur = dir.child(part). A File mid-path -> NotADirectory, a missing name -> NoSuchPath.
    • FileSystem (singleton, factory) — root: Directory (the / node), quota: QuotaPolicy; resolve(String path): FsNode, mkdir(String path): void, ls(String path): List<String>, writeFile(String path, String content): void, readFile(path): String, rm(path, recursive): void, mv(src, dst): void, find(dir, name): List<FsNode>. Every op calls resolve first; builds File / Directory by kind.
    • NodeRef (value) — parent: Directory, name, node; so rm / mv re-link in O(1).
    • FsVisitor (interface) — visitFile(File f), visitDir(Directory d). A new traversal, node classes untouched. FindByName, DiskUsage, TreePrinter.
    • QuotaPolicy (interface) — checkWrite(Directory dir, int addBytes); called inside writeFile / mkdir, throws when over. NoQuota, PerDirByteCap, MaxDepth, MaxChildren.
    • FsError — fail loud, a bad path never returns null: NoSuchPathException (name gone), NotADirectoryException (file mid-path), DirectoryNotEmptyException (rm, no -r), InvalidMoveException (dst inside src).

    Relationships

    A Directory owns 0..* children; a File and a Directory are both an FsNode. FileSystem owns one root.

    Key operations

    1. resolve(String path): FsNode — splits on /, folds from the root. . stays put, .. goes to the parent clamped at /. Throws NoSuchPathException for a missing name, NotADirectoryException when a File sits mid-path.
    2. mkdir(String path): void — the same walk, but it creates every missing directory (mkdir -p). A name already held by a File is a collision, so it throws. Idempotent on a directory that exists.
    3. ls(String path): List<String> — a file path returns just its own name. A directory path returns its child names sorted. O(children) — the TreeMap is already ordered.
    4. writeFile(String path, String content): void — resolves the parent, creating it if missing, then creates the File or appends to it. size grows by the bytes added.

    The path walk

    • part "" -> cur = / (root); part "a" -> cur = /a child; part "b" -> cur = /a/b child; part "file.txt" -> File, return.
    • at /a/b part ".." -> cur = /a (parent).
    • ls "/a" -> [ "b", "c" ] sorted keys.
    • ls "/x.txt" -> [ "x.txt" ] for a File path.

    Recall drill: cover the operations column, write the four with their guarantee. Most people forget ls on a file path returns a one-element list, not the file's content.

    The One Run to Hold in Your Head

    Resolve /a/b/../c/note.md from the root. Walk it: root, then a, then b, then .. pops back to a, into c, then the file. Which nodes did you touch, and what does ls /a/c return?

    The Change

    They ask for ln -s. Add a SymlinkNode, a third FsNode kind holding a target path. When resolve meets one it restarts the walk from the target and counts hops — past 40, throw ELOOP. File and Directory do not change. Composite absorbs the new kind.

    What the Picture Can't Show

    The cost of mv. In a Composite tree it re-links one pointer and every path underneath is still right, because a node's path is computed by walking parent, never stored. Key a flat map by full path instead and the same mv rewrites every descendant key.

    If They Make You Code It

    Resolve, mkdir and ls, the whole thing:

    class FileSystem {                                   // one root, all in memory
    final Directory root = new Directory("", null);

    FsNode resolve(String path) {
        Directory cur = root;                        // path is absolute
        String[] parts = path.split("/");
        for (int i = 0; i < parts.length; i++) {
            String p = parts[i];
            if (p.isEmpty() || p.equals(".")) continue;
            if (p.equals("..")) {                    // clamp at /
                cur = cur.parent != null ? cur.parent : root;
                continue;
            }
            FsNode next = cur.children.get(p);
            if (next == null) throw new NoSuchPathException(path);
            if (i == parts.length - 1) return next;  // leaf node
            if (!(next instanceof Directory))
                throw new NotADirectoryException(p); // mid-path
            cur = (Directory) next;
        }
        return cur;                                  // path was "/"
    }

    void mkdir(String path) {                        // mkdir -p
        Directory cur = root;
        for (String p : path.split("/")) {
            if (p.isEmpty() || p.equals(".")) continue;
            if (p.equals("..")) {
                cur = cur.parent != null ? cur.parent : root; continue; }
            FsNode n = cur.children.get(p);
            if (n == null)
                cur.children.put(p, n = new Directory(p, cur));
            if (!(n instanceof Directory))
                throw new NotADirectoryException(p);
            cur = (Directory) n;
        }
    }

    List<String> ls(String path) {
        FsNode n = resolve(path);
        if (n instanceof File) return List.of(n.name);
        return new ArrayList<>(
            ((Directory) n).children.keySet());      // sorted
    }
}

    The Four Hazards

    1. rm on a non-empty directory. Recurse and free the subtree, or refuse without -r. State the choice: rm(path, recursive). One unlink from the parent map drops everything below. Plain rm on a dir with children throws DirectoryNotEmptyException; rm -r unlinks the node.
    2. mv a dir into its own subtree. mv /a /a/b/c makes a cycle and orphans the tree from the root. Walk dst's parent links up; if you pass src, throw InvalidMoveException. Also block mv onto a name that is a non-empty dir.
    3. ".." at the root. /.., /../.., ../x from /. Clamp every .. to cur.parent ?? root. Never let cur go null, never model a parent-of-root.
    4. Trailing slash / empty component. /a//b, /a/b/, "", /. Normalise once in the splitter: drop "" and .. Then ls("/a/") equals ls("/a"); a name that is already a File mid-path is a NotADirectoryException.

    Name them before they are asked.

    The Three Lines They Are Watching

    1. p.isEmpty() || p.equals(".") — a trailing slash, // and /./ all collapse to nothing, never a blank child name.
    2. .. sets cur to parent or root — you never walk above / and never null-deref.
    3. !(next instanceof Directory) mid-path throws — you cannot descend through a File.

    How to Represent the Tree

    Approach Lookup /a/b/c ls a dir mv / rename a subtree A node's own path Hard links Extra memory
    Composite tree of nodes (the default) O(depth) walk O(children) re-link one pointer walk parent up refcount by hand one object per node
    Flat map by full path O(1) get O(all keys) + prefix filter rewrite every descendant key it is the key already awkward a full path string per node
    Inode + dirent tables O(depth) over dirents O(children) dirents re-link one dirent walk dirents up fall out for free an inode + a dirent per name

    A Composite tree of node objects. mv and rename are one pointer swap, ls is local, and a node never stores its own path so nothing goes stale. Reach for inode + dirent only when the brief adds hard links or on-disk layout.

    Rejection Signals

    These end the interview:

    • One Node class with an isFile flag plus both a children map and a content field — a file can sprout children.
    • ls hands back children in insertion or hash order — the spec asks for sorted names.
    • resolve splits on / but never handles ., .., // or a trailing slash.
    • .. at the root null-derefs parent instead of clamping to /.
    • mv /a into /a/b is allowed — the subtree becomes a cycle, unreachable from the root.
    • Walking through a File mid-path returns null silently instead of raising NotADirectoryException.

    Patterns Used

    Composite — the File / Directory tree; a Directory treats every child as an FsNode. Iterator / Visitor — find, du and a tree print walk the tree without touching the node classes. Strategy — a swappable QuotaPolicy, or a pluggable path-resolution rule. Factory — FileSystem builds a File or Directory from a kind.

    Say It Like This

    "One root Directory, held by a FileSystem facade. Every node is an FsNode with a name and a parent; a File carries bytes, a Directory carries a sorted map of children — that is Composite. resolve splits the path and folds from the root: . stays put, .. is the parent clamped at /, anything else descends one child, and a File mid-path is an error. mkdir is the same walk that creates what is missing. mv and rename re-link one pointer; find and du are Visitors over the tree."

    The Follow-ups That Decide It

    1. Resolve /a/./b/../c. Walk it. . stays, .. pops b, land on /a/c.
    2. mkdir /x/y/z with /x missing. Creates x, y, z in one walk — mkdir -p.
    3. ls a file path vs a directory path. File -> [name]; dir -> child names, sorted.
    4. rm a directory that still has children. -r unlinks it and drops the subtree, else DirectoryNotEmptyException.
    5. mv /a /a/b/c. Reject: dst sits under src, found by walking parent up.
    6. ".." from /. Clamp to /; never null-deref the root's parent.
    7. find /a "*.txt" over a deep tree. A Visitor / Iterator; the node classes do not change.
    8. "Add a per-directory byte quota." A QuotaPolicy checked in writeFile; the tree is untouched.

    Deliberately Not Built

    • Real blocks / inodes / an allocator — content is a StringBuilder, size() is its length. Name the on-disk layout and move on.
    • POSIX permission bits and ACLs — an owner plus a mode checked on every op. One of the two ghosts.
    • Symlinks and hard links — a third FsNode kind, or a shared child pointer with a refcount. The other ghost; needs a loop guard.
    • Concurrency and locking — one lock on the tree, or a lock per directory. A different question.
    • Persistence — serialise the tree, replay it on start. Name it, move on.
