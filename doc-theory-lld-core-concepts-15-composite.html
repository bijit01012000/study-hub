    Composite

    11 sections · 841 words

    Structural · Design Patterns · Pattern 06 of 12

    Intent

    Treat one object and a whole tree of objects the same way, so an operation like size() or render() is written once against a shared component interface.

    When To Use It

    The Signs

    • Code that branches: if (n instanceof Leaf) ... else recurse over children.
    • You want to treat one object and a whole group of them the same way.
    • A tree: files and folders, a UI, an org chart, nested menus.
    • An operation like size() or render() reimplemented per level.

    Don't Bother If

    • The structure is flat, never nested.
    • Leaves and groups genuinely need different call sites.
    • There is no shared operation to push down.
    • A plain recursive function over one node type reads fine.

    Before

    long totalSize(Node n) {
    // a free function
    if (n instanceof File)
        return ((File) n).bytes;
    long sum = 0;
    // else it's a Dir
    for (Node c : ((Dir) n).children)
        sum += totalSize(c);
        // recurse by hand
    return sum;
}
// every operation re-writes this instanceof + recurse:
// path(), countFiles(), find() each repeat the ladder

    Branch on the type.

    After

    interface FsNode { long size(); }

class File implements FsNode {
    private final byte[] data;
    public long size() { return data.length; }
}

class Directory implements FsNode {
    private final Map<String,FsNode> children = new TreeMap<>();
    public long size() {
        long s = 0;
        for (FsNode c : children.values()) s += c.size();
        return s;
    }
    void add(String name, FsNode n) { children.put(name, n); }
}
// root.size(): the same call on a file or a whole tree

    Or a giant node with an isDir flag:

    class Node {
    // one class, an isDir flag
    boolean isDir;
    byte[] data;     // only when it's a file
    List<Node> kids; // only when it's a dir
}
// nothing stops a File from getting kids,
// and a File still carries an unused kids list

    Structure

    «INTERFACE»
FsNode
    + size(): long
    + path(): String
    one call, file or tree

Directory
    - children: Map<String,FsNode>
    size() loops its children
    0..* children
    realizes

File
    size() = data.length
    LEAF

        /
       bin/
       a.txt
    bin/ is a Directory too
    ls, cp

A GROUP OF FsNodes IS ITSELF AN FsNode

    How It's Built (3 Steps)

    1. One Component interface with the operation(s) every node supports: size(), path().
    2. Leaf implements them directly. File.size() just returns its own byte count.
    3. Composite holds List<Component> (or a Map) and implements each operation by looping its children and combining the results.

    Quick Check

    Ask "is a group of these things also a thing of the same kind?" If a folder is usable wherever a file is, that is a Composite.

    In The Interview

    "FsNode is the component. File is a leaf, Directory is a composite that holds FsNodes. size() and path() work the same on both, so the caller never asks what kind of node it has."

    How It's Different

    From The Lookalikes

    Vs a plain recursive fn. Over one node type you keep an instanceof ladder. Composite splits leaf and branch into their own classes, so a new node kind is just a new class.

    Vs Decorator. A Decorator is a chain of wrappers around one object, each adding behaviour. A Composite is a tree of many child objects, all treated as one.

    Vs Visitor. A Visitor adds a new operation across an existing Composite without touching the node classes. Composite is the shape the visitor walks.

    Vs Iterator. An Iterator gives you a flat sequence over a Composite. Composite is about applying an operation in place, recursively.

    They Say: "now add a symlink"

    • With it: one new SymlinkNode implements FsNode. The tree walk and every operation are untouched.
    • Without: a new branch in every instanceof ladder, in every operation.

    Watch Out For

    • Where do add / remove live? On the Component (uniform, but Leaf must throw) or only on Composite (safe, but callers cast). Pick one and say so.
    • Guard against cycles: moving a directory into its own subtree. Check the destination is not a descendant.
    • Parent pointers make path() and remove() easy but must be kept in sync on every move.
    • A deep tree can blow the call stack. An explicit stack or queue makes traversal iterative.
    • Caching an aggregate (total size) on the Composite needs invalidation up the parent chain on every change.
