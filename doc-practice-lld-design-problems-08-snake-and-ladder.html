    Design a Snake and Ladder Game

    15 sections · 1,932 words

    LLD Design Problems, problem 08 of 20.

    The Ask

    Build

    • A board of N cells, default 100.
    • Some cells carry a jump: a ladder up or a snake down.
    • A ladder and a snake are one edge, only the direction differs.
    • K players, a fixed turn order, round-robin.
    • Each turn: roll 1..6, advance the token, resolve a jump if you land on one.
    • Win on reaching cell N.
    • The die is swappable: standard, loaded, two dice.
    • Live position and a move log for the display.

    Skip

    • GUI, animation, the board render.
    • Network multiplayer, reconnection.
    • Betting or scoring variants.
    • Non-linear board geometry.
    • Save / resume, a database.

    Our Model

    One game, a board of cells, jump edges. Players sit in a round-robin queue; a turn is roll, move, jump, check.

    Actors and classes

    • Referee — game: Game, players: List; run(): Player loops game.playTurn(next) until WON.
    • Game (turn orchestrator) — board: Board, queue: TurnQueue, die: DiceStrategy, state: GameState (RUNNING -> WON), winner: Player; playTurn(Player p): int, start(), currentPlayer(): Player. Computes to = board.move(p.pos, die.roll()).
    • Player — name: String, pos: int (0 = off); moveTo(int cell), position(): int.
    • TurnQueue — q: Deque<Player>; peek(): Player, rotate(), add(Player), remove(Player). A drop-out just leaves; no reindex.
    • Board — n: int = 100, jumps: Map<Integer,Integer>, cells: Cell[1..n]; move(int from, int roll): int, jumpFrom(int cell): int, hasWon(int pos): boolean; jumps built and checked by a BoardFactory.
    • Cell — index: int; winning(): boolean (index == n), at(int i): Cell (made once, reused).
    • Jump — start: int, end: int; isLadder(): boolean (end > start), isSnake(): boolean (end < start); direction is the sign of end - start.
    • Move (value + command) — player: Player, from: int, roll: int, landed: int, jumped: boolean; replay(Game g): void — the turn as data.
    • DiceStrategy (interface) — roll(): int (1..6, the only randomness, takes a seed for tests). StandardDie, LoadedDie, TwoDice.
    • MoveObserver (interface) — onMove(Move m): void; MoveLog, ConsoleView, ReplayRecorder (an append-only list of Move; every observer gets the same Move).

    The die rules

    • StandardDie -> 1 + rand(6).
    • LoadedDie -> weighted faces.
    • TwoDice -> sum of two rolls, 2..12.

    Land exactly or bounce

    This sheet bounces back off 100, and resolves one jump per turn.

    Key operations

    1. playTurn(Player p): int — rolls the die, moves p, records the Move, checks the win, and rotates the queue unless p just won. Returns p's new cell. The only method the Referee calls.
    2. move(int from, int roll): int — adds the roll, applies the overshoot rule (this sheet bounces off N), then resolves at most one jump. Pure; it reads the jump Map and returns, it never touches a Player.
    3. jumpFrom(int cell): int — jumps.getOrDefault(cell, cell), one hop. A ladder that ends on a snake's head leaves you on that head, not further. O(1).
    4. hasWon(int pos): boolean — pos == N. Exact by construction, because move() can never return more than N. The signal for playTurn to stop rotating the queue.

    win when pos == N; jump when jumps.containsKey(next). next = from + roll; if next > N: next = 2N - next; return jumps.getOrDefault(next, next).

    The One Run to Hold in Your Head

    A player is on cell 3 and rolls a 4. She lands on 7, the foot of a ladder to 14. Next turn she is on 98 and rolls a 5. What cell is she on after each turn, and which objects touched the move?

    pos 3 + roll 4 -> 7 = ladder foot -> 14. pos 98 + roll 5 -> 103 > 100 -> 200 - 103 -> 97.

    The Change

    They ask for "land exactly on 100", "roll a 6 to start", "roll again on a 6", or "bump the token you land on". Pull these off the turn loop into a RuleSet the Game consults each turn: move() asks how to resolve an overshoot, playTurn() asks whether the roll repeats. Strategy, a second time on this sheet.

    What the Picture Can't Show

    The turn loop. A Referee calls playTurn on the Game once per player, round and round, until state is WON. Nothing here is a thread. The die is the only randomness and it takes a seed, so a finished game replays move for move.

    If They Make You Code It

    playTurn and move, the whole thing:

    class Game {                                     // the turn orchestrator
    final Board board;                           // cells 1..N + jump Map
    final TurnQueue queue;                       // round-robin, K players
    final DiceStrategy die;                      // std / loaded / 2 dice
    GameState state = RUNNING;
    Player winner;

    int playTurn(Player p) {
        int roll = die.roll();                   // 1..6 - the seam
        int from = p.position();
        int to = board.move(from, roll);         // overshoot + jump
        p.moveTo(to);
        log.onMove(new Move(p, from, roll, to)); // Observer
        if (board.hasWon(to)) { state = WON; winner = p; }
        else queue.rotate();                     // head player to the tail
        return to;
    }
}

class Board {                                    // cells 1..N + jump Map
    final int n;                                 // 100
    final Map<Integer,Integer> jumps;            // start -> end

    int move(int from, int roll) {
        int next = from + roll;
        if (next > n) next = 2 * n - next;       // bounce off N
        return jumpFrom(next);                   // resolve ONE jump
    }

    int jumpFrom(int cell) {
        return jumps.getOrDefault(cell, cell);   // one hop
    }

    boolean hasWon(int pos) { return pos == n; }
}

    The Four Hazards

    1. Overshoot at the end. from + roll can pass N. Pick one rule and use it everywhere: bounce back off N, land exactly or forfeit, or just cap at N. This sheet bounces.
    2. A chained jump. A ladder to 80, and 80 is itself a snake's head. One hop only: getOrDefault is applied to the cell you rolled onto and nowhere else, so you rest on 80. Chasing it transitively can cycle and never matches the physical board.
    3. Extra turn on a 6, unbounded. House rule: roll a 6, roll again. With no cap, 6 after 6 never yields the turn. Bound it: two 6s then move and pass, or three 6s and the whole turn is void. Count consecutive sixes in playTurn; past the cap, rotate the queue anyway.
    4. Two tokens on one cell. Both tokens share the cell. In the base game that is fine — no interaction. Only add a bump if asked: the token already there goes back to its start, which still terminates.

    Name them before they are asked.

    The Three Lines They Are Watching

    1. board.move() runs the overshoot rule then one getOrDefault — bounce off N, then at most one jump.
    2. jumpFrom is one hop — a ladder that ends on a snake's head is not chased further this turn.
    3. queue.rotate() runs only when nobody won — the winning roll is the last thing that happens.

    Storing the Jumps

    Approach Lookup Build Cell state Snake vs ladder Memory
    int -> int Map (the default) O(1) getOrDefault loop over pairs none, it is an int sign of end - start one entry per jump
    Cell[] + jump field (array of nodes) O(1) cells[i].jump alloc N cells, set jumps cell can hold more sign of end - start N cells always live
    Snake / Ladder list (polymorphic edges) O(n) scan, or index it new per snake / ladder state on the edge two subclasses object + vtable per jump

    int -> int Map. O(1) lookup, the build is a loop over pairs, and a jump is one entry. Go to Cell[] only when a cell carries its own state; reach for Snake / Ladder classes only when the two need different behaviour, which the base game never gives them.

    Rejection Signals

    These end the interview:

    • Chasing jumps transitively — a ladder into a snake head loops, or lands where the physical board never would.
    • 1 + rand.nextInt(6) written inline — the die cannot become a loaded die or a seeded test die.
    • Separate Snake and Ladder classes with identical bodies — a jump is one edge, direction is a sign.
    • Extra turn on a 6 with no cap — three sixes and the turn never ends.
    • No overshoot rule stated, or two code paths that disagree — the token walks off the end of the board.
    • The board built with no validation — a snake on cell N, or a jump off the board, surfaces mid-game.
    • Turn order as an index into a list that shifts when a player leaves — the wrong player moves next.

    Patterns Used

    Strategy — the die, and (page 2) the house-rule set. Factory — builds and validates the board and its jumps. Observer — the move log and the display follow the token. Command — a Move records a turn you can replay.

    Say It Like This

    "A board is cells 1 to N with a Map of jump edges — a ladder goes up, a snake goes down, the same thing with the sign flipped. Players sit in a round-robin queue. A turn is: roll a swappable die, add it to your cell, bounce back if you passed N, then one getOrDefault to resolve a jump. Reach N and you win. The die and the house rules are strategies, so a new variant never touches the turn loop."

    The Follow-ups That Decide It

    1. Player rolls past cell N. Bounce off N here; or land-exactly, or cap — state it once.
    2. A ladder ends on a snake's head. One hop; getOrDefault runs once, you rest there.
    3. Roll a 6 — does the player go again? House rule; cap at two sixes so the turn terminates.
    4. Two tokens on the same cell. Both stay; add a bump only if asked, resident to start.
    5. Loaded die, two dice, an 8-sided die. A new DiceStrategy; the turn loop is untouched.
    6. "Cell 100 needs an exact roll." An overshoot rule in the RuleSet; move() asks it.
    7. A snake on 100, or a ladder off the board. Factory validates: start 2..N-1, end 1..N, start != end.
    8. Four players, one quits mid-game. Remove from the TurnQueue; round-robin closes the gap, no reindex.

    Deliberately Not Built

    • GUI and animation — the token hop is a render concern. The model returns the new cell and stops. Another layer.
    • Network multiplayer — turns over the wire, reconnection, anti-cheat. A transport around playTurn, not a model change.
    • Betting and scoring variants — stakes, points, elimination. A RuleSet on top; name it and move on.
    • Non-linear boards — branch tiles, two-way warps, loops. The jump Map already teleports; richer geometry is a bigger question.
    • Save and resume — serialise the queue, the positions and the RNG seed. One snapshot object.
