    Sharding and Consistent Hashing

    4 sections · 449 words

    Splitting data across servers and routing keys reliably.

    1. Why Shard

    A single server has a fixed capacity (the example uses RAM 32 GB and HD 1 TB). As the number of users grows (0-100 users in the picture), the DB tier must be split across servers s1, s2, and so on.

    A sharding key decides which shard a row goes to. A simple range scheme:

    Shard Range
    DB1 0-30
    DB2 31-60
    DB3 61-100

    This is horizontal scaling of the database.

    2. Hash Methods - the Modulo Operator

    Instead of ranges, a hash function maps a key to a shard:

    • A hash function takes any datatype and returns an integer: hash(datatype) = integer.
    • Examples: hash("Hello") = 1234, hash(43) = 4567, hash(true) = 790.
    • Then % n maps the integer into 0 ... n-1.

    Example with 3 shards:

    Key hash(key) % 3 Shard
    key0 0 DB1
    key1 1 DB2
    key2 2 DB3
    key3 3 % 3 DB1

    The hash can scale to 1 billion keys, and SHA-1 is one candidate hash.

    Limitation: with plain modulo hashing, when the number of servers changes, DB migration is very high - most keys get remapped.

    3. Consistent Hashing

    Consistent hashing fixes the mass-migration problem by placing both servers and keys on a hash ring (for example 1-100).

    • Servers hash onto the ring: DB1 at 1/100, DB4 at 75, DB2 at 25, DB3 at 50.
    • Keys hash onto the ring: hash(key0) = 11, hash(key1) = 41, hash(key2) = 65, hash(key3) = 80.
    • A key is stored on the first server encountered clockwise from the key's position.
    • Adding or removing a server only moves the keys in the affected arc, so standard deviation is minimised.

    Limitations:

    • Uneven distribution of keys.
    • Celebrity problem (hotspot key problem): one key (for example a celebrity) gets far more traffic than others.
    • hash(X) must be a good hash function.

    The uneven-distribution case is shown with a high standard deviation: keys such as key4: SRK, key5: Virat Kohli, key6: Ronaldo, and key7: Modi land on the same shard because a hot celebrity key skews the load.

    4. Virtual Nodes

    Virtual nodes are replicas of the original nodes. By placing many replicas of each server (DB1_1, DB1_2, DB2_1, DB2_2, and so on) around the ring, keys are spread more evenly and the standard deviation drops from HIGH to Low.
