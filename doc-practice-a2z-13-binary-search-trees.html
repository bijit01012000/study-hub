    1. Binary Search Tree Fundamentals

    Problem. What defines a Binary Search Tree (BST), and what property makes it useful over a plain binary tree?

    Input: n/a (conceptual)

    Output: BST invariant: left subtree < node < right subtree, recursively; inorder traversal is sorted ascending

    • A BST is a binary tree with an ordering invariant: for every node, all values in its left subtree are strictly less than the node's value, and all values in its right subtree are strictly greater - applied recursively to every subtree, not just the root.
    • The immediate payoff is search: because the invariant tells you at each node whether a target lies left or right, you discard half the remaining tree at every step, giving O(h) lookup where h is the height - O(log n) for a balanced tree versus O(n) for an unordered binary tree.
    • A defining consequence used constantly downstream: an inorder traversal of a BST visits values in sorted ascending order - many BST problems reduce to "do the sorted-order thing" (kth element, validate, two-sum, recover) precisely because of this.
    • Most standard BSTs assume distinct keys; duplicates require an explicit convention (e.g. store counts, or always insert equal keys to one side) and are called out per-problem when they matter.

    Time: N/A | Space: N/A

    BST Invariant (Theory)

    Conceptual - no implementation.

    2. Search in a BST

    Problem. Given the root of a BST and a target value, return the subtree rooted at the node whose value equals the target, or null if no such node exists.

    Input: tree = [4,2,7,1,3], target = 2

    Output: subtree rooted at node 2, i.e. [2,1,3]

    • Walk down from the root comparing the target to the current node's value: equal means found; if the target is smaller go left, if larger go right - the BST invariant guarantees the target can only live on that one side, so you never branch.
    • Because each step drops to a single child, this is a plain iterative loop (no stack, no recursion needed) that terminates when it either lands on the target or falls off the tree into null.
    • This exact descend-by-comparison skeleton is the reusable core of nearly every BST operation - insert, delete, floor/ceil, LCA all start by walking down this same way and only differ in what they do at each step.
    • O(h) time where h is the tree height (O(log n) balanced, O(n) for a degenerate skewed tree), O(1) space for the iterative version.

    Time: O(h) | Space: O(1)

    Iterative Descend-by-Comparison

    public TreeNode searchBST(TreeNode root, int val) {
    while (root != null && root.val != val) {
        root = val < root.val ? root.left : root.right;
    }
    return root;
}

    3. Minimum and Maximum in a BST

    Problem. Given the root of a non-empty BST, find its minimum and maximum values.

    Input: tree = [8,3,10,1,6,null,14]

    Output: min = 1, max = 14

    • The minimum is the leftmost node: from the root, keep following left children until one has no left child - the BST invariant guarantees nothing smaller can exist off to the right of any node on that path.
    • The maximum is the mirror image: keep following right children until one has no right child, since every right step moves to a strictly larger value and there's nothing larger once the right pointer is null.
    • Neither operation needs to inspect values or compare anything - it's pure pointer-following, which is why both are O(h) with no extra bookkeeping.
    • These leftmost/rightmost walks are themselves reused elsewhere: the leftmost-node walk is exactly how delete finds a node's inorder successor when replacing a two-child node.
    • O(h) time (one descent), O(1) space (iterative).

    Time: O(h) | Space: O(1)

    Leftmost / Rightmost Walk

    public int findMin(TreeNode root) {
    while (root.left != null) root = root.left;
    return root.val;
}

public int findMax(TreeNode root) {
    while (root.right != null) root = root.right;
    return root.val;
}

    4. Ceil in a BST

    Problem. Given the root of a BST and a key, find the ceil of the key - the smallest value in the BST that is greater than or equal to the key (return -1 if none exists).

    Input: tree = [8,4,12,2,6,10,14], key = 5

    Output: 6

    • Walk down from the root: if the current node's value equals the key, that's the ceil exactly and you can stop; otherwise decide which way to go by comparison.
    • If the current value is greater than the key, it's a valid ceil candidate - record it, then move left to try to find an even smaller value that's still >= key; if the current value is less than the key, it can't be the ceil, so discard it and move right seeking larger values.
    • The key insight is that you provisionally save each "greater-than-key" node as you descend and keep tightening it by going left - the last such saved value when you fall off the tree is the tightest ceil.
    • O(h) time (single descent), O(1) space.

    Time: O(h) | Space: O(1)

    Candidate-Tracking Descent

    public int findCeil(TreeNode root, int key) {
    int ceil = -1;
    while (root != null) {
        if (root.val == key) return root.val;
        if (root.val > key) {
            ceil = root.val;
            root = root.left;
        } else {
            root = root.right;
        }
    }
    return ceil;
}

    5. Floor in a BST

    Problem. Given the root of a BST and a key, find the floor of the key - the largest value in the BST that is less than or equal to the key (return -1 if none exists).

    Input: tree = [8,4,12,2,6,10,14], key = 5

    Output: 4

    • This is the exact mirror of Ceil: walk down from the root, and if a node's value equals the key it's the floor immediately.
    • If the current value is less than the key, it's a valid floor candidate - record it and move right to hunt for an even larger value still <= key; if the current value is greater than the key it can't be the floor, so discard it and move left.
    • The last recorded "less-than-key" value when you fall off the tree is the tightest floor - same candidate-tightening descent as ceil, with the comparison directions flipped.
    • O(h) time (single descent), O(1) space.

    Time: O(h) | Space: O(1)

    Candidate-Tracking Descent (Mirrored)

    public int findFloor(TreeNode root, int key) {
    int floor = -1;
    while (root != null) {
        if (root.val == key) return root.val;
        if (root.val < key) {
            floor = root.val;
            root = root.right;
        } else {
            root = root.left;
        }
    }
    return floor;
}

    6. Insert into a BST

    Problem. Given the root of a BST and a value, insert the value as a new leaf so the BST property is preserved, and return the root. Assume the value is not already present.

    Input: tree = [4,2,7,1,3], val = 5

    Output: tree = [4,2,7,1,3,5] (5 attached as left child of 7)

    • Reuse the descend-by-comparison walk from Search: go left when the value is smaller, right when larger - the invariant guarantees there is exactly one null pointer where the value belongs, and you never need to restructure existing nodes.
    • The clean iterative form tracks the current node and stops when the next step would go off the tree; you then attach the new node as the appropriate (left or right) child of the last real node visited.
    • A common subtlety: you must remember the parent when the child pointer becomes null, since that's where the new node hangs - the recursive form sidesteps this by returning the (possibly new) subtree up and letting each caller re-link its child.
    • Insertion always creates a leaf; it never needs rotations or moves, which is what keeps it O(h).
    • O(h) time (one descent to the insertion point), O(1) space iterative (O(h) recursive).

    Time: O(h) | Space: O(h)

    Descend to Null, Re-link Child

    public TreeNode insertIntoBST(TreeNode root, int val) {
    if (root == null) return new TreeNode(val);
    if (val < root.val) root.left = insertIntoBST(root.left, val);
    else root.right = insertIntoBST(root.right, val);
    return root;
}

    7. Delete a Node in a BST

    Problem. Given the root of a BST and a key, delete the node with that key (if present) while preserving the BST property, and return the (possibly new) root.

    Input: tree = [5,3,6,2,4,null,7], key = 3

    Output: tree = [5,4,6,2,null,null,7] (3 replaced by successor 4)

    • First descend by comparison to locate the target, using the "return the subtree so each parent re-links its child" idiom so the deletion splices cleanly into the tree without tracking parents manually.
    • Handle three cases at the found node: (a) no children -> return null; (b) exactly one child -> return that child (it slides up into the gap, still valid); (c) two children -> you can't just remove it, so replace its value with its inorder successor (the leftmost node of the right subtree, i.e. the smallest value larger than it), then recursively delete that successor from the right subtree.
    • The successor is chosen precisely because it's the one value that can sit in the deleted node's place without violating the invariant on either side - it's larger than everything in the left subtree and smaller than everything else in the right subtree.
    • An alternative "two children" fix attaches the entire left subtree under the leftmost node of the right subtree and returns the right subtree, avoiding a second search - either is O(h).
    • O(h) time (descent plus at most one successor descent), O(h) space for recursion.

    Time: O(h) | Space: O(h)

    Three-Case Delete via Inorder Successor

    private TreeNode findMin(TreeNode node) {
    while (node.left != null) node = node.left;
    return node;
}

public TreeNode deleteNode(TreeNode root, int key) {
    if (root == null) return null;
    if (key < root.val) root.left = deleteNode(root.left, key);
    else if (key > root.val) root.right = deleteNode(root.right, key);
    else {
        if (root.left == null) return root.right;
        if (root.right == null) return root.left;
        TreeNode successor = findMin(root.right);
        root.val = successor.val;
        root.right = deleteNode(root.right, successor.val);
    }
    return root;
}

    8. K-th Smallest and Largest Element in a BST

    Problem. Given the root of a BST and an integer k, find the k-th smallest element (and, symmetrically, the k-th largest).

    Input: tree = [5,3,6,2,4,null,null,1], k = 3

    Output: 3 (sorted order is 1,2,3,4,5,6; 3rd smallest is 3)

    • Lean on the defining fact that an inorder traversal of a BST yields values in sorted ascending order - so the k-th node visited by inorder is exactly the k-th smallest, no sorting required.
    • Do the inorder walk while decrementing a counter, and stop the moment the counter hits k rather than traversing the whole tree - an iterative stack-based inorder makes this early-exit clean and avoids visiting the remaining larger elements.
    • For the k-th largest, do the mirror: a reverse-inorder traversal (right, node, left) visits values in descending order, so the k-th node there is the k-th largest - same code with the two recursive calls swapped.
    • O(h + k) time with early exit (descend to the smallest, then advance k steps), O(h) space for the stack; a plain full inorder is O(n)/O(h).

    Time: O(h + k) | Space: O(h)

    Inorder Walk with Early Exit

    public int kthSmallest(TreeNode root, int k) {
    Deque<TreeNode> st = new ArrayDeque<>();
    TreeNode curr = root;
    while (curr != null || !st.isEmpty()) {
        while (curr != null) { st.push(curr); curr = curr.left; }
        curr = st.pop();
        if (--k == 0) return curr.val;
        curr = curr.right;
    }
    return -1;
}

    9. Validate a Binary Search Tree

    Problem. Given the root of a binary tree, determine whether it is a valid Binary Search Tree.

    Input: tree = [5,1,4,null,null,3,6]

    Output: false (node 3 sits in the right subtree of 5 but is < 5)

    • The classic mistake is checking only that each node is greater than its left child and less than its right child - that's insufficient, because the invariant is about entire subtrees, not just immediate children (a deep-left descendant could still exceed the root).
    • The correct approach passes a valid (low, high) range down the recursion: the root may be anything, each left child tightens the upper bound to the parent's value, and each right child tightens the lower bound - a node is valid iff its value lies strictly inside its inherited open interval, and both children pass their tightened ranges.
    • An equivalent approach does an inorder traversal and verifies the sequence is strictly increasing (each value greater than the previously visited one) - this reuses the "inorder = sorted" property and only needs to remember the last value seen.
    • Use a wide sentinel range (e.g. LONG_MIN/LONG_MAX) so boundary node values at INT limits don't cause false failures.
    • O(n) time (visits every node once), O(h) space for recursion.

    Time: O(n) | Space: O(h)

    Range-Passing Recursion

    private boolean validate(TreeNode node, long low, long high) {
    if (node == null) return true;
    if (node.val <= low || node.val >= high) return false;
    return validate(node.left, low, node.val)
        && validate(node.right, node.val, high);
}

public boolean isValidBST(TreeNode root) {
    return validate(root, Long.MIN_VALUE, Long.MAX_VALUE);
}

    10. Lowest Common Ancestor of a BST

    Problem. Given the root of a BST and two nodes p and q present in it, find their lowest common ancestor (LCA).

    Input: tree = [6,2,8,0,4,7,9], p = 2, q = 8

    Output: 6 (2 and 8 split at the root)

    • The BST invariant makes this far cheaper than the general-binary-tree LCA: you don't need to search both subtrees, just walk down comparing both target values to the current node.
    • If both p and q are smaller than the current node, the LCA must be in the left subtree - go left; if both are larger, go right; the first node where the two targets diverge (one <= node <= other, i.e. the split point) is the LCA, because that's the deepest node from which p and q descend into different sides.
    • No recursion or auxiliary storage is needed - it's a single descend-by-comparison loop, again a variation on the same walk from Search.
    • O(h) time (one descent to the split point), O(1) space.

    Time: O(h) | Space: O(1)

    Descend to the Split Point

    public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
    while (root != null) {
        if (p.val < root.val && q.val < root.val) root = root.left;
        else if (p.val > root.val && q.val > root.val) root = root.right;
        else return root;
    }
    return null;
}

    11. Construct a BST from Preorder

    Problem. Given the preorder traversal of a BST (with distinct values), reconstruct the original BST.

    Input: preorder = [8,5,1,7,10,12]

    Output: tree = [8,5,10,1,7,null,12]

    • Unlike a general binary tree (which needs two traversals), a BST needs only preorder - because the BST ordering itself supplies the "which values go left vs. right" information that inorder would otherwise provide.
    • The efficient O(n) approach passes an upper-bound down the recursion: the first element is the root, and you keep consuming subsequent elements into the left subtree as long as they're smaller than the current bound, then into the right subtree with a widened bound - a shared, only-advancing index walks the preorder array once.
    • Intuition for the bound: every node in a left subtree must be less than its parent, and every node in a right subtree is bounded above by the nearest ancestor from which it turned right - the recursion threads exactly these limits.
    • Two simpler-but-slower alternatives exist (insert each element one at a time -> O(n*h); or sort preorder to get inorder and use the general two-traversal build -> O(n log n)); the bound-passing method is the one to know.
    • O(n) time (each element consumed once under the bound test), O(h) space for recursion.

    Time: O(n) | Space: O(h)

    Upper-Bound-Threaded Single Pass

    private int idx;

public TreeNode bstFromPreorder(int[] preorder) {
    idx = 0;
    return build(preorder, Long.MAX_VALUE);
}

private TreeNode build(int[] preorder, long bound) {
    if (idx == preorder.length || preorder[idx] > bound) return null;
    TreeNode root = new TreeNode(preorder[idx++]);
    root.left = build(preorder, root.val);
    root.right = build(preorder, bound);
    return root;
}

    12. Inorder Successor and Predecessor in a BST

    Problem. Given the root of a BST and a key (or node), find its inorder successor - the smallest value in the BST strictly greater than the key (and, symmetrically, the predecessor - the largest value strictly less).

    Input: tree = [8,4,12,2,6,10,14], key = 8

    Output: successor = 10, predecessor = 6

    • Without needing parent pointers, the successor is found by the same candidate-tracking descent as Ceil, but with a strict inequality: walk down, and whenever the current node's value is greater than the key, record it as a candidate and go left to seek a tighter (smaller-but-still-greater) one; otherwise go right.
    • The last recorded value when you fall off the tree is the inorder successor - it's exactly the ceil computed with > instead of >=, which is why this problem is essentially Ceil/Floor in disguise.
    • The predecessor is the mirror: record whenever the node's value is less than the key and go right to tighten, else go left - identical to Floor with a strict inequality.
    • If parent pointers were available there's an alternate O(h) rule (successor = leftmost of right subtree if it exists, else the lowest ancestor for which the node is in the left subtree), but the candidate-descent needs no parents.
    • O(h) time (single descent), O(1) space.

    Time: O(h) | Space: O(1)

    Candidate Descent with Strict Inequality

    public int inorderSuccessor(TreeNode root, int key) {
    int succ = -1;
    while (root != null) {
        if (root.val > key) { succ = root.val; root = root.left; }
        else root = root.right;
    }
    return succ;
}

public int inorderPredecessor(TreeNode root, int key) {
    int pred = -1;
    while (root != null) {
        if (root.val < key) { pred = root.val; root = root.right; }
        else root = root.left;
    }
    return pred;
}

    13. Merge Two BSTs

    Problem. Given the roots of two BSTs, return a single sorted list (or a balanced BST) containing all elements of both.

    Input: bst1 = [3,1,5], bst2 = [4,2,6]

    Output: [1,2,3,4,5,6]

    • Convert each BST to a sorted array via inorder traversal (O(n) and O(m)) - again exploiting "inorder = sorted" so you get two sorted sequences for free without any comparisons.
    • Merge the two sorted arrays with the standard two-pointer merge (as in merge sort) into one combined sorted array in O(n + m) - this avoids re-sorting, which would cost an unnecessary log factor.
    • If a balanced BST output is required rather than a list, build it from the merged sorted array by recursively taking the middle element as the root (sorted-array-to-balanced-BST), giving an O(n + m) height-balanced tree.
    • The whole pipeline - two inorder flattens, one linear merge, one middle-out build - is O(n + m) time and O(n + m) space, strictly better than dumping everything into one tree and re-sorting.
    • O(n + m) time, O(n + m) space.

    Time: O(n + m) | Space: O(n + m)

    Inorder Flatten + Two-Pointer Merge

    private void inorder(TreeNode node, List<Integer> out) {
    if (node == null) return;
    inorder(node.left, out);
    out.add(node.val);
    inorder(node.right, out);
}

public List<Integer> mergeBSTs(TreeNode root1, TreeNode root2) {
    List<Integer> a = new ArrayList<>(), b = new ArrayList<>(), merged = new ArrayList<>();
    inorder(root1, a);
    inorder(root2, b);
    int i = 0, j = 0;
    while (i < a.size() && j < b.size()) {
        if (a.get(i) <= b.get(j)) merged.add(a.get(i++));
        else merged.add(b.get(j++));
    }
    while (i < a.size()) merged.add(a.get(i++));
    while (j < b.size()) merged.add(b.get(j++));
    return merged;
}

    14. Two Sum in a BST

    Problem. Given the root of a BST and a target k, determine whether there exist two distinct nodes whose values sum to k.

    Input: tree = [5,3,6,2,4,null,7], k = 9

    Output: true (2 + 7 = 9)

    • The lazy approach flattens the BST to a sorted array via inorder and runs the standard two-pointer two-sum (one pointer at each end, move inward based on whether the sum is too small or too large) - correct and O(n) time, but O(n) extra space.
    • The elegant BST-native approach uses two iterators walking the tree in opposite directions simultaneously: a forward inorder iterator yielding ascending values and a reverse inorder iterator yielding descending values, playing the two-pointer game directly over the tree without materializing the full array.
    • Each iterator is a controlled stack-based traversal (a "BSTIterator" that exposes next()/prev()); advance the smaller side up or the larger side down until the two sum to k or the pointers cross - reducing auxiliary space from O(n) to O(h).
    • Skip the same node being used twice by requiring the two iterator positions to remain distinct (the ascending pointer stays strictly left of the descending pointer).
    • O(n) time (each node is produced at most once per iterator), O(h) space for the two traversal stacks.

    Time: O(n) | Space: O(h)

    Dual Forward/Reverse Inorder Iterators

    class BSTIterator {
    Deque<TreeNode> st = new ArrayDeque<>();
    boolean reverse;

    BSTIterator(TreeNode root, boolean isReverse) { reverse = isReverse; pushAll(root); }

    void pushAll(TreeNode node) {
        while (node != null) { st.push(node); node = reverse ? node.right : node.left; }
    }

    int next() {
        TreeNode node = st.pop();
        pushAll(reverse ? node.left : node.right);
        return node.val;
    }

    boolean hasNext() { return !st.isEmpty(); }
}

public boolean findTarget(TreeNode root, int k) {
    if (root == null) return false;
    BSTIterator left = new BSTIterator(root, false), right = new BSTIterator(root, true);
    int i = left.next(), j = right.next();
    while (i < j) {
        if (i + j == k) return true;
        else if (i + j < k) i = left.next();
        else j = right.next();
    }
    return false;
}

    15. Recover a Swapped BST

    Problem. Given the root of a BST in which exactly two nodes' values were swapped by mistake, recover the tree by fixing those two values, without changing its structure.

    Input: tree = [3,1,4,null,null,2] (values 2 and 3 swapped)

    Output: tree = [2,1,4,null,null,3]

    • Since inorder of a correct BST is strictly increasing, an inorder walk of the corrupted tree has exactly one or two descents (places where the previous value exceeds the current) - those violations pinpoint the two swapped nodes.
    • Two adjacent swapped nodes produce a single violation (mark the larger of that pair as "first" and the smaller as "second"); two non-adjacent swapped nodes produce two separate violations (take "first" from the first violation and "second" from the second) - track a running prev pointer and capture first/second accordingly.
    • After the single inorder pass identifies the two offending nodes, swap their values back - this fixes the tree in place without touching any pointers or structure.
    • The optimal O(1)-extra-space version replaces the recursion/stack with a Morris inorder traversal (threading), so the whole recovery uses constant auxiliary space - tying directly back to the Morris traversal problems in the Trees section.
    • O(n) time (one inorder pass), O(h) space recursive / O(1) space with Morris.

    Time: O(n) | Space: O(h)

    Inorder Violation Detection

    private TreeNode first, second, prev;

private void inorder(TreeNode node) {
    if (node == null) return;
    inorder(node.left);
    if (prev != null && prev.val > node.val) {
        if (first == null) first = prev;
        second = node;
    }
    prev = node;
    inorder(node.right);
}

public void recoverTree(TreeNode root) {
    inorder(root);
    int tmp = first.val;
    first.val = second.val;
    second.val = tmp;
}

    16. Largest BST Subtree

    Problem. Given the root of a binary tree (not necessarily a BST), find the size (number of nodes) of the largest subtree that is itself a valid BST.

    Input: tree = [10,5,15,1,8,null,7]

    Output: 3 (the subtree [5,1,8] is the largest valid BST)

    • The naive approach validates every subtree independently and takes its size - O(n^2). The optimal approach is a single bottom-up (postorder) pass where each node returns a small summary of its subtree: (min value, max value, size, isBST) - or an equivalent packed struct.
    • At each node, combine the children's summaries: the subtree rooted here is a valid BST only if both children are valid BSTs AND the node's value is greater than the left subtree's max and less than the right subtree's min - the exact local condition that guarantees the global BST invariant when built bottom-up.
    • When it is a valid BST, its size is left.size + right.size + 1 and its (min, max) range is (left.min, right.max); when it isn't, propagate size = max(left.size, right.size) upward and a range that forces every ancestor to also fail (e.g. min = -inf, max = +inf).
    • Track the global maximum BST size seen across all nodes during the postorder - that's the answer, computed in one traversal.
    • O(n) time (each node processed once with O(1) merge work), O(h) space for recursion.

    Time: O(n) | Space: O(h)

    Bottom-Up (min,max,size,isBST) Aggregation

    class Info {
    int minVal, maxVal, size;
    boolean isBST;
    Info(int mn, int mx, int sz, boolean b) { minVal = mn; maxVal = mx; size = sz; isBST = b; }
}

private int largestBST = 0;

private Info solve(TreeNode node) {
    if (node == null) return new Info(Integer.MAX_VALUE, Integer.MIN_VALUE, 0, true);
    Info left = solve(node.left);
    Info right = solve(node.right);
    if (left.isBST && right.isBST && node.val > left.maxVal && node.val < right.minVal) {
        int size = left.size + right.size + 1;
        largestBST = Math.max(largestBST, size);
        return new Info(Math.min(node.val, left.minVal), Math.max(node.val, right.maxVal), size, true);
    }
    return new Info(Integer.MIN_VALUE, Integer.MAX_VALUE, Math.max(left.size, right.size), false);
}

public int largestBSTSubtree(TreeNode root) {
    solve(root);
    return largestBST;
}
