    1. Reverse a Stack Using Recursion

    Difficulty: LOW

    Statement/Hint: Reverse the order of elements in a stack using only recursion - no additional data structure like an array or a second explicit stack.

    Example: - Input: stack (top to bottom) = 1,2,3,4,5 - Output: stack (top to bottom) = 5,4,3,2,1

    Approach: Recursive Pop + Bottom Insertion - Recursively pop all elements until the stack is empty (base case), then on the way back up, insert each popped element at the very bottom of the (already reversed) remaining stack instead of the top. - Inserting at the bottom is itself a recursive helper: if the stack is empty, just push the element; otherwise pop the top, recursively insert at the bottom, then push the popped element back on top. - The recursion call stack functions as the only auxiliary storage - the same "use the call stack as extra space" technique as sorting a stack recursively. - O(n^2) time (each bottom-insertion is O(n)), O(n) space for the recursion stack.

    Time / Space: O(n^2) time, O(n) space.

    private void insertAtBottom(Deque<Integer> st, int x) {
    if (st.isEmpty()) {
        st.push(x);
        return;
    }
    int top = st.pop();
    insertAtBottom(st, x);
    st.push(top);
}

public void reverseStack(Deque<Integer> st) {
    if (st.isEmpty()) return;
    int top = st.pop();
    reverseStack(st);
    insertAtBottom(st, top);
}

    2. Generate Binary Strings Without Consecutive 1s

    Difficulty: MEDIUM

    Statement/Hint: Given an integer K, generate all binary strings of length K that do not contain two consecutive 1s.

    Example: - Input: K = 3 - Output: ["000","001","010","100","101"]

    Approach: Constrained Recursive Construction - Build the string one character at a time via recursion; at each position, you may always place a '0', but may only place a '1' if the previous character placed was not '1' (tracked via a lastWasOne flag passed down). - Base case: when the current string reaches length K, record it as one valid result. - This branch-and-bound style (skip the '1' branch entirely when it would create "11") is more efficient than generating all 2^K strings and filtering, since invalid branches are pruned immediately rather than generated and discarded. - O(2^K) time in the worst case (the number of valid strings is actually Fibonacci-like, strictly less than 2^K), O(K) space for the recursion stack and current string.

    Time / Space: O(2^K) time, O(K) space.

    private void solve(int k, StringBuilder curr, boolean lastWasOne, List<String> result) {
    if (curr.length() == k) {
        result.add(curr.toString());
        return;
    }
    curr.append('0');
    solve(k, curr, false, result);
    curr.deleteCharAt(curr.length() - 1);
    if (!lastWasOne) {
        curr.append('1');
        solve(k, curr, true, result);
        curr.deleteCharAt(curr.length() - 1);
    }
}

public List<String> generateBinaryStrings(int k) {
    List<String> result = new ArrayList<>();
    solve(k, new StringBuilder(), false, result);
    return result;
}

    3. String to Integer (atoi) Using Recursion

    Difficulty: LOW

    Statement/Hint: Implement the atoi function (string to integer conversion) using recursion instead of iteration.

    Example: - Input: s = " -042abc" - Output: -42

    Approach: Recursive Digit Accumulation with Overflow Clamping - Recursively strip leading whitespace, then handle an optional sign character, then recursively build the numeric value digit by digit: the helper returns the accumulated value once it hits a non-digit or the end of string. - Clamp the final result to the 32-bit signed integer range [-2^31, 2^31 - 1] before returning, since the recursive digit accumulation can overflow past int range. - Base case: recursion stops when a non-digit character is encountered or the string ends. - O(n) time, O(n) space for the recursion call stack (versus O(1) space for the standard iterative version) - recursion here is an academic exercise since the iterative version is strictly better.

    Time / Space: O(n) time, O(n) space.

    private long helper(String s, int i, long val) {
    if (i == s.length() || !Character.isDigit(s.charAt(i)) || val > Integer.MAX_VALUE) return val;
    return helper(s, i + 1, val * 10 + (s.charAt(i) - '0'));
}

public int myAtoi(String s) {
    int i = 0, n = s.length();
    while (i < n && s.charAt(i) == ' ') i++;
    int sign = 1;
    if (i < n && (s.charAt(i) == '+' || s.charAt(i) == '-')) sign = (s.charAt(i++) == '-') ? -1 : 1;
    long val = sign * helper(s, i, 0);
    if (val > Integer.MAX_VALUE) return Integer.MAX_VALUE;
    if (val < Integer.MIN_VALUE) return Integer.MIN_VALUE;
    return (int) val;
}

    4. Pow(x, n)

    Difficulty: MEDIUM

    Statement/Hint: Implement pow(x, n), computing x raised to the power n, in O(log n) time.

    Example: - Input: x = 2.0, n = 10 - Output: 1024.0

    Approach: Fast Exponentiation (Binary Exponentiation) - Use fast exponentiation: recursively compute half = pow(x, n/2), then combine as half*half (even n) or half*half*x (odd n) - this halves the problem size each call instead of multiplying n times. - Handle negative n by inverting x (x = 1/x) and negating n first, converting n to a long before negating to avoid overflow when n = INT_MIN. - Base case: n == 0 returns 1. - O(log n) time, O(log n) space for the recursion stack (or O(1) iteratively by repeated squaring with a loop).

    Time / Space: O(log n) time, O(log n) space.

    private double helper(double x, long n) {
    if (n == 0) return 1.0;
    double half = helper(x, n / 2);
    double result = half * half;
    if (n % 2 != 0) result *= x;
    return result;
}

public double myPow(double x, int n) {
    long N = n;
    if (N < 0) {
        x = 1 / x;
        N = -N;
    }
    return helper(x, N);
}

    5. Count Good Numbers

    Difficulty: MEDIUM

    Statement/Hint: A digit string is "good" if every even index (0-indexed) has an even digit and every odd index has a prime digit (2,3,5,7). Count how many good digit strings of length n exist, modulo 10^9+7.

    Example: - Input: n = 1 - Output: 5

    Approach: Combinatorial Counting + Modular Fast Exponentiation - The choices at each position are independent: even indices have 5 choices (0,2,4,6,8), odd indices have 4 choices (2,3,5,7). The total count is 5^(ceil(n/2)) * 4^(floor(n/2)). - Compute each power using fast exponentiation (binary exponentiation) under the modulus, since n can be astronomically large - a naive loop multiplying n times would be too slow. - Apply the modulus after every multiplication in the exponentiation to prevent overflow. - O(log n) time, O(log n) space (recursive fast power) - the key insight is recognizing this reduces entirely to counting + modular exponentiation, not an actual recursive search over strings.

    Time / Space: O(log n) time, O(log n) space.

    private static final long MOD = 1_000_000_007L;

private long power(long x, long n) {
    if (n == 0) return 1;
    long half = power(x, n / 2) % MOD;
    long result = (half * half) % MOD;
    if (n % 2 != 0) result = (result * x) % MOD;
    return result;
}

public int countGoodNumbers(long n) {
    long evenCount = (n + 1) / 2;
    long oddCount = n / 2;
    long result = (power(5, evenCount) * power(4, oddCount)) % MOD;
    return (int) result;
}

    6. Sort a Stack Using Recursion

    Difficulty: MEDIUM

    Statement/Hint: Sort a stack in ascending order (smallest element on top) using only recursion - no additional data structure like an array or a second explicit stack.

    Example: - Input: stack (pushed order) = [3, 1, 4, 1, 5] - Output: stack sorted ascending, top to bottom = [1,1,3,4,5]

    Approach: Recursive Pop + Sorted Insertion - Recursively pop all elements off the stack until it's empty (base case), which naturally uses the call stack as auxiliary storage. - On the way back up, insert each popped element into its correct sorted position within the (already recursively sorted) remaining stack - this insertion is itself a recursive helper: pop elements greater than the current value, recursively insert, then push the popped elements back. - Because both operations only use recursion (no explicit loop-based data structure), the call stack itself stands in for the "extra space" needed. - O(n^2) time in the worst case (each insertion can take O(n)), O(n) space for the recursion stack.

    Time / Space: O(n^2) time, O(n) space.

    private void insertSorted(Deque<Integer> st, int x) {
    if (st.isEmpty() || st.peek() <= x) {
        st.push(x);
        return;
    }
    int top = st.pop();
    insertSorted(st, x);
    st.push(top);
}

public void sortStack(Deque<Integer> st) {
    if (st.isEmpty()) return;
    int top = st.pop();
    sortStack(st);
    insertSorted(st, top);
}

    7. Generate Parentheses

    Difficulty: HIGH

    Statement/Hint: Given n pairs of parentheses, generate all combinations of well-formed (balanced) parentheses strings.

    Example: - Input: n = 3 - Output: ["((()))","(()())","(())()","()(())","()()()"]

    Approach: Constrained Recursive Construction - Build the string recursively, tracking the count of open and close parentheses used so far; add an open paren whenever open < n, and a close paren whenever close < open (never let closes exceed opens, which keeps every prefix balanced). - Base case: when the string reaches length 2n, it's a complete valid combination - add it to the result. - Because invalid branches (where close would exceed open) are never explored, every string generated is guaranteed well-formed - no post-filtering needed. - O(4^n / sqrt(n)) time (bounded by the nth Catalan number, the count of valid combinations), O(n) space for the recursion stack and current string (excluding output storage).

    Time / Space: O(4^n / sqrt(n)) time, O(n) space.

    private void solve(int open, int close, int n, StringBuilder curr, List<String> result) {
    if (curr.length() == 2 * n) {
        result.add(curr.toString());
        return;
    }
    if (open < n) {
        curr.append('(');
        solve(open + 1, close, n, curr, result);
        curr.deleteCharAt(curr.length() - 1);
    }
    if (close < open) {
        curr.append(')');
        solve(open, close + 1, n, curr, result);
        curr.deleteCharAt(curr.length() - 1);
    }
}

public List<String> generateParenthesis(int n) {
    List<String> result = new ArrayList<>();
    solve(0, 0, n, new StringBuilder(), result);
    return result;
}

    8. Power Set (All Subsequences)

    Difficulty: HIGH

    Statement/Hint: Given a string (or array), print/return all of its subsequences (the power set) - every possible subset of characters, preserving relative order.

    Example: - Input: s = "abc" - Output: ["","c","b","bc","a","ac","ab","abc"] (order depends on take/skip branch ordering)

    Approach: Take/Not-Take Recursion - At each index, make a binary choice: either include the current character in the subsequence being built, or skip it - then recurse on the remaining characters for both choices. - Base case: when the index reaches the end of the string, the currently built subsequence (which may be empty) is one complete subset - record it. - This is the canonical "take / not-take" recursion template that every subsequence-based problem in this topic (combination sum, subsets, etc.) builds on, just with an added constraint or aggregation on top. - O(2^n * n) time (2^n subsequences, each taking O(n) to copy/build), O(n) space for the recursion stack (excluding output storage).

    Time / Space: O(2^n * n) time, O(n) space.

    private void solve(int idx, String s, StringBuilder curr, List<String> result) {
    if (idx == s.length()) {
        result.add(curr.toString());
        return;
    }
    curr.append(s.charAt(idx));
    solve(idx + 1, s, curr, result);
    curr.deleteCharAt(curr.length() - 1);
    solve(idx + 1, s, curr, result);
}

public List<String> powerSet(String s) {
    List<String> result = new ArrayList<>();
    solve(0, s, new StringBuilder(), result);
    return result;
}

    9. Subsequence Template Variations

    Difficulty: LOW

    Statement/Hint: What are the standard variations of the take/not-take subsequence recursion template, and when should you print results directly during recursion vs. return/collect them?

    Example: - Input: "print one subsequence with sum K" vs "count all subsequences with sum K" vs "does a subsequence with sum K exist" - Output: three structurally different recursive templates (boolean short-circuit, additive count, OR short-circuit) all built on the same take/not-take skeleton

    Approach: Template Recognition (Theory) - Print-one variant: when you only need the first subsequence satisfying a condition, have the recursive function return a boolean once found, and check that boolean before exploring the second (not-take) branch - this short-circuits further recursion once done. - Count variant: when you need to count how many subsequences satisfy a condition, sum the results of both branches at each step (count = f(take) + f(notTake)) rather than pushing values into a result list. - Existence variant: when you only need a yes/no answer, combine branches with a logical OR (f(take) || f(notTake)) so recursion short-circuits as soon as one branch succeeds. - Collect-all variant (the default, as in Power Set): explore both branches unconditionally and add every complete subsequence to a result list - the only variant that must visit every leaf of the recursion tree.

    Time / Space: O(2^n) worst case per variant, O(n) space.

    // Print one subsequence with sum K (short-circuits after first find)
private boolean printOneWithSumK(int idx, int[] arr, int k, List<Integer> curr) {
    if (idx == arr.length) {
        if (k == 0) { System.out.println(curr); return true; }
        return false;
    }
    curr.add(arr[idx]);
    if (printOneWithSumK(idx + 1, arr, k - arr[idx], curr)) return true;
    curr.remove(curr.size() - 1);
    return printOneWithSumK(idx + 1, arr, k, curr);
}

// Count all subsequences with sum K
private int countWithSumK(int idx, int[] arr, int k) {
    if (idx == arr.length) return k == 0 ? 1 : 0;
    int take = countWithSumK(idx + 1, arr, k - arr[idx]);
    int notTake = countWithSumK(idx + 1, arr, k);
    return take + notTake;
}

// Does any subsequence with sum K exist
private boolean existsWithSumK(int idx, int[] arr, int k) {
    if (idx == arr.length) return k == 0;
    return existsWithSumK(idx + 1, arr, k - arr[idx]) || existsWithSumK(idx + 1, arr, k);
}

    10. Count Subsequences with Sum K

    Difficulty: MEDIUM

    Statement/Hint: Given an array of integers and a target sum K, count the number of subsequences whose elements sum to K.

    Example: - Input: arr = [1,2,3], k = 3 - Output: 2 (subsequences [1,2] and [3])

    Approach: Take/Not-Take Recursion with Additive Count - Use the take/not-take recursion template: at each index, either include the current element (recurse with idx+1 and k - arr[idx]) or skip it (recurse with idx+1 and k unchanged), and sum the results of both branches. - Base case: when idx reaches the end of the array, return 1 if the remaining target k has been reduced to exactly 0, otherwise return 0. - Every complete root-to-leaf path through the recursion tree corresponds to exactly one subsequence (include/exclude decision per element), so summing valid leaves gives the total count. - O(2^n) time (every subsequence is explored), O(n) space for the recursion stack. This can be optimized to O(n*k) with dynamic programming by memoizing on (idx, remaining sum).

    Time / Space: O(2^n) time, O(n) space.

    private int countSubsequences(int idx, int[] arr, int k) {
    if (idx == arr.length) return (k == 0) ? 1 : 0;
    int take = countSubsequences(idx + 1, arr, k - arr[idx]);
    int notTake = countSubsequences(idx + 1, arr, k);
    return take + notTake;
}

    11. Check if a Subsequence with Sum K Exists

    Difficulty: MEDIUM

    Statement/Hint: Given an array of integers and a target sum K, determine whether any subsequence exists whose elements sum to exactly K.

    Example: - Input: arr = [1,2,3], k = 6 - Output: true (the full array sums to 6)

    Approach: Take/Not-Take Recursion with OR Short-Circuit - Use the take/not-take recursion template, but combine branches with a logical OR instead of summing: return existsSubsequence(idx+1, k - arr[idx]) || existsSubsequence(idx+1, k) - this lets recursion short-circuit as soon as one branch confirms existence. - Base case: when idx reaches the end of the array, return true only if the remaining target k has been reduced to exactly 0. - Because of the OR short-circuit, this doesn't have to explore all 2^n subsequences in the average case - it stops the moment any valid one is found, unlike the "count all" variant which must visit every leaf. - O(2^n) time in the worst case (no valid subsequence exists), O(n) space for the recursion stack.

    Time / Space: O(2^n) time, O(n) space.

    private boolean existsSubsequence(int idx, int[] arr, int k) {
    if (idx == arr.length) return k == 0;
    return existsSubsequence(idx + 1, arr, k - arr[idx]) || existsSubsequence(idx + 1, arr, k);
}

    12. Combination Sum

    Difficulty: HIGH

    Statement/Hint: Given an array of distinct positive integers and a target, find all unique combinations where the chosen numbers sum to the target - the same number may be reused unlimited times.

    Example: - Input: candidates = [2,3,6,7], target = 7 - Output: [[2,2,3],[7]]

    Approach: Take/Not-Take with Index Repetition - At each index, try including the current element and recurse WITHOUT advancing the index (since it can be reused), then also try skipping it entirely by recursing with idx+1 - take/not-take, but the "take" branch stays at the same index to allow repetition. - Reduce the remaining target by the chosen element's value each time it's taken; base cases are target == 0 (record the current combination) or idx reaches the end / target < 0 (dead end, backtrack). - Sorting the input first lets you break out of the take-loop early once arr[idx] > target, pruning branches that can't possibly succeed. - O(2^target) time in the worst case, O(target / min(arr)) space for the recursion depth.

    Time / Space: O(2^target) time, O(target / min(arr)) space.

    private void solve(int idx, int[] arr, int target, List<Integer> curr, List<List<Integer>> result) {
    if (idx == arr.length) {
        if (target == 0) result.add(new ArrayList<>(curr));
        return;
    }
    if (arr[idx] <= target) {
        curr.add(arr[idx]);
        solve(idx, arr, target - arr[idx], curr, result);
        curr.remove(curr.size() - 1);
    }
    solve(idx + 1, arr, target, curr, result);
}

public List<List<Integer>> combinationSum(int[] candidates, int target) {
    List<List<Integer>> result = new ArrayList<>();
    solve(0, candidates, target, new ArrayList<>(), result);
    return result;
}

    13. Combination Sum II

    Difficulty: HIGH

    Statement/Hint: Given an array of integers (which may contain duplicates) and a target, find all unique combinations where the chosen numbers sum to the target - each number may be used at most once, and the result must not contain duplicate combinations.

    Example: - Input: candidates = [10,1,2,7,6,1,5], target = 8 - Output: [[1,1,6],[1,2,5],[1,7],[2,6]]

    Approach: Sort + Loop-Based Recursion with Duplicate Skipping - Sort the array first so duplicate values become adjacent - this is what makes duplicate-combination skipping possible. - Use a single loop at each recursion level (rather than binary take/not-take) trying every index from the current start position onward; recurse into idx+1 (each element used at most once) and skip to the next distinct value with if (i > idx && arr[i] == arr[i-1]) continue - this prevents generating the same combination twice from duplicate values at the same recursion depth. - Base cases: target == 0 records the current combination; target < 0 or exhausting choices backtracks without recording. - O(2^n) time in the worst case, O(n) space for the recursion stack - the duplicate-skip check is the key addition over the standard "each element used once" combination pattern.

    Time / Space: O(2^n) time, O(n) space.

    private void solve(int idx, int[] arr, int target, List<Integer> curr, List<List<Integer>> result) {
    if (target == 0) {
        result.add(new ArrayList<>(curr));
        return;
    }
    for (int i = idx; i < arr.length; i++) {
        if (i > idx && arr[i] == arr[i - 1]) continue;
        if (arr[i] > target) break;
        curr.add(arr[i]);
        solve(i + 1, arr, target - arr[i], curr, result);
        curr.remove(curr.size() - 1);
    }
}

public List<List<Integer>> combinationSum2(int[] candidates, int target) {
    Arrays.sort(candidates);
    List<List<Integer>> result = new ArrayList<>();
    solve(0, candidates, target, new ArrayList<>(), result);
    return result;
}

    14. Subset Sums

    Difficulty: MEDIUM

    Statement/Hint: Given an array of integers, return the sum of every possible subset (including the empty subset) - i.e., all subset sums.

    Example: - Input: arr = [2,3] - Output: [0,3,2,5]

    Approach: Take/Not-Take Recursion with Running Sum - Use the standard take/not-take recursion: at each index, recurse once including the current element in a running sum, and once excluding it. - Base case: when the index reaches the end of the array, the accumulated running sum represents the total of one complete subset - record it. - Unlike "Power Set" (which returns the actual subsequences), this only needs the aggregate sums, so you can pass the running sum by value instead of building/copying an explicit list at each step, which is slightly more efficient. - O(2^n) time (2^n subsets), O(n) space for the recursion stack.

    Time / Space: O(2^n) time, O(n) space.

    private void solve(int idx, int[] arr, int sum, List<Integer> result) {
    if (idx == arr.length) {
        result.add(sum);
        return;
    }
    solve(idx + 1, arr, sum + arr[idx], result);
    solve(idx + 1, arr, sum, result);
}

public List<Integer> subsetSums(int[] arr) {
    List<Integer> result = new ArrayList<>();
    solve(0, arr, 0, result);
    return result;
}

    15. Subsets II

    Difficulty: MEDIUM

    Statement/Hint: Given an array of integers that may contain duplicates, return all possible unique subsets (the power set, without duplicate subsets).

    Example: - Input: arr = [1,2,2] - Output: [[],[1],[1,2],[1,2,2],[2],[2,2]]

    Approach: Sort + Loop-Based Recursion with Duplicate Skipping - Sort the array first so duplicate values become adjacent, then use loop-based recursion (like Combination Sum II) rather than binary take/not-take: at each level, try every index from the current start position onward as the "next element to add." - Skip duplicate values at the same recursion depth with if (i > idx && arr[i] == arr[i-1]) continue - this ensures a duplicate value is only used as the "first occurrence taken at this depth" once, preventing duplicate subsets. - Record the current subset (curr) at the START of every recursive call (not just at a base case) - every partial combination, including the empty one, is itself a valid subset. - O(2^n) time, O(n) space for the recursion stack - the duplicate-skip loop is the same technique as Combination Sum II, applied to unconstrained-length subsets instead of a fixed target sum.

    Time / Space: O(2^n) time, O(n) space.

    private void solve(int idx, int[] arr, List<Integer> curr, List<List<Integer>> result) {
    result.add(new ArrayList<>(curr));
    for (int i = idx; i < arr.length; i++) {
        if (i > idx && arr[i] == arr[i - 1]) continue;
        curr.add(arr[i]);
        solve(i + 1, arr, curr, result);
        curr.remove(curr.size() - 1);
    }
}

public List<List<Integer>> subsetsWithDup(int[] arr) {
    Arrays.sort(arr);
    List<List<Integer>> result = new ArrayList<>();
    solve(0, arr, new ArrayList<>(), result);
    return result;
}

    16. Combination Sum III

    Difficulty: MEDIUM

    Statement/Hint: Find all valid combinations of exactly K numbers (each from 1-9, used at most once) that sum to a target N, with no duplicate combinations.

    Example: - Input: k = 3, n = 7 - Output: [[1,2,4]]

    Approach: Loop-Based Recursion with Dual Constraints - Use loop-based recursion, trying each next candidate from the current start value up to 9; recurse into start+1 with the candidate added, decrementing both the remaining target and the remaining count of numbers needed. - Base cases: if count reaches 0, record the combination only if the remaining target is also exactly 0; prune early if the remaining target drops below 0 or the current candidate itself exceeds the remaining target, since candidates only increase from here. - Because candidates are drawn from a fixed range (1-9) with no duplicates in the source range itself, no explicit duplicate-skip check is needed (unlike Combination Sum II) - just the natural "start from i+1" prevents reuse. - O(C(9,k)) time (bounded by choosing k of 9 digits), O(k) space for the recursion depth.

    Time / Space: O(C(9,k)) time, O(k) space.

    private void solve(int start, int k, int n, List<Integer> curr, List<List<Integer>> result) {
    if (k == 0) {
        if (n == 0) result.add(new ArrayList<>(curr));
        return;
    }
    for (int i = start; i <= 9; i++) {
        if (i > n) break;
        curr.add(i);
        solve(i + 1, k - 1, n - i, curr, result);
        curr.remove(curr.size() - 1);
    }
}

public List<List<Integer>> combinationSum3(int k, int n) {
    List<List<Integer>> result = new ArrayList<>();
    solve(1, k, n, new ArrayList<>(), result);
    return result;
}

    17. Letter Combinations of a Phone Number

    Difficulty: MEDIUM

    Statement/Hint: Given a string of digits (2-9), return all possible letter combinations that the number could represent on a phone keypad (e.g. 2 -> 'abc').

    Example: - Input: digits = "23" - Output: ["ad","ae","af","bd","be","bf","cd","ce","cf"]

    Approach: Digit-to-Letter Recursive Construction - Build a lookup table mapping each digit to its corresponding letters, then recurse index by index through the digit string: at each index, try appending each possible letter for that digit and recurse to the next index. - Base case: when the index reaches the end of the digit string, the currently built combination is complete - record it. - Return an empty result immediately if the input string is empty (no digits means no combinations), avoiding an incorrect single empty-string result. - O(4^n * n) time (each of n digits maps to at most 4 letters, and building each string takes O(n)), O(n) space for the recursion stack.

    Time / Space: O(4^n * n) time, O(n) space.

    private void solve(int idx, String digits, String[] mapping, StringBuilder curr, List<String> result) {
    if (idx == digits.length()) {
        result.add(curr.toString());
        return;
    }
    String letters = mapping[digits.charAt(idx) - '0'];
    for (char c : letters.toCharArray()) {
        curr.append(c);
        solve(idx + 1, digits, mapping, curr, result);
        curr.deleteCharAt(curr.length() - 1);
    }
}

public List<String> letterCombinations(String digits) {
    List<String> result = new ArrayList<>();
    if (digits.isEmpty()) return result;
    String[] mapping = {"", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"};
    solve(0, digits, mapping, new StringBuilder(), result);
    return result;
}

    18. Palindrome Partitioning

    Difficulty: HIGH

    Statement/Hint: Given a string, partition it such that every substring in the partition is a palindrome. Return all possible palindrome partitions.

    Example: - Input: s = "aab" - Output: [["a","a","b"],["aa","b"]]

    Approach: Backtracking over Partition Points with Palindrome Check - Recurse over starting positions: at each start index, try every possible end index for the "next piece," and only recurse further (from end+1) if the substring from start to end is itself a palindrome - otherwise skip that end index. - Base case: when start reaches the end of the string, the current partition (a list of palindromic pieces) is complete - record a copy of it. - Checking whether a substring is a palindrome is itself an O(length) operation, so precomputing a 2D "is palindrome" table for all substrings up front trades O(n^2) space for avoiding repeated O(n) checks during the exponential partition search. - O(2^n * n) time in the worst case (exponential partitions, each requiring O(n) palindrome verification), O(n) space for the recursion stack (plus O(n^2) if precomputing the palindrome table).

    Time / Space: O(2^n * n) time, O(n) space.

    private boolean isPalindrome(String s, int start, int end) {
    while (start < end) {
        if (s.charAt(start) != s.charAt(end)) return false;
        start++;
        end--;
    }
    return true;
}

private void solve(int start, String s, List<String> curr, List<List<String>> result) {
    if (start == s.length()) {
        result.add(new ArrayList<>(curr));
        return;
    }
    for (int end = start; end < s.length(); end++) {
        if (isPalindrome(s, start, end)) {
            curr.add(s.substring(start, end + 1));
            solve(end + 1, s, curr, result);
            curr.remove(curr.size() - 1);
        }
    }
}

public List<List<String>> partition(String s) {
    List<List<String>> result = new ArrayList<>();
    solve(0, s, new ArrayList<>(), result);
    return result;
}

    19. Word Search

    Difficulty: HIGH

    Statement/Hint: Given an m x n grid of characters and a word, determine whether the word can be constructed by sequentially connecting adjacent cells (horizontally or vertically), without reusing the same cell twice within one word.

    Example: - Input: board = [["A","B","C","E"],["S","F","C","S"],["A","D","E","E"]], word = "ABCCED" - Output: true

    Approach: Grid Backtracking with In-Place Visited Marking - Try starting the search from every cell in the grid; at each step, recurse in all 4 directions (up/down/left/right) only if the neighboring cell matches the next required character. - Mark the current cell as visited before recursing (e.g. temporarily overwrite it with a sentinel character) and restore it afterward (backtrack) - this prevents reusing the same cell within a single path without needing a separate visited matrix. - Base case: if the index reaches the length of the word, every character has been matched - return true, short-circuiting further search. - O(m*n*4^L) time (L = word length, since each of the 4^L character-position paths for a given start cell is explored), O(L) space for the recursion stack.

    Time / Space: O(m*n*4^L) time, O(L) space.

    private boolean solve(char[][] board, String word, int i, int j, int idx) {
    if (idx == word.length()) return true;
    if (i < 0 || i >= board.length || j < 0 || j >= board[0].length || board[i][j] != word.charAt(idx))
        return false;
    char temp = board[i][j];
    board[i][j] = '#';
    boolean found = solve(board, word, i + 1, j, idx + 1) ||
            solve(board, word, i - 1, j, idx + 1) ||
            solve(board, word, i, j + 1, idx + 1) ||
            solve(board, word, i, j - 1, idx + 1);
    board[i][j] = temp;
    return found;
}

public boolean exist(char[][] board, String word) {
    for (int i = 0; i < board.length; i++) {
        for (int j = 0; j < board[0].length; j++) {
            if (solve(board, word, i, j, 0)) return true;
        }
    }
    return false;
}

    20. N-Queens

    Difficulty: HIGH

    Statement/Hint: Place N queens on an N x N chessboard such that no two queens attack each other (no shared row, column, or diagonal). Return all distinct valid board configurations.

    Example: - Input: n = 4 - Output: [[".Q..","...Q","Q...","..Q."],["..Q.","Q...","...Q",".Q.."]]

    Approach: Row-by-Row Backtracking with O(1) Conflict Tracking - Place queens one row at a time via recursion (each row can have at most one queen, so this naturally avoids row conflicts); at each row, try every column and check whether placing a queen there conflicts with any queen already placed in previous rows. - Use three boolean arrays to track occupied columns and the two diagonal directions (/ diagonal: row+col, \ diagonal: row-col) - this makes each placement check O(1) instead of re-scanning all previously placed queens. - Base case: once all N rows have a queen placed (row == N), the current board configuration is complete and valid - record it. - O(N!) time in the worst case (roughly N choices for row 0, N-1 for row 1, etc., pruned further by diagonal conflicts), O(N) space for the column/diagonal tracking arrays plus recursion depth.

    Time / Space: O(N!) time, O(N) space.

    private void solve(int row, int n, char[][] board, List<List<String>> result,
                   boolean[] col, boolean[] diag1, boolean[] diag2) {
    if (row == n) {
        List<String> config = new ArrayList<>();
        for (char[] r : board) config.add(new String(r));
        result.add(config);
        return;
    }
    for (int c = 0; c < n; c++) {
        if (col[c] || diag1[row + c] || diag2[row - c + n - 1]) continue;
        board[row][c] = 'Q';
        col[c] = diag1[row + c] = diag2[row - c + n - 1] = true;
        solve(row + 1, n, board, result, col, diag1, diag2);
        board[row][c] = '.';
        col[c] = diag1[row + c] = diag2[row - c + n - 1] = false;
    }
}

public List<List<String>> solveNQueens(int n) {
    List<List<String>> result = new ArrayList<>();
    char[][] board = new char[n][n];
    for (char[] row : board) Arrays.fill(row, '.');
    solve(0, n, board, result, new boolean[n], new boolean[2 * n], new boolean[2 * n]);
    return result;
}

    21. Rat in a Maze

    Difficulty: MEDIUM

    Statement/Hint: Given an N x N maze of 0s and 1s (1 = open path, 0 = blocked), find all paths for a rat to travel from the top-left cell to the bottom-right cell, moving only down, left, right, or up, without revisiting a cell.

    Example: - Input: maze = [[1,0,0,0],[1,1,0,1],[1,1,0,0],[0,1,1,1]] - Output: ["DDRDRR","DRDDRR"]

    Approach: Grid Backtracking with Explicit Visited Matrix - Recurse from the current cell, trying moves in a fixed direction order (commonly Down, Left, Right, Up to produce lexicographically sorted paths), only proceeding into a neighboring cell if it's within bounds, open (value 1), and not already visited in the current path. - Mark the current cell as visited before recursing into neighbors, and unmark it afterward (backtrack) - this allows the same cell to be reused on a different candidate path. - Base case: reaching the bottom-right cell means a complete path was found - record the direction string built so far (e.g. "DDRDRR"). - O(4^(n^2)) time in the worst case (4 choices at each of up to n^2 cells), O(n^2) space for the visited matrix and recursion depth.

    Time / Space: O(4^(n^2)) time, O(n^2) space.

    private void solve(int i, int j, int[][] maze, int n, int[][] visited, StringBuilder path, List<String> result) {
    if (i == n - 1 && j == n - 1) {
        result.add(path.toString());
        return;
    }
    int[] di = {1, 0, 0, -1};
    int[] dj = {0, -1, 1, 0};
    char[] dirChar = {'D', 'L', 'R', 'U'};
    for (int k = 0; k < 4; k++) {
        int ni = i + di[k], nj = j + dj[k];
        if (ni >= 0 && ni < n && nj >= 0 && nj < n && maze[ni][nj] == 1 && visited[ni][nj] == 0) {
            visited[ni][nj] = 1;
            path.append(dirChar[k]);
            solve(ni, nj, maze, n, visited, path, result);
            path.deleteCharAt(path.length() - 1);
            visited[ni][nj] = 0;
        }
    }
}

public List<String> findPath(int[][] maze, int n) {
    List<String> result = new ArrayList<>();
    if (maze[0][0] == 0) return result;
    int[][] visited = new int[n][n];
    visited[0][0] = 1;
    solve(0, 0, maze, n, visited, new StringBuilder(), result);
    return result;
}

    22. Word Break

    Difficulty: HIGH

    Statement/Hint: Given a string and a dictionary of words, determine whether the string can be segmented into a sequence of one or more dictionary words.

    Example: - Input: s = "leetcode", wordDict = ["leet","code"] - Output: true

    Approach: Backtracking over Split Points with Memoization - Recurse over starting positions: at each start index, try every possible end index for the "next word," and only recurse further (from end+1) if the substring from start to end exists in the dictionary - otherwise skip that end index. - Base case: start reaching the end of the string means the entire string was successfully segmented - return true, short-circuiting further exploration. - The naive recursion re-solves the same "can the suffix starting at index i be segmented" subproblem repeatedly across different paths - memoizing on the start index turns this into O(n^2) instead of exponential recursion. - O(2^n) time without memoization (exponential due to overlapping subproblems), O(n^2) time with memoization on start index, O(n) space for the recursion stack (plus O(n) for memoization).

    Time / Space: O(n^2) time with memo, O(n) space.

    private boolean solve(int start, String s, Set<String> dict, int[] memo) {
    if (start == s.length()) return true;
    if (memo[start] != -1) return memo[start] == 1;
    for (int end = start; end < s.length(); end++) {
        String piece = s.substring(start, end + 1);
        if (dict.contains(piece) && solve(end + 1, s, dict, memo)) {
            memo[start] = 1;
            return true;
        }
    }
    memo[start] = 0;
    return false;
}

public boolean wordBreak(String s, List<String> wordDict) {
    Set<String> dict = new HashSet<>(wordDict);
    int[] memo = new int[s.length()];
    Arrays.fill(memo, -1);
    return solve(0, s, dict, memo);
}

    23. M-Coloring Problem

    Difficulty: MEDIUM

    Statement/Hint: Given an undirected graph and M colors, determine whether the graph's vertices can be colored using at most M colors such that no two adjacent vertices share the same color.

    Example: - Input: graph = 4-cycle (0-1-2-3-0), m = 3 - Output: true

    Approach: Vertex-by-Vertex Backtracking with Adjacency Check - Recurse vertex by vertex (0 to n-1); at each vertex, try every color from 1 to M, checking whether assigning that color conflicts with any already-colored adjacent vertex. - The conflict check (isSafe) scans the vertex's row in the adjacency matrix and rejects a color if any adjacent vertex already has it - O(n) per check, so O(n*M) per vertex overall. - Base case: if all n vertices have been successfully colored (vertex == n), a valid full coloring was found - return true. Backtrack (uncolor and try the next color) if a vertex can't be colored safely with any of the M colors. - O(M^n) time in the worst case (M choices for each of n vertices), O(n) space for the color assignment array plus recursion depth.

    Time / Space: O(M^n) time, O(n) space.

    private boolean isSafe(int node, int[][] graph, int[] color, int c, int n) {
    for (int k = 0; k < n; k++) {
        if (graph[node][k] == 1 && color[k] == c) return false;
    }
    return true;
}

private boolean solve(int node, int[][] graph, int[] color, int m, int n) {
    if (node == n) return true;
    for (int c = 1; c <= m; c++) {
        if (isSafe(node, graph, color, c, n)) {
            color[node] = c;
            if (solve(node + 1, graph, color, m, n)) return true;
            color[node] = 0;
        }
    }
    return false;
}

public boolean graphColoring(int[][] graph, int m, int n) {
    int[] color = new int[n];
    return solve(0, graph, color, m, n);
}

    24. Sudoku Solver

    Difficulty: HIGH

    Statement/Hint: Given a partially filled 9x9 Sudoku board, fill in the empty cells so the completed board follows Sudoku rules (each row, column, and 3x3 sub-box contains digits 1-9 exactly once).

    Example: - Input: a 9x9 board with some cells pre-filled and others marked '.' - Output: the same board with every '.' replaced by a valid digit satisfying all Sudoku constraints

    Approach: Cell-by-Cell Backtracking with Row/Column/Box Validation - Scan for the next empty cell and try placing each digit 1-9 in it; before committing a digit, verify it doesn't already appear in the same row, same column, or same 3x3 sub-box. - Recurse to solve the rest of the board after tentatively placing a digit; if that recursive call fails (no valid completion exists), undo the placement (backtrack) and try the next digit. - Base case: if no empty cell remains, the board is completely and validly filled - return true, which propagates back up through all the recursive calls without further backtracking. - O(9^n) time in the worst case where n is the number of empty cells (9 candidate digits per empty cell), O(1) extra space beyond the board itself (aside from recursion depth) since validity checks scan the fixed-size board directly.

    Time / Space: O(9^n) time, O(1) space.

    private boolean isValid(char[][] board, int row, int col, char c) {
    for (int i = 0; i < 9; i++) {
        if (board[row][i] == c) return false;
        if (board[i][col] == c) return false;
        if (board[3 * (row / 3) + i / 3][3 * (col / 3) + i % 3] == c) return false;
    }
    return true;
}

private boolean solve(char[][] board) {
    for (int row = 0; row < 9; row++) {
        for (int col = 0; col < 9; col++) {
            if (board[row][col] == '.') {
                for (char c = '1'; c <= '9'; c++) {
                    if (isValid(board, row, col, c)) {
                        board[row][col] = c;
                        if (solve(board)) return true;
                        board[row][col] = '.';
                    }
                }
                return false;
            }
        }
    }
    return true;
}

public void solveSudoku(char[][] board) {
    solve(board);
}

    25. Expression Add Operators

    Difficulty: HIGH

    Statement/Hint: Given a string of digits and a target integer, insert the binary operators '+', '-', or '*' between digits (no unary operators) so that the resulting expression evaluates to the target. Return all such expressions.

    Example: - Input: num = "123", target = 6 - Output: ["1+2+3","1*2*3"]

    Approach: Backtracking with Running Total and Last-Operand Adjustment - Recurse over the digit string, at each position trying every possible next operand length (1 or more digits), and for each candidate operand trying all three operators - skip any operand with a leading zero longer than one digit (e.g. "05" is invalid), since numbers can't have leading zeros. - Track both the running evaluated total AND the value of the last operand added, because multiplication needs to "undo" the previous addition/subtraction and reapply it with higher precedence: new total = total - lastOperand + lastOperand * currentOperand. - Base case: when the entire digit string has been consumed, check whether the running total equals the target; if so, record the built expression string. - O(4^n) time (at each of n positions, roughly 3 operators x multiple split lengths), O(n) space for the recursion stack and expression string being built.

    Time / Space: O(4^n) time, O(n) space.

    private void solve(String num, int target, int idx, String expr, long total, long lastOperand, List<String> result) {
    if (idx == num.length()) {
        if (total == target) result.add(expr);
        return;
    }
    for (int len = 1; idx + len <= num.length(); len++) {
        String part = num.substring(idx, idx + len);
        if (len > 1 && part.charAt(0) == '0') break;
        long val = Long.parseLong(part);
        if (idx == 0) {
            solve(num, target, idx + len, part, val, val, result);
        } else {
            solve(num, target, idx + len, expr + "+" + part, total + val, val, result);
            solve(num, target, idx + len, expr + "-" + part, total - val, -val, result);
            solve(num, target, idx + len, expr + "*" + part, total - lastOperand + lastOperand * val, lastOperand * val, result);
        }
    }
}

public List<String> addOperators(String num, int target) {
    List<String> result = new ArrayList<>();
    solve(num, target, 0, "", 0, 0, result);
    return result;
}
