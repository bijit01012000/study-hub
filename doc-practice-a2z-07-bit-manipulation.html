    1. Odd or Even (Bitwise)

    Problem. Check whether a given integer n is odd, using a bitwise operation instead of the modulo operator.

    Difficulty: LOW

    Input: n = 7

    Output: true (odd)

    • The LSB of a number's binary representation is 1 if and only if the number is odd (every power of 2 above bit 0 contributes an even value).
    • Mask with 1 using AND: n & 1 - result is 1 for odd, 0 for even.
    • O(1) time, O(1) space - faster than n % 2 on some architectures since it avoids a division instruction.

    Time: O(1) | Space: O(1)

    LSB Mask

    public boolean isOdd(int n) {
    return (n & 1) == 1;
}

    2. Power of Two

    Problem. Check whether a positive integer n is a power of 2 (1, 2, 4, 8, 16, ...).

    Difficulty: LOW

    Input: n = 16

    Output: true

    • A power of 2 has exactly one set bit (e.g. 8 = 1000). Subtracting 1 flips that single set bit to 0 and all bits below it to 1 (8-1 = 7 = 0111) - so n & (n-1) clears the lowest set bit and equals 0 only when n had exactly one set bit.
    • Must also check n > 0, since n = 0 gives n & (n-1) = 0 & -1 which is nonzero, but 0 is not a power of 2 anyway - and the check should reject negative n.
    • O(1) time, O(1) space.

    Time: O(1) | Space: O(1)

    Clear Lowest Set Bit

    public boolean isPowerOfTwo(int n) {
    return n > 0 && (n & (n - 1)) == 0;
}

    3. Count Set Bits

    Problem. Count the number of set bits (1s) in the binary representation of a non-negative integer n.

    Difficulty: MEDIUM

    Input: n = 11 (binary 1011)

    Output: 3

    • Brian Kernighan's algorithm: repeatedly clear the lowest set bit with n = n & (n-1) and increment a counter, until n becomes 0 - each iteration removes exactly one set bit.
    • This runs in time proportional to the number of set bits (at most 32 for a 32-bit int), rather than iterating over all 32 bit positions regardless of how many are set.
    • O(number of set bits) ~ O(log n) time, O(1) space.

    Time: O(log n) | Space: O(1)

    Brian Kernighan's Algorithm

    public int countSetBits(int n) {
    int count = 0;
    while (n != 0) {
        n &= (n - 1);
        count++;
    }
    return count;
}

    4. Set Rightmost Unset Bit

    Problem. Given a number n, set its rightmost unset bit (the lowest-order 0 bit) to 1, leaving all other bits unchanged.

    Difficulty: LOW

    Input: n = 5 (binary 101)

    Output: 7 (binary 111)

    • Adding 1 to n flips every trailing 1 bit to 0 and the first 0 bit it encounters to 1 (standard binary increment carry behavior).
    • OR-ing n with (n+1) restores all the trailing 1 bits that the increment zeroed out, while keeping the newly-set bit - net effect: only the rightmost unset bit changes, from 0 to 1.
    • O(1) time, O(1) space - no loop needed.

    Time: O(1) | Space: O(1)

    OR with n+1

    public int setRightmostUnsetBit(int n) {
    return n | (n + 1);
}

    5. Swap Two Numbers (XOR)

    Problem. Swap the values of two integer variables a and b without using a temporary variable.

    Difficulty: LOW

    Input: a = 5, b = 9

    Output: a = 9, b = 5

    • XOR swap: a ^= b (a now holds a^b); b ^= a (b becomes b^(a^b) = a, since b^b cancels); a ^= b (a becomes (a^b)^a = b, since a^a cancels).
    • Relies on XOR's self-inverse property (x^x = 0) and identity property (x^0 = x) to reconstruct each original value from the combined a^b.
    • O(1) time, O(1) space - but only safe when a and b are distinct memory locations (XOR-swapping a variable with itself zeroes it out).

    Time: O(1) | Space: O(1)

    XOR Swap

    public void swapXOR(int[] arr, int i, int j) {
    arr[i] ^= arr[j];
    arr[j] ^= arr[i];
    arr[i] ^= arr[j];
}

    6. Check i-th Bit

    Problem. Given a number n and an index i (0-indexed from the LSB), check whether the i-th bit of n is set (1) or not (0).

    Difficulty: LOW

    Input: n = 13 (binary 1101), i = 2

    Output: true (bit at index 2 is 1)

    • Right-shift n by i positions so the target bit lands in the LSB position, then mask with 1 using AND: (n >> i) & 1.
    • Equivalently, build a mask with a single 1 at position i (1 << i) and AND it with n - the bit is set if the result is nonzero.
    • O(1) time, O(1) space - a single shift and mask.

    Time: O(1) | Space: O(1)

    Right Shift + Mask

    public boolean checkIthBit(int n, int i) {
    return ((n >> i) & 1) == 1;
}

    7. Divide Two Integers

    Problem. Divide two integers dividend and divisor without using multiplication, division, or the mod operator. Return the quotient, truncated toward zero, clamped to the 32-bit signed integer range.

    Difficulty: MEDIUM

    Input: dividend = 22, divisor = 3

    Output: 7

    • Work with the absolute values as longs (to avoid overflow when negating INT_MIN), and track the sign of the result separately from the XOR of the two original signs.
    • Binary long division: repeatedly find the largest value divisor << k such that (divisor << k) <= remaining dividend, subtract it out, and add (1 << k) to the quotient - this is like doubling-and-subtracting instead of one-at-a-time subtraction, giving O(log^2 n) instead of O(n).
    • Clamp the final signed result to [INT_MIN, INT_MAX] since dividing INT_MIN by -1 would otherwise overflow.
    • O(log^2 n) time (log n outer iterations, each doing an O(log n) shift-search), O(1) space.

    Time: O(log^2 n) | Space: O(1)

    Binary Long Division (Shift + Subtract)

    public int divide(int dividend, int divisor) {
    if (dividend == Integer.MIN_VALUE && divisor == -1) return Integer.MAX_VALUE;
    long a = Math.abs((long) dividend), b = Math.abs((long) divisor);
    int sign = ((dividend < 0) ^ (divisor < 0)) ? -1 : 1;
    long quotient = 0;
    while (a >= b) {
        long temp = b, multiple = 1;
        while (a >= (temp << 1)) {
            temp <<= 1;
            multiple <<= 1;
        }
        a -= temp;
        quotient += multiple;
    }
    return (int) (sign * quotient);
}

    8. Minimum Bit Flips to Convert Number

    Problem. Given two integers start and goal, find the minimum number of bit flips required to convert start into goal.

    Difficulty: MEDIUM

    Input: start = 10, goal = 7

    Output: 3

    • XOR-ing start and goal produces a number whose set bits are exactly the positions where the two numbers differ - every differing bit needs exactly one flip.
    • So the answer is simply the count of set bits in (start ^ goal), computed with Brian Kernighan's algorithm (n & (n-1) repeatedly).
    • O(log n) time, O(1) space.

    Time: O(log n) | Space: O(1)

    XOR + Popcount

    public int minBitFlips(int start, int goal) {
    int diff = start ^ goal;
    int count = 0;
    while (diff != 0) {
        diff &= (diff - 1);
        count++;
    }
    return count;
}

    9. Single Number

    Problem. Given an array where every element appears exactly twice except for one element that appears exactly once, find that single element in O(n) time and O(1) extra space.

    Difficulty: MEDIUM

    Input: nums = [4, 1, 2, 1, 2]

    Output: 4

    • XOR is commutative, associative, self-inverse (x^x=0), and has identity 0 (x^0=x) - XOR-ing every element together cancels all the pairs (each pair XORs to 0), leaving only the unpaired element.
    • No sorting or hash set needed, which is what makes it O(n) time and O(1) space instead of O(n) space for a frequency map.
    • O(n) time, O(1) space.

    Time: O(n) | Space: O(1)

    XOR All Elements

    public int singleNumber(int[] nums) {
    int result = 0;
    for (int x : nums) result ^= x;
    return result;
}

    10. Subsets (Power Set)

    Problem. Given an array nums of n distinct integers, return all possible subsets (the power set) using bitmasking instead of recursion.

    Difficulty: MEDIUM

    Input: nums = [1, 2, 3]

    Output: [[], [1], [2], [1,2], [3], [1,3], [2,3], [1,2,3]]

    • Every subset corresponds to a unique bitmask from 0 to 2^n - 1: bit j of the mask being 1 means nums[j] is included in that subset.
    • Iterate mask from 0 to (1<<n)-1, and for each mask, iterate its bits j from 0 to n-1, appending nums[j] to the current subset whenever bit j is set.
    • Avoids recursive call overhead entirely - iterative and easy to reason about since each mask deterministically maps to one subset.
    • O(n * 2^n) time (2^n subsets, O(n) to build each), O(n) extra space per subset excluding output storage.

    Time: O(n * 2^n) | Space: O(n)

    Bitmask Enumeration

    public List<List<Integer>> subsets(int[] nums) {
    int n = nums.length;
    List<List<Integer>> result = new ArrayList<>();
    for (int mask = 0; mask < (1 << n); mask++) {
        List<Integer> subset = new ArrayList<>();
        for (int j = 0; j < n; j++) {
            if ((mask & (1 << j)) != 0) subset.add(nums[j]);
        }
        result.add(subset);
    }
    return result;
}

    11. XOR of Range [L, R]

    Problem. Given two integers L and R, find the XOR of all integers from L to R (inclusive) without iterating over the whole range.

    Difficulty: MEDIUM

    Input: L = 3, R = 9

    Output: 2

    • Define xorUpto(n) = XOR of all integers from 1 to n. This follows a repeating pattern based on n mod 4: n -> n, n -> 1, n+1 -> 0, based on n%4 == 0, 1, 2, 3 respectively (derived from how consecutive XORs telescope in groups of 4).
    • The XOR of the range [L, R] equals xorUpto(R) ^ xorUpto(L-1), since XOR-ing xorUpto(L-1) again cancels out the 1..L-1 portion that xorUpto(R) included.
    • O(1) time, O(1) space - versus O(R-L) for a naive loop.

    Time: O(1) | Space: O(1)

    XOR-from-1-to-n Pattern (mod 4)

    private int xorUpto(int n) {
    switch (n % 4) {
        case 0: return n;
        case 1: return 1;
        case 2: return n + 1;
        default: return 0;
    }
}

public int xorInRange(int L, int R) {
    return xorUpto(R) ^ xorUpto(L - 1);
}

    12. Single Number III

    Problem. Given an array where exactly two elements appear once and every other element appears exactly twice, find the two unique elements in O(n) time and O(1) extra space.

    Difficulty: HIGH

    Input: nums = [1, 2, 1, 3, 2, 5]

    Output: [3, 5] (order may vary)

    • XOR-ing every element gives xorAll = a ^ b (the two unique elements), since all paired elements cancel out.
    • Since a != b, xorAll is nonzero, so it has at least one set bit; isolate the lowest set bit with diffBit = xorAll & (- xorAll) (two's-complement negation flips bits below and including the lowest set bit, so ANDing with the original isolates just that bit).
    • That bit is guaranteed to differ between a and b (since it's set in their XOR), so partition all array elements into two groups by whether they have that bit set, and XOR within each group - pairs stay together in the same group and cancel, leaving exactly one unique element per group.
    • O(n) time, O(1) space.

    Time: O(n) | Space: O(1)

    XOR All + Partition by Lowest Differing Bit

    public int[] singleNumberIII(int[] nums) {
    long xorAll = 0;
    for (int x : nums) xorAll ^= x;
    long diffBit = xorAll & (-xorAll);
    int a = 0, b = 0;
    for (int x : nums) {
        if ((x & diffBit) != 0) a ^= x;
        else b ^= x;
    }
    return new int[]{a, b};
}

    13. Prime Factors

    Problem. Print all prime factors of a number n, with repetition (e.g. 12 = 2 * 2 * 3).

    Difficulty: HIGH

    Input: n = 100

    Output: [2, 2, 5, 5]

    • Trial-divide n by every integer i from 2 up to sqrt(n): while n is divisible by i, repeatedly divide n by i and record i as a factor - this strips out all copies of each small prime factor before moving to the next i.
    • Once i exceeds sqrt(n), whatever remains of n (if > 1) must itself be a single remaining prime factor, since any composite remainder would have already been reduced by a smaller factor.
    • Only needing to check up to sqrt(n) - instead of up to n - is what keeps this efficient: n can have at most one prime factor greater than sqrt(n).
    • O(sqrt(n)) time, O(1) extra space (excluding output).

    Time: O(sqrt(n)) | Space: O(1)

    Trial Division up to sqrt(n)

    public List<Integer> primeFactors(int n) {
    List<Integer> factors = new ArrayList<>();
    for (int i = 2; (long) i * i <= n; i++) {
        while (n % i == 0) {
            factors.add(i);
            n /= i;
        }
    }
    if (n > 1) factors.add(n);
    return factors;
}

    14. Count Primes in Range

    Problem. Given a range [L, R], count how many primes lie within it, where multiple such range queries may need answering efficiently.

    Difficulty: HIGH

    Input: L = 10, R = 20

    Output: 4 (primes: 11, 13, 17, 19)

    • Build a Sieve of Eratosthenes up to R once: start with all numbers marked prime, then for each prime p starting from 2, mark all multiples of p (starting from p*p, since smaller multiples were already marked by smaller primes) as composite.
    • After sieving, counting primes in [L, R] is a simple linear scan over the precomputed boolean array (or a prefixcount array for O(1) per query across many queries).
    • O(R log log R) time to build the sieve, O(R) space for the boolean array.

    Time: O(R log log R) | Space: O(R)

    Sieve of Eratosthenes

    public int countPrimesInRange(int L, int R) {
    boolean[] isComposite = new boolean[R + 1];
    int count = 0;
    for (int i = 2; i <= R; i++) {
        if (!isComposite[i]) {
            if (i >= L) count++;
            for (long j = (long) i * i; j <= R; j += i) {
                isComposite[(int) j] = true;
            }
        }
    }
    return count;
}

    15. Smallest Prime Factor Sieve

    Problem. Given many numbers up to N to factorize, precompute a structure so each number's prime factorization can be produced in O(log n) instead of O(sqrt(n)) per query.

    Difficulty: HIGH

    Input: N = 360 (SPF table built up to N, then factorize 360)

    Output: [2, 2, 2, 3, 3, 5]

    • Precompute a Smallest Prime Factor (SPF) array via a modified sieve: for each prime p (found when spf[p] is still unset), mark spf[multiple] = p for every unmarked multiple of p starting from p*p - each composite ends up storing the smallest prime that divides it.
    • To factorize a number n using the SPF table: repeatedly take factor = spf[n], record it, and divide n by it (n /= spf[n]) until n == 1 - since dividing by the smallest prime factor each time still takes only O(log n) steps (n at least halves every 1-2 steps).
    • Building the SPF table costs O(N log log N) once; each subsequent factorization query then costs only O(log n), which is why this beats plain trial division when factorizing many numbers.
    • O(N log log N) preprocessing, O(log n) per query, O(N) space for the SPF table.

    Time: O(N log log N) build, O(log n) per query | Space: O(N)

    Smallest Prime Factor (SPF) Sieve

    public int[] buildSPF(int N) {
    int[] spf = new int[N + 1];
    for (int i = 1; i <= N; i++) spf[i] = i;
    for (int i = 2; (long) i * i <= N; i++) {
        if (spf[i] == i) {
            for (long j = (long) i * i; j <= N; j += i) {
                if (spf[(int) j] == (int) j) spf[(int) j] = i;
            }
        }
    }
    return spf;
}

public List<Integer> factorizeWithSPF(int n, int[] spf) {
    List<Integer> factors = new ArrayList<>();
    while (n != 1) {
        factors.add(spf[n]);
        n /= spf[n];
    }
    return factors;
}
