    Backpressure

    6 sections · 453 words

    What happens when the consumer is slower. Messaging & Async, concept 29 of 36.

    The Idea

    What happens when a producer creates work faster than the consumer that has to process it? Without backpressure, the work just piles up in a buffer until something runs out of memory and the whole thing falls over. With backpressure, the system pushes back deliberately: slows the producer down, drops messages, or buffers only up to a limit and then refuses more, instead of failing silently later.

    A buffer filling faster than it drains: Producer (fast) -> Buffer (filling up) -> Consumer (slow). Without backpressure, the buffer just keeps growing until memory runs out.

    Watch Out For

    • A system with no backpressure at all looks perfectly healthy right up until the moment it runs out of memory and crashes hard.
    • Backpressure implemented only on paper, with an unbounded queue and a comment saying this should never fill up, is not backpressure.

    Where You Will See It

    • TCP itself, which uses flow control windows to slow a sender down when a receiver cannot keep up.
    • Reactive streams libraries (RxJava, Project Reactor), built specifically to propagate backpressure through a processing pipeline.
    • Load shedding at API gateways, rejecting excess requests outright once capacity is reached.

    How It Connects

    • Message Queues: a bounded queue is the simplest form of backpressure between a producer and a consumer.
    • Rate Limiting: a related idea applied at the edge, capping load before it ever reaches an internal queue.
    • Circuit Breaker: both stop a system from being overwhelmed, but backpressure regulates flow while a circuit breaker cuts it off entirely.

    Follow-Up Questions

    1. A producer generates events faster than a consumer can process them, with no limit on the buffer between them. What eventually happens? The buffer grows unbounded until the process runs out of memory and crashes, taking down data that was still queued.

    2. A queue is given a maximum size, and producers block once it is full. What is that an example of? Backpressure: pushing back on the producer instead of letting work pile up without limit.

    3. What are the three broad responses a system can take under backpressure? Slow the producer down, drop some messages, or buffer up to a limit and reject anything past it.

    4. Why is silently dropping requests sometimes preferable to letting a system fall over completely? A controlled, visible failure for some requests is recoverable. An out-of-memory crash loses everything, including requests that were not even the problem.

    Recall It As

    An unbounded buffer is not a buffer. It is a slow-motion crash waiting for enough time to pass.
