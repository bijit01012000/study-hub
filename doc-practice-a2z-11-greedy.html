    1. Assign Cookies

    Difficulty: LOW

    Statement/Hint: Given children's greed factors g[] and cookie sizes s[], where a child i is content if given a cookie of size >= g[i], maximize the number of content children (each cookie satisfies at most one child).

    Example: - Input: g = [1,2,3], s = [1,1] - Output: 1

    Approach: Sort + Two Pointers (Match Smallest Sufficient) - Sort both greed factors and cookie sizes ascending - greedily giving the smallest sufficient cookie to the least-greedy unsatisfied child never wastes capacity that a greedier child might need later. - Walk both sorted arrays with two pointers: if the current cookie satisfies the current child (cookie >= greed), advance both pointers and count a match; otherwise the cookie is too small for anyone remaining, so only advance the cookie pointer. - Stop when either array is exhausted; the match count is the answer. - O(n log n + m log m) time (dominated by sorting both arrays), O(1) extra space.

    Time / Space: O(n log n + m log m) time, O(1) space.

    public int findContentChildren(int[] g, int[] s) {
    Arrays.sort(g);
    Arrays.sort(s);
    int i = 0, j = 0, count = 0;
    while (i < g.length && j < s.length) {
        if (s[j] >= g[i]) {
            count++;
            i++;
        }
        j++;
    }
    return count;
}

    2. Fractional Knapsack

    Difficulty: MEDIUM

    Statement/Hint: Given item weights and values and a knapsack capacity W, where fractions of an item may be taken, maximize the total value.

    Example: - Input: items = [(value=60,weight=10),(value=100,weight=20),(value=120,weight=30)], W = 50 - Output: 240.0

    Approach: Sort by Value Density (Greedy Fill) - Compute each item's value-per-unit-weight ratio, then sort items descending by that ratio - filling the knapsack with the highest-density item first can never be beaten by any other order, since swapping a lower-density item in earlier only wastes capacity. - Take whole items greedily while capacity remains; when the next item no longer fits whole, take exactly the fraction that fills the remaining capacity, then stop (every later item has equal or lower density and no room remains). - Unlike 0/1 Knapsack, allowing fractions removes the need for DP entirely - the greedy exchange argument is airtight once partial items are allowed. - O(n log n) time (sorting by ratio), O(1) extra space.

    Time / Space: O(n log n) time, O(1) space.

    public double fractionalKnapsack(int W, int[][] items) {
    Arrays.sort(items, (a, b) -> Double.compare((double) b[0] / b[1], (double) a[0] / a[1]));
    double totalValue = 0;
    int remaining = W;
    for (int[] item : items) {
        int value = item[0], weight = item[1];
        if (weight <= remaining) {
            totalValue += value;
            remaining -= weight;
        } else {
            totalValue += value * ((double) remaining / weight);
            break;
        }
    }
    return totalValue;
}

    3. Lemonade Change

    Difficulty: LOW

    Statement/Hint: Each lemonade costs $5; customers pay with a $5, $10, or $20 bill in order, and you start with no change. Determine whether you can give correct change to every customer.

    Example: - Input: bills = [5,5,5,10,20] - Output: true

    Approach: Greedy Bill Counting (Prefer Fives) - Only $5 and $10 bills are ever useful as change (a $20 can't make change for anything smaller), so just track counts of $5s and $10s on hand. - For a $5 bill: no change needed, just add it to the $5 count. - For a $10 bill: must give one $5 back - fail immediately if none available; otherwise consume one $5, add one $10. - For a $20 bill: prefer giving a $10 + a $5 over three $5s when possible - this greedily conserves $5 bills, which are more broadly useful (needed for both $10 and $20 change) than $10 bills (only useful for $20 change). - O(n) time, O(1) space.

    Time / Space: O(n) time, O(1) space.

    public boolean lemonadeChange(int[] bills) {
    int five = 0, ten = 0;
    for (int bill : bills) {
        if (bill == 5) {
            five++;
        } else if (bill == 10) {
            if (five == 0) return false;
            five--;
            ten++;
        } else {
            if (ten > 0 && five > 0) {
                ten--;
                five--;
            } else if (five >= 3) {
                five -= 3;
            } else {
                return false;
            }
        }
    }
    return true;
}

    4. Valid Parenthesis String

    Difficulty: MEDIUM

    Statement/Hint: Given a string containing '(', ')', and '' (where '' can be treated as '(', ')', or an empty string), determine whether the string can form a valid parentheses sequence.

    Example: - Input: s = "(*))" - Output: true

    Approach: Range Tracking (Min/Max Open Count) - Track a range [loMin, hiMax] of the possible number of unmatched open parentheses, instead of a single count - since each '' is ambiguous, tracking a range covers every interpretation simultaneously without branching. - For '(': both bounds increase by 1. For ')': both bounds decrease by 1. For '': the low bound decreases by 1 (treat as ')') and the high bound increases by 1 (treat as '('). - Clamp loMin to 0 whenever it goes negative (an interpretation with too many closes so far is simply discarded, not tracked) - but if hiMax ever goes negative, no interpretation can recover, so return false immediately. - The string is valid iff loMin == 0 at the end (some interpretation closes every open exactly). O(n) time, O(1) space.

    Time / Space: O(n) time, O(1) space.

    public boolean checkValidString(String s) {
    int loMin = 0, hiMax = 0;
    for (char c : s.toCharArray()) {
        if (c == '(') {
            loMin++;
            hiMax++;
        } else if (c == ')') {
            loMin--;
            hiMax--;
        } else {
            loMin--;
            hiMax++;
        }
        if (hiMax < 0) return false;
        loMin = Math.max(loMin, 0);
    }
    return loMin == 0;
}

    5. N Meetings in One Room

    Difficulty: HIGH

    Statement/Hint: Given n meetings with start and end times, find the maximum number of meetings that can be held in a single room (no two selected meetings may overlap).

    Example: - Input: start = [1,3,0,5,8,5], end = [2,4,6,7,9,9] - Output: 4

    Approach: Sort by End Time (Activity Selection) - Sort meetings by end time ascending - greedily picking the meeting that finishes earliest always leaves the most remaining room for future meetings, compared to picking by start time or duration. - Scan the sorted meetings, keeping a "last selected end time"; select a meeting only if its start time is strictly after the last selected end time, and update the last end time on selection. - This is the classic activity-selection greedy proof: any optimal solution can be transformed to also pick the earliest-finishing meeting first without losing count. - O(n log n) time (sorting dominates), O(n) space to pair times together, O(1) beyond that.

    Time / Space: O(n log n) time, O(n) space.

    public int maxMeetings(int[] start, int[] end) {
    int n = start.length;
    int[][] meetings = new int[n][2];
    for (int i = 0; i < n; i++) meetings[i] = new int[]{end[i], start[i]};
    Arrays.sort(meetings, (a, b) -> a[0] - b[0]);
    int count = 0, lastEnd = -1;
    for (int[] m : meetings) {
        if (m[1] > lastEnd) {
            count++;
            lastEnd = m[0];
        }
    }
    return count;
}

    6. Jump Game

    Difficulty: MEDIUM

    Statement/Hint: Given an array where each element is the maximum jump length from that position, determine whether you can reach the last index starting from index 0.

    Example: - Input: nums = [2,3,1,1,4] - Output: true

    Approach: Greedy Frontier Extension - Track the farthest index reachable so far; at each index i (only while i is within that reachable range), update farthest = max(farthest, i + nums[i]). - If farthest ever reaches or passes the last index, the array is reachable - return true early. - If the loop reaches an index i that exceeds the current farthest before that happens, no jump can bridge the gap, so return false. - O(n) time (single pass), O(1) space - no need to try every jump combination.

    Time / Space: O(n) time, O(1) space.

    public boolean canJump(int[] nums) {
    int n = nums.length;
    int farthest = 0;
    for (int i = 0; i < n; i++) {
        if (i > farthest) return false;
        farthest = Math.max(farthest, i + nums[i]);
        if (farthest >= n - 1) return true;
    }
    return true;
}

    7. Jump Game II

    Difficulty: MEDIUM

    Statement/Hint: Given an array where each element is the maximum jump length from that position, find the minimum number of jumps needed to reach the last index (guaranteed reachable).

    Example: - Input: nums = [2,3,1,1,4] - Output: 2

    Approach: Greedy Level-by-Level Jumps - Process the array in "levels": each level represents everywhere reachable using one more jump than the previous level, similar to BFS layer-by-layer expansion. - Maintain currentEnd (the farthest reachable with the jumps used so far) and farthest (the farthest reachable with one more jump); scan indices, updating farthest = max(farthest, i + nums[i]) each step. - When i reaches currentEnd, a jump is forced to continue past this point - increment the jump count and set currentEnd = farthest, then keep scanning. - O(n) time (single pass), O(1) space - far better than the O(n^2) DP of trying every jump length from every index.

    Time / Space: O(n) time, O(1) space.

    public int jump(int[] nums) {
    int n = nums.length;
    int jumps = 0, currentEnd = 0, farthest = 0;
    for (int i = 0; i < n - 1; i++) {
        farthest = Math.max(farthest, i + nums[i]);
        if (i == currentEnd) {
            jumps++;
            currentEnd = farthest;
        }
    }
    return jumps;
}

    8. Minimum Platforms

    Difficulty: HIGH

    Statement/Hint: Given arrival and departure times of n trains at a station, find the minimum number of platforms required so that no train has to wait.

    Example: - Input: arr = [900,940,950,1100,1500,1800], dep = [910,1200,1120,1130,1900,2000] - Output: 3

    Approach: Sort Arrivals/Departures + Two-Pointer Sweep - Sort arrival times and departure times independently (not as pairs) - only the relative ordering of all arrivals versus all departures matters for counting overlaps, not which specific train each time belongs to. - Walk both sorted arrays with two pointers, incrementing a running platform count whenever the next event is an arrival (arr[i] <= dep[j], using <= since a train arriving exactly when another departs still needs a platform) and decrementing it whenever the next event is a departure. - Track the maximum value the running count ever reaches - that peak is the minimum platforms needed. - O(n log n) time (sorting both arrays), O(1) extra space.

    Time / Space: O(n log n) time, O(1) space.

    public int findPlatform(int[] arr, int[] dep) {
    Arrays.sort(arr);
    Arrays.sort(dep);
    int n = arr.length;
    int i = 0, j = 0, platforms = 0, maxPlatforms = 0;
    while (i < n && j < n) {
        if (arr[i] <= dep[j]) {
            platforms++;
            maxPlatforms = Math.max(maxPlatforms, platforms);
            i++;
        } else {
            platforms--;
            j++;
        }
    }
    return maxPlatforms;
}

    9. Job Sequencing Problem

    Difficulty: HIGH

    Statement/Hint: Given n jobs, each with a deadline and a profit, where each job takes exactly one unit of time and only one job can run per unit, find the maximum profit obtainable by scheduling jobs (a job earns its profit only if completed by its deadline).

    Example: - Input: jobs = [(id=1,deadline=4,profit=20),(id=2,deadline=1,profit=10),(id=3,deadline=1,profit=40),(id=4,deadline=1,profit=30)] - Output: count = 2, profit = 60

    Approach: Sort by Profit + Latest-Slot Backfill - Sort jobs by profit descending - greedily trying to schedule the most profitable job first maximizes value captured before slots run out, since a lower-profit job can always yield to a higher one for the same slot. - For each job in that order, try to place it in the latest available time slot at or before its deadline (scan backward from min(deadline, maxDeadline) down to slot 1) - placing it as late as possible preserves earlier slots for jobs with tighter deadlines seen later. - A boolean occupied array (sized to the maximum deadline) tracks which slots are filled; skip a job entirely if every slot up to its deadline is already taken. - O(n log n + n * maxDeadline) time (sort, then a bounded backward scan per job), O(maxDeadline) space.

    Time / Space: O(n log n + n*maxDeadline) time, O(maxDeadline) space.

    public int[] jobSequencing(int[][] jobs) {
    // jobs: {id, deadline, profit}
    Arrays.sort(jobs, (a, b) -> b[2] - a[2]);
    int maxDeadline = 0;
    for (int[] job : jobs) maxDeadline = Math.max(maxDeadline, job[1]);
    boolean[] slot = new boolean[maxDeadline + 1];
    int count = 0, totalProfit = 0;
    for (int[] job : jobs) {
        for (int t = Math.min(job[1], maxDeadline); t > 0; t--) {
            if (!slot[t]) {
                slot[t] = true;
                count++;
                totalProfit += job[2];
                break;
            }
        }
    }
    return new int[]{count, totalProfit};
}

    10. Candy

    Difficulty: HIGH

    Statement/Hint: Given the ratings of n children standing in a line, give each child at least one candy such that any child with a higher rating than an immediate neighbor gets more candies than that neighbor; find the minimum total candies needed.

    Example: - Input: ratings = [1,0,2] - Output: 5

    Approach: Two-Pass Left-Right / Right-Left Max - Give every child 1 candy initially, then reconcile in two directional passes rather than trying to satisfy both neighbor comparisons at once. - Left-to-right pass: whenever rating[i] > rating[i-1], set candies[i] = candies[i-1] + 1 - this enforces the "higher than left neighbor" rule. - Right-to-left pass: whenever rating[i] > rating[i+1], set candies[i] = max(candies[i], candies[i+1] + 1) - the max is essential, since the left pass may have already given candies[i] a value that must be preserved if it's larger. - Sum all candies for the answer. O(n) time (two linear passes), O(n) space for the candies array.

    Time / Space: O(n) time, O(n) space.

    public int candy(int[] ratings) {
    int n = ratings.length;
    int[] candies = new int[n];
    Arrays.fill(candies, 1);
    for (int i = 1; i < n; i++) {
        if (ratings[i] > ratings[i - 1]) candies[i] = candies[i - 1] + 1;
    }
    for (int i = n - 2; i >= 0; i--) {
        if (ratings[i] > ratings[i + 1]) candies[i] = Math.max(candies[i], candies[i + 1] + 1);
    }
    int total = 0;
    for (int c : candies) total += c;
    return total;
}

    11. Shortest Job First

    Difficulty: MEDIUM

    Statement/Hint: Given n jobs' arrival times and burst (execution) times, find the average waiting time using the non-preemptive Shortest Job First CPU scheduling algorithm.

    Example: - Input: arrival = [0,1,2], burst = [8,4,9] - Output: average waiting time = 5.67 (run order: job0 wait 0, job1 wait 7, job2 wait 10; total 17 / 3)

    Approach: Greedy Shortest-Available-Job Simulation - Among all jobs that have already arrived by the current time, always pick the one with the smallest burst time next - this greedy minimizes average waiting time, since finishing short jobs first lets more jobs finish sooner overall (an exchange argument shows any other order increases total wait). - Simulate: maintain a current time; at each step, scan arrived-but-not-yet-run jobs for the smallest burst time, run it (advance current time by its burst), and record its waiting time as (start time - arrival time). - If no job has arrived yet at the current time, jump current time forward to the next arrival instead of idling job selection. - Average waiting time is the sum of all individual waits divided by n. O(n^2) time with a linear scan per step (O(n log n) achievable by pushing newly-arrived jobs into a min-heap keyed by burst time as current time advances), O(n) space.

    Time / Space: O(n^2) (O(n log n) with a heap pool) time, O(n) space.

    public double shortestJobFirst(int[] arrival, int[] burst) {
    int n = arrival.length;
    boolean[] done = new boolean[n];
    long currentTime = 0, totalWait = 0;
    int completed = 0;
    while (completed < n) {
        int best = -1;
        for (int i = 0; i < n; i++) {
            if (!done[i] && arrival[i] <= currentTime) {
                if (best == -1 || burst[i] < burst[best]) best = i;
            }
        }
        if (best == -1) {
            int nextArrival = Integer.MAX_VALUE;
            for (int i = 0; i < n; i++) if (!done[i]) nextArrival = Math.min(nextArrival, arrival[i]);
            currentTime = nextArrival;
            continue;
        }
        totalWait += currentTime - arrival[best];
        currentTime += burst[best];
        done[best] = true;
        completed++;
    }
    return (double) totalWait / n;
}

    12. Insert Interval

    Difficulty: MEDIUM

    Statement/Hint: Given a list of non-overlapping intervals sorted by start time, and a new interval, insert it into the list, merging overlaps as needed, and return the resulting sorted list of intervals.

    Example: - Input: intervals = [[1,3],[6,9]], newInterval = [2,5] - Output: [[1,5],[6,9]]

    Approach: Three-Phase Single Pass Merge - Split the work into three phases in a single left-to-right pass: first copy every interval that ends strictly before the new interval starts (no overlap possible, since intervals are sorted). - Then merge every interval that overlaps the new interval (its start is <= the new interval's current end) into the new interval by expanding its start to the min and its end to the max of both, growing the new interval as merges accumulate. - Finally copy every remaining interval that starts strictly after the merged new interval ends. - O(n) time (single pass over the input), O(n) space for the result.

    Time / Space: O(n) time, O(n) space.

    public int[][] insertInterval(int[][] intervals, int[] newInterval) {
    List<int[]> result = new ArrayList<>();
    int i = 0, n = intervals.length;
    while (i < n && intervals[i][1] < newInterval[0]) {
        result.add(intervals[i]);
        i++;
    }
    while (i < n && intervals[i][0] <= newInterval[1]) {
        newInterval[0] = Math.min(newInterval[0], intervals[i][0]);
        newInterval[1] = Math.max(newInterval[1], intervals[i][1]);
        i++;
    }
    result.add(newInterval);
    while (i < n) {
        result.add(intervals[i]);
        i++;
    }
    return result.toArray(new int[0][]);
}

    13. Merge Intervals

    Difficulty: HIGH

    Statement/Hint: Given an array of intervals, merge all overlapping intervals and return the resulting array of non-overlapping intervals covering all the input ranges.

    Example: - Input: intervals = [[1,3],[2,6],[8,10],[15,18]] - Output: [[1,6],[8,10],[15,18]]

    Approach: Sort by Start + Linear Scan Merge - Sort intervals by start time first - once sorted, any interval that overlaps the current merged interval must appear immediately in sequence, so a single linear scan suffices. - Keep a "current merged interval," initialized to the first; for each subsequent interval, if its start is <= the current merged interval's end, extend the current end to the max of both; otherwise the current interval can't merge further, so push it to the result and start a new current interval. - Push the final current interval after the scan ends. - O(n log n) time (dominated by the sort), O(n) space for the result.

    Time / Space: O(n log n) time, O(n) space.

    public int[][] mergeIntervals(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> a[0] - b[0]);
    List<int[]> result = new ArrayList<>();
    for (int[] interval : intervals) {
        if (result.isEmpty() || result.get(result.size() - 1)[1] < interval[0]) {
            result.add(interval);
        } else {
            result.get(result.size() - 1)[1] = Math.max(result.get(result.size() - 1)[1], interval[1]);
        }
    }
    return result.toArray(new int[0][]);
}

    14. Non-overlapping Intervals

    Difficulty: MEDIUM

    Statement/Hint: Given an array of intervals, find the minimum number of intervals to remove so that the rest are non-overlapping.

    Example: - Input: intervals = [[1,2],[2,3],[3,4],[1,3]] - Output: 1

    Approach: Sort by End Time (Activity Selection, Count Removals) - Sort intervals by end time ascending - the same activity-selection greedy as N Meetings in One Room: keeping the earliest-finishing interval at each step leaves the most room for the rest. - Scan the sorted intervals, tracking the end time of the last kept interval; keep the current interval (no removal) if its start is >= that last end, and update the last end - otherwise it overlaps, so it must be removed (increment a removal counter) and the last end is left unchanged, since keeping the earlier-ending interval is always at least as good. - The removal counter after the scan is the answer. - O(n log n) time (sort dominates), O(1) extra space.

    Time / Space: O(n log n) time, O(1) space.

    public int eraseOverlapIntervals(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> a[1] - b[1]);
    int removals = 0;
    int lastEnd = Integer.MIN_VALUE;
    for (int[] interval : intervals) {
        if (interval[0] >= lastEnd) {
            lastEnd = interval[1];
        } else {
            removals++;
        }
    }
    return removals;
}
