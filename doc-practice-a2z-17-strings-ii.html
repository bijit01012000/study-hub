    1. Minimum Characters to Add at Front for Palindrome

    Problem. Given a string, find the minimum number of characters to add at the FRONT to make the whole string a palindrome.

    Input: s = "AACECAAAA"

    Output: 2 (prepend "AA" -> "AAAACECAAAA")

    • We want the longest palindromic PREFIX of s; the remaining suffix, reversed, is what must be prepended. Answer = n - (length of longest palindromic prefix).
    • Compute it with the KMP failure function on the combined string t = s + "#" + reverse(s) (the '#' separator prevents overflow across the boundary). The final LPS (longest-prefix-suffix) value of t equals the longest palindromic prefix of s.
    • Intuition: a prefix of s that also matches a suffix of reverse(s) is a prefix of s that reads the same backwards - i.e. a palindromic prefix.
    • Answer is n minus that LPS value; the separator is essential so the matched border cannot exceed len(s).

    Time: O(n) | Space: O(n)

    KMP LPS on s + # + reverse(s)

    int minCharsForPalindrome(String s) {
    String rev = new StringBuilder(s).reverse().toString();
    String t = s + "#" + rev;
    int m = t.length();
    int[] lps = new int[m];
    for (int i = 1; i < m; i++) {
        int len = lps[i - 1];
        while (len > 0 && t.charAt(i) != t.charAt(len)) len = lps[len - 1];
        if (t.charAt(i) == t.charAt(len)) len++;
        lps[i] = len;
    }
    return s.length() - lps[m - 1];
}

    2. Longest Prefix Suffix (KMP Failure Function)

    Problem. Given a string, find the length of the longest proper prefix that is also a suffix (the value lps[n-1] of the KMP failure function). Proper means not the whole string.

    Input: s = "ababab"

    Output: 4 (prefix "abab" = suffix "abab")

    • Build the lps array where lps[i] = length of the longest proper prefix of s[0..i] that is also a suffix of s[0..i]. This is exactly the KMP preprocessing step.
    • Two pointers: len tracks the current border length. For each i, while s[i] != s[len] and len > 0, fall back to lps[len-1] (the next shorter border to try); if the characters match, increment len. Set lps[i] = len.
    • The fallback lps[len-1] is the heart of KMP: it reuses already-computed borders instead of rescanning, giving amortized O(n).
    • The answer is lps[n-1]. This same array powers linear-time pattern search and the palindrome-prefix trick.

    Time: O(n) | Space: O(n)

    Failure Function with Fallback

    int longestPrefixSuffix(String s) {
    int n = s.length();
    int[] lps = new int[n];
    int len = 0;
    for (int i = 1; i < n; i++) {
        while (len > 0 && s.charAt(i) != s.charAt(len)) len = lps[len - 1];
        if (s.charAt(i) == s.charAt(len)) len++;
        lps[i] = len;
    }
    return lps[n - 1];
}

    3. KMP Pattern Search

    Problem. Given a text and a pattern, find all starting indices where the pattern occurs in the text, in O(n + m) time.

    Input: text = "abxabcabcaby", pattern = "abcaby"

    Output: [6]

    • Precompute the pattern's lps (failure) array. Then scan the text with two pointers: i over text, j over pattern.
    • On a match advance both; on a mismatch with j > 0, fall back j = lps[j-1] (do NOT reset j to 0 or move i back) - this reuses the matched prefix and is what avoids re-scanning the text.
    • When j reaches the pattern length, record a match at i - m and continue by setting j = lps[j-1] to look for overlapping occurrences.
    • The failure array guarantees i never retreats, giving linear time - the definitive improvement over the O(n*m) naive scan.

    Time: O(n + m) | Space: O(m)

    LPS-Driven Scan

    List<Integer> kmpSearch(String text, String pat) {
    int n = text.length(), m = pat.length();
    int[] lps = new int[m];
    for (int i = 1, len = 0; i < m; ) {
        if (pat.charAt(i) == pat.charAt(len)) lps[i++] = ++len;
        else if (len > 0) len = lps[len - 1];
        else lps[i++] = 0;
    }
    List<Integer> res = new ArrayList<>();
    for (int i = 0, j = 0; i < n; ) {
        if (text.charAt(i) == pat.charAt(j)) { i++; j++; }
        if (j == m) { res.add(i - m); j = lps[j - 1]; }
        else if (i < n && text.charAt(i) != pat.charAt(j)) {
            if (j > 0) j = lps[j - 1];
            else i++;
        }
    }
    return res;
}

    4. Shortest Palindrome

    Problem. Given a string s, form the shortest palindrome by adding characters ONLY at the front. Return that palindrome.

    Input: s = "aacecaaa"

    Output: "aaacecaaa"

    • Same core as "min chars to make palindrome": find the longest palindromic PREFIX using the KMP lps of t = s + "#" + reverse(s). Let k = lps[last] be its length.
    • The characters of s AFTER that palindromic prefix (s[k..n-1]) reversed must be prepended. Construct the answer = reverse(s.substring(k)) + s.
    • The '#' separator again prevents the border from spanning both halves, so k never exceeds n.
    • This card differs from the "count only" version by actually CONSTRUCTING the result - the reversed leftover suffix glued in front of the original.

    Time: O(n) | Space: O(n)

    Longest Palindromic Prefix + Prepend

    String shortestPalindrome(String s) {
    String rev = new StringBuilder(s).reverse().toString();
    String t = s + "#" + rev;
    int m = t.length();
    int[] lps = new int[m];
    for (int i = 1, len = 0; i < m; ) {
        if (t.charAt(i) == t.charAt(len)) lps[i++] = ++len;
        else if (len > 0) len = lps[len - 1];
        else lps[i++] = 0;
    }
    int k = lps[m - 1];
    // longest palindromic prefix
    String suffix = new StringBuilder(s.substring(k)).reverse().toString();
    return suffix + s;
}

    5. Longest Happy Prefix

    Problem. A "happy prefix" is a non-empty prefix that is also a suffix (excluding the whole string). Given a string, return the longest happy prefix.

    Input: s = "level"

    Output: "l"

    • This is literally the KMP failure function: lps[n-1] gives the length of the longest proper prefix that is also a suffix. The answer is s.substring(0, lps[n-1]).
    • Build the lps array with the standard two-pointer fallback (len = lps[len-1] on mismatch), then slice the prefix of that length.
    • Recognizing that "happy prefix" is a rebranding of "longest prefix that is also a suffix" is the whole insight - no new algorithm, just the failure function plus a substring.
    • If lps[n-1] is 0, there is no happy prefix and the answer is the empty string.

    Time: O(n) | Space: O(n)

    lps[n-1] Prefix Slice

    String longestPrefix(String s) {
    int n = s.length();
    int[] lps = new int[n];
    for (int i = 1, len = 0; i < n; ) {
        if (s.charAt(i) == s.charAt(len)) lps[i++] = ++len;
        else if (len > 0) len = lps[len - 1];
        else lps[i++] = 0;
    }
    return s.substring(0, lps[n - 1]);
}

    6. Z-Function and Pattern Search

    Problem. Compute the Z-array of a string (Z[i] = length of the longest substring starting at i that matches a prefix of the string) and use it to find all pattern occurrences.

    Input: pattern = "aab", text = "aabxaabxcaab"

    Output: [0, 4, 9]

    • The Z-array maintains a "Z-box" [l, r], the rightmost interval known to match a prefix. For each i inside the box, initialize Z[i] from the mirror position Z[i-l], then extend by direct comparison; update [l, r] when the match reaches further right.
    • The box lets each character be compared O(1) amortized times, giving linear construction - the same efficiency spirit as KMP but conceptually about prefix-matches at every position.
    • For pattern search, build the Z-array of pattern + "#" + text; any position with Z[i] == len(pattern) marks an occurrence in the text (offset by pattern length + 1).
    • Z-function and KMP are interchangeable for matching; Z is often simpler to reason about for "prefix appears here" style queries.

    Time: O(n + m) | Space: O(n + m)

    Z-Box Construction + Search

    int[] zFunction(String s) {
    int n = s.length();
    int[] z = new int[n];
    z[0] = n;
    for (int i = 1, l = 0, r = 0; i < n; i++) {
        if (i < r) z[i] = Math.min(r - i, z[i - l]);
        while (i + z[i] < n && s.charAt(z[i]) == s.charAt(i + z[i])) z[i]++;
        if (i + z[i] > r) { l = i; r = i + z[i]; }
    }
    return z;
}
List<Integer> zSearch(String text, String pat) {
    String combined = pat + "#" + text;
    int[] z = zFunction(combined);
    int m = pat.length();
    List<Integer> res = new ArrayList<>();
    for (int i = m + 1; i < combined.length(); i++)
        if (z[i] == m) res.add(i - m - 1);
    return res;
}

    7. Rabin-Karp (Rolling Hash)

    Problem. Given a text and a pattern, use a rolling polynomial hash (Rabin-Karp) to find all occurrences of the pattern in the text.

    Input: text = "GEEKS FOR GEEKS", pattern = "GEEK"

    Output: [0, 10]

    • Treat each length-m window as a base-B polynomial modulo a large prime. Precompute the pattern's hash and the first window's hash; slide the window updating the hash in O(1): subtract the leaving char's contribution, multiply by B, add the entering char.
    • When a window hash equals the pattern hash, VERIFY by direct character comparison to rule out hash collisions (the hash equality is necessary, not sufficient).
    • Choosing a large prime modulus and a base larger than the alphabet keeps collisions rare, giving expected O(n + m); worst case (adversarial collisions) is O(n*m).
    • The rolling update - remove-front, shift, add-back in constant time - is the reusable core idea behind substring hashing and many dedup/sliding problems.

    Time: O(n + m) expected | Space: O(1)

    Polynomial Rolling Hash + Verify

    List<Integer> rabinKarp(String text, String pat) {
    int n = text.length(), m = pat.length();
    List<Integer> res = new ArrayList<>();
    if (m > n) return res;
    final long B = 256, MOD = 1_000_000_007L;
    long patHash = 0, winHash = 0, power = 1;
    for (int i = 0; i < m - 1; i++) power = (power * B) % MOD;
    for (int i = 0; i < m; i++) {
        patHash = (patHash * B + pat.charAt(i)) % MOD;
        winHash = (winHash * B + text.charAt(i)) % MOD;
    }
    for (int i = 0; i + m <= n; i++) {
        if (patHash == winHash && text.regionMatches(i, pat, 0, m))
            res.add(i);
        // verify on hash match
        if (i + m < n) {
            winHash = ((winHash - text.charAt(i) * power % MOD + MOD) % MOD * B
                    + text.charAt(i + m)) % MOD;
        }
    }
    return res;
}

    8. Repeated String Match

    Problem. Given strings a and b, return the minimum number of times a must be repeated so that b is a substring of the repetition, or -1 if impossible.

    Input: a = "abcd", b = "cdabcdab"

    Output: 3 ("abcdabcdabcd" contains "cdabcdab")

    • b can only appear inside repeats of a spanning at most ceil(len(b)/len(a)) copies, plus one extra to cover a straddling boundary. So repeating a until its length >= len(a) + len(b) is sufficient - any more copies cannot help.
    • Concretely: repeat a while its length < len(b) (need at least k = ceil(lenB/lenA) copies), then test if b is a substring; if not, append one more copy of a and test again. If still absent, return -1.
    • The bound "k or k+1 copies" is the key insight - it caps the search so you never over-repeat, and a substring check (or KMP for large inputs) confirms the match.
    • Return the copy count on success, else -1.

    Time: O(n + m) | Space: O(n + m)

    Repeat to Bound + Substring Check

    int repeatedStringMatch(String a, String b) {
    StringBuilder repeated = new StringBuilder(a);
    int count = 1;
    while (repeated.length() < b.length()) {
        repeated.append(a);
        count++;
    }
    if (repeated.indexOf(b) != -1) return count;
    repeated.append(a); // one extra for boundary straddle
    count++;
    if (repeated.indexOf(b) != -1) return count;
    return -1;
}

    9. Count and Say

    Problem. The count-and-say sequence starts with "1"; each subsequent term is the run-length encoding read-out of the previous term. Given n, return the n-th term.

    Input: n = 4

    Output: "1211"

    • Iterate from term 1 up to n. To produce the next term from the current one, run-length encode it: scan grouping consecutive equal digits, and emit the count followed by the digit for each group.
    • Example: "1211" reads as "one 1, one 2, two 1" -> "111221". The build is a straightforward group-and-append pass over the current string.
    • There is no closed form; the sequence is defined by literally "saying" the previous term, so simulate term by term.
    • The reusable skill is clean run-length encoding with a two-pointer / running-count group scan - the same routine used in string compression problems.

    Time: O(n * L) | Space: O(L)

    Iterative Run-Length Read-Out

    String countAndSay(int n) {
    String result = "1";
    for (int term = 2; term <= n; term++) {
        StringBuilder next = new StringBuilder();
        int i = 0, len = result.length();
        while (i < len) {
            int j = i;
            while (j < len && result.charAt(j) == result.charAt(i)) j++;
            next.append(j - i);                 // count
            next.append(result.charAt(i));      // digit
            i = j;
        }
        result = next.toString();
    }
    return result;
}
