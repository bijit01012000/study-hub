      Rapid-Fire Concept Check

      0 sections · 422 words

      Short answers for concepts an interviewer may drill:

      110. CAP for your system?

      Per-service Postgres is CP. Kafka + outbox makes cross-service consistency eventual — I chose availability + eventual consistency across services over distributed transactions.

      111. Idempotency vs. exactly-once?

      Idempotency = same operation applied twice has the same effect. Exactly-once delivery is hard/expensive; at-least-once + idempotent consumers gives effectively-once, which is what I built.

      112. Optimistic vs. pessimistic locking?

      Optimistic assumes rare conflicts, checks a @Version on write, retries on collision — no locks held. Pessimistic locks the row up front. I use optimistic because ingestion work is long and I don't want to hold locks.

      113. Cosine similarity vs. Euclidean for embeddings?

      Cosine — it measures direction/semantic orientation and ignores magnitude, which is what you want for text embeddings. pgvector's <=> is cosine distance.

      114. HNSW?

      Hierarchical Navigable Small World — an approximate-nearest-neighbor graph index that makes vector search ~O(log n) instead of scanning every row.

      115. Why 768 dims?

      That's nomic-embed-text's output dimensionality; swapping to OpenAI would be 1536, which is exactly why embeddings live in their own table.

      116. SSE vs. WebSocket in one line?

      SSE = unidirectional server→client over plain HTTP with auto-reconnect; WebSocket = bidirectional after an upgrade handshake. Streaming tokens → SSE; persistent notification channel → WebSocket.

      117. At-least-once vs at-most-once?

      At-least-once risks duplicates (retry on uncertainty); at-most-once risks loss (never retry). I chose at-least-once + dedup because losing a notification/event is worse than a harmless duplicate.

      118. Consumer group?

      A set of consumers sharing a subscription; Kafka assigns each partition to one consumer in the group. One group per service = each service processes every event once (barring redelivery).

      119. JWT vs session?

      JWT is stateless/self-contained — the gateway validates the signature without a session store; the trade-off is you can't trivially revoke one before expiry, hence short-lived access tokens + refresh.

      120. JWKS?

      Keycloak's published set of public keys; the gateway caches them and validates JWT signatures locally instead of calling Keycloak per request.

      121. Why k=60 in RRF?

      Empirical constant from the original RRF paper that dampens how much a single top rank dominates the fused score.

      122. @Transactional(readOnly=true)?

      Hints the driver/ORM it's a read-only tx (no dirty checking/flush) — a small optimization and a correctness guardrail on query methods.

      123. Reactive gateway, blocking services — contradiction?

      No — reactive for I/O-bound proxying, blocking for straightforward DB work. Match the model to the workload.
