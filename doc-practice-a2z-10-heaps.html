    1. Implement a Binary Heap

    Difficulty: LOW

    Statement/Hint: What is a binary heap, and how does it implement a priority queue's insert and extract-min operations efficiently?

    Example: - Input: insert(5), insert(3), insert(8), extractMin() - Output: 3

    Approach: Array-Backed Binary Heap - A binary heap is a complete binary tree stored implicitly in an array: for a node at index i, its children live at 2i+1 and 2i+2, so no pointers are needed. - Insert: append the new element at the array's end, then "sift up" - repeatedly swap it with its parent while it violates heap order (smaller than parent for a min-heap). - Extract-min: swap the root with the last element, remove the last element, then "sift down" the new root - repeatedly swap with its smaller child while it violates heap order. - Both operations cost O(log n) since sift up/down traverses at most the tree's height; O(n) space for the backing array.

    Time / Space: O(log n) time, O(n) space.

    class MinHeap {
    private final List<Integer> heap = new ArrayList<>();

    private void siftUp(int i) {
        while (i > 0 && heap.get((i - 1) / 2) > heap.get(i)) {
            Collections.swap(heap, (i - 1) / 2, i);
            i = (i - 1) / 2;
        }
    }

    private void siftDown(int i) {
        int n = heap.size();
        while (true) {
            int left = 2 * i + 1, right = 2 * i + 2, smallest = i;
            if (left < n && heap.get(left) < heap.get(smallest)) smallest = left;
            if (right < n && heap.get(right) < heap.get(smallest)) smallest = right;
            if (smallest == i) break;
            Collections.swap(heap, i, smallest);
            i = smallest;
        }
    }

    void insert(int val) {
        heap.add(val);
        siftUp(heap.size() - 1);
    }

    int extractMin() {
        int top = heap.get(0);
        heap.set(0, heap.get(heap.size() - 1));
        heap.remove(heap.size() - 1);
        siftDown(0);
        return top;
    }
}

    2. Top K Frequent Elements

    Difficulty: MEDIUM

    Statement/Hint: Given an integer array and integer k, return the k most frequent elements.

    Example: - Input: nums = [1,1,1,2,2,3], k = 2 - Output: [1, 2]

    Approach: Bounded Min-Heap by Frequency - Count each element's frequency into a hashmap, then push (frequency, value) pairs into a min-heap bounded to size k - whenever the heap exceeds size k, pop the smallest-frequency entry. - After scanning all distinct values, the heap holds exactly the k highest-frequency elements, since anything less frequent got evicted along the way. - Same bounded-size-min-heap template as Kth Largest Element, just ordered by frequency instead of value. - O(d log k) time (d = number of distinct elements), O(d) space for the frequency map plus O(k) for the heap.

    Time / Space: O(d log k) time, O(d + k) space.

    public int[] topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> freq = new HashMap<>();
    for (int x : nums) freq.merge(x, 1, Integer::sum);
    PriorityQueue<int[]> minHeap = new PriorityQueue<>((a, b) -> a[0] - b[0]);
    for (Map.Entry<Integer, Integer> entry : freq.entrySet()) {
        minHeap.add(new int[]{entry.getValue(), entry.getKey()});
        if (minHeap.size() > k) minHeap.poll();
    }
    int[] result = new int[minHeap.size()];
    for (int i = result.length - 1; i >= 0; i--) {
        result[i] = minHeap.poll()[1];
    }
    return result;
}

    3. Implement Min-Heap and Max-Heap

    Difficulty: LOW

    Statement/Hint: Implement both a min-heap and a max-heap (each supporting insert and extractTop) using the same array-based structure.

    Example: - Input: minHeap: insert(5), insert(2), extractTop(); maxHeap: insert(5), insert(2), extractTop() - Output: minHeap extractTop() = 2; maxHeap extractTop() = 5

    Approach: Comparator-Parameterized Heap - Both variants use the identical array layout and sift-up/sift-down mechanics as a plain binary heap - only the comparison direction flips (min-heap keeps the smaller value on top, max-heap keeps the larger). - Parameterize the sift comparisons with a single boolean flag so one implementation serves both, instead of duplicating the class. - Sift-up compares a child against its parent using that flag; sift-down picks whichever child "wins" the comparison among left/right before comparing against the current node. - O(log n) time insert/extractTop, O(n) space - identical bounds to the min-heap-only version.

    Time / Space: O(log n) time, O(n) space.

    class Heap {
    private final List<Integer> data = new ArrayList<>();
    private final boolean isMin;

    Heap(boolean isMin) { this.isMin = isMin; }

    private boolean better(int a, int b) { return isMin ? a < b : a > b; }

    private void siftUp(int i) {
        while (i > 0 && better(data.get(i), data.get((i - 1) / 2))) {
            Collections.swap(data, i, (i - 1) / 2);
            i = (i - 1) / 2;
        }
    }

    private void siftDown(int i) {
        int n = data.size();
        while (true) {
            int l = 2 * i + 1, r = 2 * i + 2, best = i;
            if (l < n && better(data.get(l), data.get(best))) best = l;
            if (r < n && better(data.get(r), data.get(best))) best = r;
            if (best == i) break;
            Collections.swap(data, i, best);
            i = best;
        }
    }

    void insert(int val) {
        data.add(val);
        siftUp(data.size() - 1);
    }

    int extractTop() {
        int top = data.get(0);
        data.set(0, data.get(data.size() - 1));
        data.remove(data.size() - 1);
        siftDown(0);
        return top;
    }
}

    4. Check if an Array is a Min-Heap

    Difficulty: LOW

    Statement/Hint: Given an array, determine whether it represents a valid binary min-heap.

    Example: - Input: arr = [1, 3, 6, 5, 9, 8] - Output: true

    Approach: Internal Node Scan - Treat the array as an implicit complete binary tree using the same index mapping as heap operations: node i's children are at 2i+1 and 2i+2. - The array is a valid min-heap iff, for every internal node i (one with at least one child), its value is <= both of its existing children's values. - Only indices from 0 up to n/2 - 1 (the last internal node) need checking, since every index beyond that is a leaf with no children to violate the property. - O(n) time (single pass over internal nodes), O(1) space.

    Time / Space: O(n) time, O(1) space.

    public boolean isMinHeap(int[] arr) {
    int n = arr.length;
    for (int i = 0; i <= n / 2 - 1; i++) {
        int left = 2 * i + 1, right = 2 * i + 2;
        if (left < n && arr[i] > arr[left]) return false;
        if (right < n && arr[i] > arr[right]) return false;
    }
    return true;
}

    5. Convert a Min-Heap to a Max-Heap

    Difficulty: MEDIUM

    Statement/Hint: Given an array that is already a valid min-heap, convert it in place into a valid max-heap.

    Example: - Input: minHeap = [1, 3, 6, 5, 9, 8] - Output: [9, 5, 8, 3, 1, 6] (one valid ordering; any array satisfying max-heap property is acceptable)

    Approach: Bottom-Up Heapify (Sift Down) - Re-heapify from scratch using max-heap sift-down (the standard "build heap" procedure), rather than trying to "fix" the min-heap ordering incrementally - the existing min-heap order gives no shortcut for building a max-heap. - Starting from the last internal node (index n/2 - 1) down to the root, sift each node down according to max-heap rules (the larger child wins). - Processing bottom-up guarantees that by the time a node is sifted, both its subtrees are already valid max-heaps. - O(n) time overall (bottom-up heapify is O(n), not O(n log n), since most nodes are near the bottom and sift only a short distance), O(1) extra space in place.

    Time / Space: O(n) time, O(1) space.

    private void siftDownMax(int[] arr, int n, int i) {
    while (true) {
        int left = 2 * i + 1, right = 2 * i + 2, largest = i;
        if (left < n && arr[left] > arr[largest]) largest = left;
        if (right < n && arr[right] > arr[largest]) largest = right;
        if (largest == i) break;
        int tmp = arr[i]; arr[i] = arr[largest]; arr[largest] = tmp;
        i = largest;
    }
}

public void convertMinToMaxHeap(int[] arr) {
    int n = arr.length;
    for (int i = n / 2 - 1; i >= 0; i--) {
        siftDownMax(arr, n, i);
    }
}

    6. Kth Largest Element in an Array

    Difficulty: MEDIUM

    Statement/Hint: Given an integer array and integer k, find the kth largest element in the array (the kth largest in sorted order, not the kth distinct value).

    Example: - Input: nums = [3,2,1,5,6,4], k = 2 - Output: 5

    Approach: Min-Heap of Size K - Maintain a min-heap of size k: push each element, and whenever the heap grows past size k, pop its smallest - after the full scan, the heap's smallest remaining element is the kth largest overall. - Using a min-heap (not a max-heap) of bounded size k keeps memory to O(k) instead of O(n), and each push/pop costs O(log k). - After the scan, the heap's top is the answer directly - no extra extraction needed. - O(n log k) time, O(k) space.

    Time / Space: O(n log k) time, O(k) space.

    public int findKthLargest(int[] nums, int k) {
    PriorityQueue<Integer> minHeap = new PriorityQueue<>();
    for (int x : nums) {
        minHeap.add(x);
        if (minHeap.size() > k) minHeap.poll();
    }
    return minHeap.peek();
}

    7. Kth Smallest Element in an Array

    Difficulty: LOW

    Statement/Hint: Given an integer array and integer k, find the kth smallest element in the array.

    Example: - Input: nums = [7,10,4,3,20,15], k = 3 - Output: 7

    Approach: Max-Heap of Size K - Mirror image of Kth Largest Element: maintain a max-heap of size k instead of a min-heap - push each element, popping the largest whenever size exceeds k. - After the full scan, the max-heap holds the k smallest elements overall, and its top (the largest among them) is exactly the kth smallest. - O(n log k) time, O(k) space - same bound as Kth Largest, with the heap type and pop direction flipped.

    Time / Space: O(n log k) time, O(k) space.

    public int findKthSmallest(int[] nums, int k) {
    PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
    for (int x : nums) {
        maxHeap.add(x);
        if (maxHeap.size() > k) maxHeap.poll();
    }
    return maxHeap.peek();
}

    8. Sort a K-Sorted Array

    Difficulty: MEDIUM

    Statement/Hint: Given an array where every element is at most k positions away from its final sorted position, sort it efficiently.

    Example: - Input: arr = [6,5,3,2,8,10,9], k = 3 - Output: [2,3,5,6,8,9,10]

    Approach: Bounded Min-Heap (Size K+1) - Maintain a min-heap bounded to size k + 1: push the first k + 1 elements, then repeatedly pop the minimum (guaranteed to be the next smallest overall, since no unseen element can be more than k positions out of place) and push the next unseen element. - Once the input is exhausted, drain the remaining heap in order to finish the output. - O(n log k) time (n pushes/pops on a heap bounded to size k + 1), O(k) space, versus O(n log n) for a general sort.

    Time / Space: O(n log k) time, O(k) space.

    public int[] sortKSortedArray(int[] arr, int k) {
    PriorityQueue<Integer> minHeap = new PriorityQueue<>();
    int n = arr.length;
    int[] result = new int[n];
    int idx = 0;
    for (int i = 0; i < n; i++) {
        minHeap.add(arr[i]);
        if (minHeap.size() > k + 1) {
            result[idx++] = minHeap.poll();
        }
    }
    while (!minHeap.isEmpty()) {
        result[idx++] = minHeap.poll();
    }
    return result;
}

    9. Merge K Sorted Arrays

    Difficulty: HIGH

    Statement/Hint: Given m sorted arrays, merge them all into a single sorted array.

    Example: - Input: arrays = [[1,4,5],[1,3,4],[2,6]] - Output: [1,1,2,3,4,4,5,6]

    Approach: K-Way Merge via Min-Heap - Maintain a min-heap of (value, listIndex, elementIndex) triples, initially seeded with the first element of each of the m arrays. - Repeatedly pop the smallest triple, append its value to the result, and if that array has a next element, push it onto the heap - this always advances exactly one array per pop, one step at a time. - The heap never holds more than m elements at once (one per array), so each of the total N elements costs O(log m) to push/pop. - O(N log m) time (N = total elements across all arrays), O(m) space for the heap.

    Time / Space: O(N log m) time, O(m) space.

    public int[] mergeKSortedArrays(int[][] lists) {
    PriorityQueue<int[]> minHeap = new PriorityQueue<>((a, b) -> a[0] - b[0]);
    int m = lists.length, total = 0;
    for (int i = 0; i < m; i++) {
        if (lists[i].length > 0) minHeap.add(new int[]{lists[i][0], i, 0});
        total += lists[i].length;
    }
    int[] result = new int[total];
    int idx = 0;
    while (!minHeap.isEmpty()) {
        int[] cur = minHeap.poll();
        result[idx++] = cur[0];
        int listIdx = cur[1], elemIdx = cur[2];
        if (elemIdx + 1 < lists[listIdx].length) {
            minHeap.add(new int[]{lists[listIdx][elemIdx + 1], listIdx, elemIdx + 1});
        }
    }
    return result;
}

    10. Replace Elements with Their Rank

    Difficulty: LOW

    Statement/Hint: Given an array, replace each element with its rank (1 = smallest value; equal values share the same rank; ranks are consecutive with no gaps).

    Example: - Input: arr = [40, 10, 20, 30] - Output: [4, 1, 2, 3]

    Approach: Sort + Rank Map - Sort a copy of the array to discover the values' relative order - a heap here is just "sorting via repeated extract-min," so a plain sort is simpler and equally correct. - Walk the sorted copy assigning rank 1, 2, 3, ... but only incrementing the rank when the current value differs from the previous one (equal values reuse the same rank), building a value -> rank map. - Replace each original element with its looked-up rank from that map, preserving the original array's order. - O(n log n) time (dominated by the sort), O(n) space for the map.

    Time / Space: O(n log n) time, O(n) space.

    public int[] replaceWithRank(int[] arr) {
    int[] sorted = arr.clone();
    Arrays.sort(sorted);
    Map<Integer, Integer> rankOf = new HashMap<>();
    int rank = 0;
    for (int i = 0; i < sorted.length; i++) {
        if (i == 0 || sorted[i] != sorted[i - 1]) rank++;
        rankOf.put(sorted[i], rank);
    }
    int[] result = new int[arr.length];
    for (int i = 0; i < arr.length; i++) result[i] = rankOf.get(arr[i]);
    return result;
}

    11. Task Scheduler

    Difficulty: HIGH

    Statement/Hint: Given a list of tasks (as characters) and a cooldown n, find the minimum number of time units (including idle slots) to execute all tasks such that the same task type is separated by at least n units.

    Example: - Input: tasks = ["A","A","A","B","B","B"], n = 2 - Output: 8

    Approach: Max-Heap Round Scheduling - Count each task type's frequency and push all counts into a max-heap; the task with the highest remaining count should always run first, to spread it out earliest. - Process in rounds of size (n + 1): each round, pop up to (n + 1) most-frequent tasks, decrement their counts, and push back any with count remaining - a round contributes n + 1 time units unless no tasks remain at all, in which case it only contributes as many units as tasks actually ran. - Total time is the sum of every round's contribution; stop once the heap (and the round's leftovers) are empty. - O(T log 26) time (T = total number of tasks, heap bounded to 26 task types), O(26) space.

    Time / Space: O(T log 26) time, O(26) space.

    public int leastInterval(char[] tasks, int n) {
    int[] freq = new int[26];
    for (char t : tasks) freq[t - 'A']++;
    PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
    for (int f : freq) if (f > 0) maxHeap.add(f);
    int time = 0;
    while (!maxHeap.isEmpty()) {
        List<Integer> cooldown = new ArrayList<>();
        int slots = n + 1, used = 0;
        while (slots > 0 && !maxHeap.isEmpty()) {
            int count = maxHeap.poll();
            if (count > 1) cooldown.add(count - 1);
            used++;
            slots--;
        }
        maxHeap.addAll(cooldown);
        time += maxHeap.isEmpty() ? used : used + slots;
    }
    return time;
}

    12. Hand of Straights

    Difficulty: MEDIUM

    Statement/Hint: Given a hand of cards (integers) and a group size groupSize, determine whether the hand can be rearranged into groups of groupSize consecutive integers each.

    Example: - Input: hand = [1,2,3,6,2,3,4,7,8], groupSize = 3 - Output: true

    Approach: Min-Heap of Distinct Card Values - If the total card count isn't divisible by groupSize, it's immediately impossible. - Count each card value's frequency, and push each distinct value once into a min-heap; always start a new group from the smallest remaining card value, since starting from anywhere higher would strand smaller cards that can never be used later. - For each new group's starting value v, consume one of v, v+1, ..., v+groupSize-1 from the frequency map; if any is missing, the hand can't be arranged - then pop any heap values whose count has hit zero before picking the next start. - O(n log n) time (n distinct values pushed/popped from the heap, each group scan O(groupSize)), O(n) space for the frequency map.

    Time / Space: O(n log n) time, O(n) space.

    public boolean isNStraightHand(int[] hand, int groupSize) {
    if (hand.length % groupSize != 0) return false;
    Map<Integer, Integer> count = new HashMap<>();
    PriorityQueue<Integer> minHeap = new PriorityQueue<>();
    for (int c : hand) {
        if (count.merge(c, 1, Integer::sum) == 1) minHeap.add(c);
    }
    while (!minHeap.isEmpty()) {
        int start = minHeap.peek();
        for (int v = start; v < start + groupSize; v++) {
            Integer remaining = count.get(v);
            if (remaining == null || remaining == 0) return false;
            count.put(v, remaining - 1);
        }
        while (!minHeap.isEmpty() && count.get(minHeap.peek()) == 0) minHeap.poll();
    }
    return true;
}

    13. Design Twitter

    Difficulty: HIGH

    Statement/Hint: Design a simplified Twitter: postTweet(userId, tweetId), follow(followerId, followeeId), unfollow(followerId, followeeId), and getNewsFeed(userId) returning the 10 most recent tweet ids from the user and everyone they follow.

    Example: - Input: postTweet(1,5); follow(1,2); postTweet(2,6); getNewsFeed(1) - Output: [6, 5]

    Approach: Max-Heap Merge by Recency (Followees) - Store each tweet as (timestamp, tweetId) appended to that user's own list, using a global increasing counter as "timestamp" so recency is comparable across users. - getNewsFeed: seed a max-heap with only the most recent tweet from the user and each followee (one entry per relevant user, not their whole history), then repeatedly pop the newest tweet and push that same user's nextmost-recent tweet. - Stop once 10 tweets are collected or the heap empties - this is exactly the Merge M Sorted Arrays pattern applied to "recency" instead of "value", capped early. - O(log(followees)) time per tweet retrieved in getNewsFeed, O(tweets + follow-graph) space overall.

    Time / Space: O(log(followees)) time per tweet, O(tweets + graph) space.

    class Twitter {
    private int timeCounter = 0;
    private final Map<Integer, List<int[]>> tweets = new HashMap<>();
    private final Map<Integer, Set<Integer>> following = new HashMap<>();

    private void pushLatest(PriorityQueue<int[]> heap, int uid) {
        List<int[]> list = tweets.getOrDefault(uid, Collections.emptyList());
        if (!list.isEmpty()) {
            int idx = list.size() - 1;
            int[] t = list.get(idx);
            heap.add(new int[]{t[0], t[1], uid, idx});
        }
    }

    public void postTweet(int userId, int tweetId) {
        tweets.computeIfAbsent(userId, k -> new ArrayList<>()).add(new int[]{timeCounter++, tweetId});
    }

    public List<Integer> getNewsFeed(int userId) {
        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> b[0] - a[0]);
        pushLatest(heap, userId);
        for (int f : following.getOrDefault(userId, Collections.emptySet())) pushLatest(heap, f);
        List<Integer> result = new ArrayList<>();
        while (!heap.isEmpty() && result.size() < 10) {
            int[] cur = heap.poll();
            int tweetId = cur[1], uid = cur[2], idx = cur[3];
            result.add(tweetId);
            if (idx > 0) {
                int[] t = tweets.get(uid).get(idx - 1);
                heap.add(new int[]{t[0], t[1], uid, idx - 1});
            }
        }
        return result;
    }

    public void follow(int followerId, int followeeId) {
        if (followerId != followeeId) {
            following.computeIfAbsent(followerId, k -> new HashSet<>()).add(followeeId);
        }
    }

    public void unfollow(int followerId, int followeeId) {
        Set<Integer> set = following.get(followerId);
        if (set != null) set.remove(followeeId);
    }
}

    14. Minimum Cost to Connect Ropes

    Difficulty: MEDIUM

    Statement/Hint: Given the lengths of n ropes, connect them all into one rope, where connecting two ropes costs the sum of their lengths; find the minimum total connecting cost.

    Example: - Input: ropes = [4, 3, 2, 6] - Output: 29

    Approach: Greedy Combine Two Smallest - Always combine the two currently-shortest ropes first - greedily merging the smallest pieces early keeps them from being "recounted" at high cost in later merges. - Push all rope lengths into a min-heap; repeatedly pop the two smallest, add their sum to the total cost, and push that sum back as a new rope - repeat until one rope remains. - This is the same "combine two smallest" greedy as Huffman coding's merge step. - O(n log n) time (n - 1 merges, each O(log n)), O(n) space.

    Time / Space: O(n log n) time, O(n) space.

    public int connectRopes(int[] ropes) {
    PriorityQueue<Integer> minHeap = new PriorityQueue<>();
    for (int r : ropes) minHeap.add(r);
    int totalCost = 0;
    while (minHeap.size() > 1) {
        int first = minHeap.poll();
        int second = minHeap.poll();
        int cost = first + second;
        totalCost += cost;
        minHeap.add(cost);
    }
    return totalCost;
}

    15. Kth Largest Element in a Stream

    Difficulty: MEDIUM

    Statement/Hint: Design a class that, given an initial array and integer k, supports add(val) and returns the kth largest element in the stream seen so far after each addition.

    Example: - Input: KthLargest(3, [4,5,8,2]); add(3); add(5); add(10); add(9); add(4) - Output: add(3)=4; add(5)=5; add(10)=5; add(9)=8; add(4)=8

    Approach: Persistent Min-Heap of Size K - Maintain a min-heap containing exactly the k largest elements seen so far; its top is always the current kth largest. - Constructor: push all initial values in, popping the minimum whenever size exceeds k, same as Kth Largest Element in an Array. - add(val): push val, pop the minimum if size now exceeds k, then return the top - the heap persists across calls instead of being rebuilt from scratch each time. - O(log k) time per add, O(k) space.

    Time / Space: O(log k) time, O(k) space.

    class KthLargest {
    private final int k;
    private final PriorityQueue<Integer> minHeap = new PriorityQueue<>();

    public KthLargest(int k, int[] nums) {
        this.k = k;
        for (int x : nums) add(x);
    }

    public int add(int val) {
        minHeap.add(val);
        if (minHeap.size() > k) minHeap.poll();
        return minHeap.peek();
    }
}

    16. Maximum Sum Combinations

    Difficulty: HIGH

    Statement/Hint: Given two arrays of equal length n and integer k, find the k largest possible sums of one element from each array, considering all n^2 pairwise sums.

    Example: - Input: A = [3, 2], B = [1, 4], k = 2 - Output: [7, 6]

    Approach: Max-Heap + Visited Pair Set - Sort both arrays descending first, so the overall largest sum is guaranteed to be (A[0], B[0]) - from there, the next-largest candidates can only come from advancing one index in either array. - Use a max-heap of (sum, i, j) seeded with just (A[0]+B[0], 0, 0); each pop pushes (i+1, j) and (i, j+1) as new candidates, guarded by a visited set so the same (i, j) pair is never pushed twice. - Pop k times to get the k largest sums, without ever generating or sorting all n^2 pairs upfront. - O(k log k) time (k heap operations, each pushing at most 2 new candidates), O(k) space for the heap and visited set.

    Time / Space: O(k log k) time, O(k) space.

    public List<Integer> maxSumCombinations(int[] A, int[] B, int k) {
    int n = A.length;
    Integer[] a = Arrays.stream(A).boxed().toArray(Integer[]::new);
    Integer[] b = Arrays.stream(B).boxed().toArray(Integer[]::new);
    Arrays.sort(a, Collections.reverseOrder());
    Arrays.sort(b, Collections.reverseOrder());
    PriorityQueue<int[]> maxHeap = new PriorityQueue<>((x, y) -> y[0] - x[0]);
    Set<Long> visited = new HashSet<>();
    maxHeap.add(new int[]{a[0] + b[0], 0, 0});
    visited.add(0L);
    List<Integer> result = new ArrayList<>();
    while (k-- > 0 && !maxHeap.isEmpty()) {
        int[] cur = maxHeap.poll();
        int sum = cur[0], i = cur[1], j = cur[2];
        result.add(sum);
        long keyRight = (long) (i + 1) * n + j;
        if (i + 1 < n && visited.add(keyRight)) {
            maxHeap.add(new int[]{a[i + 1] + b[j], i + 1, j});
        }
        long keyDown = (long) i * n + (j + 1);
        if (j + 1 < n && visited.add(keyDown)) {
            maxHeap.add(new int[]{a[i] + b[j + 1], i, j + 1});
        }
    }
    return result;
}

    17. Find Median from Data Stream

    Difficulty: HIGH

    Statement/Hint: Design a data structure that supports adding integers one at a time (addNum) and returns the median of all elements seen so far (findMedian) at any point.

    Example: - Input: addNum(1); addNum(2); findMedian(); addNum(3); findMedian() - Output: findMedian() = 1.5; findMedian() = 2

    Approach: Two Balanced Heaps - Maintain two heaps: a max-heap for the smaller half of the numbers and a min-heap for the larger half, keeping them balanced within one element of each other's size. - addNum: push into the max-heap (small half) first, then move its top into the min-heap (large half) to enforce "every small-half value <= every large-half value"; if that leaves the min-heap larger, move its top back. - findMedian: if the heaps are equal in size, the median is the average of both tops; otherwise it's the top of whichever heap has one extra element (always the max-heap, by the rebalancing rule above). - O(log n) time per addNum, O(1) time per findMedian, O(n) space across both heaps.

    Time / Space: O(log n) time, O(n) space.

    class MedianFinder {
    private final PriorityQueue<Integer> small = new PriorityQueue<>(Collections.reverseOrder());
    private final PriorityQueue<Integer> large = new PriorityQueue<>();

    public void addNum(int num) {
        small.add(num);
        large.add(small.poll());
        if (large.size() > small.size()) {
            small.add(large.poll());
        }
    }

    public double findMedian() {
        if (small.size() > large.size()) return small.peek();
        return (small.peek() + large.peek()) / 2.0;
    }
}
