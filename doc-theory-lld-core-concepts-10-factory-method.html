    Factory Method

    10 sections · 821 words

    Creational · Design Patterns · Pattern 01 of 12

    Intent

    Hide the new behind a create() so callers depend on the product interface, not a concrete class. One product, one method.

    When To Use It

    The Signs

    • new ConcreteThing() scattered across many files.
    • The same switch (type) returning a new per case, copied in three places.
    • Caller code that imports and names every concrete class.
    • A class you cannot unit-test because it hardcodes what it creates.

    Don't Bother If

    • There is only ever one concrete product.
    • Construction is a plain new with no choice to make.
    • A one-line static helper reads fine and the set will not grow.
    • You would add a creator subclass just to change one line.

    Before

    class ParkingLot {
    ParkingSpot makeSpot(SpotType t) {
        switch (t) {
        case BIKE: return new BikeSpot();
        case CAR: return new CarSpot();
        case TRUCK: return new TruckSpot();
        }
        throw new IllegalArgumentException("" + t);
    }
}
// ParkingLot now names every concrete spot class,
// and this same switch is copied in Floor and in the tests

    Coupled to concretes.

    After

    interface SpotFactory { ParkingSpot create(); }
// one product, behind one method
class CarSpotFactory implements SpotFactory {
    public ParkingSpot create() { return new CarSpot(); }
}
// BikeSpotFactory, TruckSpotFactory: the same three lines

class ParkingLot {
    private final SpotFactory factory;
    ParkingLot(SpotFactory f) { this.factory = f; }
    ParkingSpot addSpot() { return factory.create(); }
}
// holds the interface, never names a concrete

    Or the compact real-world form: one registry, keyed by type.

    Map<SpotType, Supplier<ParkingSpot>> spots = Map.of(
    SpotType.BIKE, BikeSpot::new,
    SpotType.CAR, CarSpot::new,
    SpotType.TRUCK, TruckSpot::new);
ParkingSpot s = spots.get(t).get();
// a new size is one small factory, or one entry. nothing else stirs.

    Or the caller news it directly:

    ParkingSpot s = new CarSpot();
// Floor does this too. so does the seeder. so do three tests.
// each one now imports BikeSpot, CarSpot, TruckSpot by name
// and each one breaks the day a new size is added

THE CLIENT HOLDS THE INTERFACE, NEVER A CONCRETE

    How It's Built (3 Steps)

    1. Name the product interface. The thing callers actually use (ParkingSpot). They hold this, never a concrete class.
    2. Put the new behind a create(). An abstract method on a creator, a small factory class per type, or a Map<key, Supplier> registry.
    3. Callers depend on the product and the factory only. The words new CarSpot() live in exactly one place, not scattered.

    In The Interview

    "ParkingLot should not name CarSpot or BikeSpot. I would put a SpotFactory behind a create() method, or a registry of Suppliers keyed by SpotType, so adding a size is one new factory and nothing else changes."

    How It's Different

    From The Lookalikes

    Vs a plain static factory. Integer.valueOf() style. Handy, but not the GoF pattern: there is no subclass or strategy hook to vary what gets made.

    Vs Builder. Builder assembles one complex object step by step with validation. Factory Method picks which class to instantiate in one call.

    Vs Prototype. Prototype makes a new object by cloning an existing one. Factory Method constructs a fresh one from scratch.

    Vs Abstract Factory. Factory Method makes one product behind one method. Abstract Factory makes a whole family of related products (a matching button, checkbox and menu) behind one object.

    They Say: "now add an EV-only spot"

    • With it: one EvSpotFactory, one registry entry. ParkingLot, Floor and the seeder are untouched.
    • Without: you edit the same switch in three files and hope you found them all.

    Watch Out For

    • Do not return null for an unknown type. Throw, or return a Null Object the caller can safely use.
    • A factory whose switch keeps growing is its own smell. Move to a Map<key, Supplier> registry that types self-register into.
    • Keep the factory dumb: it constructs and wires, it does not run business logic.
    • Java shortcut: an enum where each constant overrides create() is a clean, closed factory.
    • A static factory method cannot be overridden or mocked. If a test must swap the product, take a SpotFactory parameter instead.
