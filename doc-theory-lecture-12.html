    Lecture 12 — Spring Boot CRUD Project with MySQL

    21 sections · 3,720 words

    Lecture 12

    Scope evidence: "Spring Boot CRUD Project with MySQL | Spring JPA Methods" (playlist map, verified). The repo lecture folder contains the crudSpringBootDemo Maven project (CrudSpringBootDemoApplication, controller.StudentController, service.StudentService, repository.StudentRepository, entity.Student), its src/main/resources/application.properties and pom.xml. Coverage below = MySQL configuration, JPA/Hibernate table mapping, entity annotations, ddl-auto, JpaRepository methods, and repository/service/controller wiring.

    This lecture turns the earlier "JPA is a spec, Hibernate is an implementation" story into a working application. We stop creating SQL tables by hand, let Hibernate build them from a Student entity, point Spring Boot at MySQL through application.properties, and expose CRUD over a repository, a service, and a controller. The point is not just to run the demo: it is to be able to explain exactly which layer owns each responsibility, and which property controls which behaviour.

    1. Why We Do Not Create the Table Manually

    In plain SQL work, the first step is always a manual DDL statement:

    CREATE TABLE students (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(255),
    email VARCHAR(255)
);

    In this project we skip that step. The application uses JPA with Hibernate, and the entity class replaces the hand-written DDL:

    • JPA lets us work with Java classes and objects.
    • Hibernate maps those classes to database tables.
    • Given the right configuration, Hibernate can look at the entity and create or update the table structure for us.

    So instead of writing CREATE TABLE students, we let Hibernate read the Student entity and derive the students table from it.

    Manual way:  write CREATE TABLE in SQL  ->  run it by hand
Hibernate way: write @Entity class      ->  Hibernate builds the table

    Important: Hibernate can create or update tables, but it cannot create the database itself. The database must already exist before the application starts.

    2. The crudSpringBootDemo Project Layout

    The demo is a standard Spring Boot Maven project. Its package layout mirrors the request flow:

    crudSpringBootDemo
  src/main/java
    .../CrudSpringBootDemoApplication   (main class, @SpringBootApplication)
    .../entity/Student                  (JPA entity -> students table)
    .../repository/StudentRepository    (extends JpaRepository)
    .../service/StudentService          (business logic, @Service)
    .../controller/StudentController    (@RestController, /api/students)
  src/main/resources
    application.properties              (MySQL + JPA configuration)
  pom.xml                               (dependencies incl. the MySQL driver)

    Each package has one job: entity describes the table, repository talks to the database, service holds business rules, and controller handles HTTP. Keeping them separate is what makes the project testable and readable later.

    3. Creating the Database Once

    Even though we do not create the table manually, the database container does not exist yet, so we create it one time:

    CREATE DATABASE student_crud_db;

    After that single statement, Hibernate can create and update tables inside student_crud_db. The rule to remember:

    Database: create it once, by hand.
Tables:   let Hibernate create and update them.

    Golden rule: a database is a server-level container you create once; tables are schema objects Hibernate is allowed to manage. Do not confuse the two.

    4. MySQL Configuration in application.properties

    All connection and JPA settings live in src/main/resources/application.properties:

    spring.datasource.url=jdbc:mysql://localhost:3306/student_crud_db
spring.datasource.username=root
spring.datasource.password=your_password
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true

    Each property has exactly one meaning:

    Property Value in the project Meaning
    spring.datasource.url jdbc:mysql://localhost:3306/student_crud_db Where the database lives and how to reach it
    spring.datasource.username root The MySQL user (root is common in local dev)
    spring.datasource.password your_password Password of that MySQL user
    spring.jpa.hibernate.ddl-auto update How Hibernate treats the table structure
    spring.jpa.show-sql true Print the generated SQL in the console
    spring.jpa.properties.hibernate.format_sql true Pretty-print that SQL instead of one long line

    If the real MySQL password were 123456, the line becomes spring.datasource.password=123456. Nothing else changes.

    Interviewer's perspective: These six lines are the first thing a reviewer reads in a Spring Boot database project. Being able to say what each one does, and what breaks if it is wrong, signals real project experience rather than copied boilerplate.

    5. The JDBC URL Breakdown

    The URL is not magic text; it is a path with named parts:

    jdbc:mysql://localhost:3306/student_crud_db
    Part Meaning
    jdbc Java Database Connectivity URL format
    mysql The database type is MySQL
    localhost MySQL runs on the same system as the app
    3306 The default MySQL port
    student_crud_db The database name to connect to

    Read aloud, the URL means: "Connect this Spring Boot application to the MySQL database named student_crud_db, running on the local machine at port 3306." Changing localhost to a server IP, or student_crud_db to another name, changes what the app talks to.

    6. The MySQL Driver Dependency

    Spring Boot needs a JDBC driver on the classpath to speak MySQL. In most Spring Boot projects we do not write the driver class name ourselves: Spring Boot detects it from the MySQL dependency and the JDBC URL. The driver comes in through pom.xml as the MySQL connector. Only if driver-related issues appear do we add the explicit class name:

    spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver

    The mental order is: add the dependency, provide the URL, and let Spring Boot infer the driver. The explicit driver-class-name is a fallback, not the default habit.

    Important: com.mysql.cj.jdbc.Driver is the modern MySQL connector class. Spring Boot usually resolves it automatically, so treat the explicit property as a troubleshooting lever.

    7. JPA, Hibernate, and ORM: Mapping Entity to Table

    The worlds do not line up by themselves:

    Java world      ->  classes and objects
Database world  ->  tables and rows

    JPA provides Object-Relational Mapping (ORM): mapping Java classes to relational database tables. The mapping is one-to-one conceptually:

    Java side Database side
    Student class students table
    Student object one row in students
    Student fields columns of the table

    So Student student = new Student(); creates a Java object. When JPA saves that object, it can become a row inside students.

    8. The Entity Class and Its Annotations

    An entity is a Java class that represents a database table:

    package com.example.crudSpringBootDemo.entity;

import jakarta.persistence.*;

@Entity
@Table(name = "students")
public class Student {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String name;
    private String email;
    private Integer age;
    private String mobile;
    private Boolean isDeleted = false;

    // getters and setters
}

    The four annotations carry the meaning:

    Annotation What it tells JPA
    @Entity Treat this class as a database entity: it can be mapped to a table and its objects saved as rows
    @Table(name = "students") The table name is explicitly students
    @Id The field id is the primary key
    @GeneratedValue(strategy = GenerationType.IDENTITY) The ID is generated automatically by the database

    Without @Entity, JPA treats the class as a normal Java class and nothing maps to a table. Without @Table, JPA usually uses the class name as the table name: Student may map to a table named student. @Table lets us control that name explicitly.

    9. Primary Key and Generation Strategies

    Every table should have a primary key: a column that uniquely identifies each row. In the Student entity that column is id.

    We do not want to supply the ID by hand every time we create a student, so @GeneratedValue tells JPA to generate it. The strategy decides who generates it:

    Strategy Who generates the ID Notes
    GenerationType.IDENTITY The database Auto-increment column; the project's choice
    GenerationType.AUTO The provider picks Hibernate chooses based on the dialect
    GenerationType.SEQUENCE A database sequence Common on Oracle/PostgreSQL
    GenerationType.TABLE A separate table Portable but slow; rarely used

    With IDENTITY, MySQL uses an auto-increment column: the database hands out the next ID when the row is inserted.

    Important: The ID is the primary key and the entity's identity. save() decides insert versus update largely based on whether the ID is null.

    10. ddl-auto: Values and Hibernate Auto DDL vs Manual SQL

    spring.jpa.hibernate.ddl-auto controls how Hibernate treats the table structure. The common values:

    Value Meaning
    none Hibernate does not manage the table structure
    validate Hibernate only checks whether the table matches the entity
    update Hibernate updates the table structure from the entity
    create Drops old tables and creates fresh ones on every start
    create-drop Creates tables on start and drops them on stop

    With update, if the target table does not exist Hibernate can create it; if a new field is added to the entity, Hibernate can try to add the column. Existing data is usually not deleted with update.

    The trade-off against manual SQL:

    Aspect Manual SQL DDL Hibernate ddl-auto
    Who writes the table You, by hand Hibernate, from the entity
    Source of truth The SQL script The Java entity class
    New field added You edit the script Hibernate alters the table (update)
    Risk to data Controlled by you create/create-drop drop tables and data
    Production use Migrations (Flyway, Liquibase) Fine for learning and local development

    Interviewer's perspective: In real production projects, schema changes are usually not handled with ddl-auto=update; teams use controlled migration tools such as Flyway or Liquibase with SQL migration scripts. update is convenient for learning and local development, not a production policy.

    11. Repository Layer and JpaRepository

    The application works with Java objects, but the data must live in MySQL. The layer that performs database operations is the repository:

    • save a student into the database;
    • fetch students from the database;
    • find a student by ID;
    • update a student;
    • delete a student.

    We create an interface, not a class:

    package com.example.crudSpringBootDemo.repository;

import com.example.crudSpringBootDemo.entity.Student;
import org.springframework.data.jpa.repository.JpaRepository;
import java.util.List;

public interface StudentRepository extends JpaRepository<Student, Long> {
    List<Student> findByIsDeletedFalse();
}

    JpaRepository needs two things:

    1. the entity type: Student;
    2. the primary key type: Long.

    So JpaRepository<Student, Long> provides database operations for the Student entity whose ID type is Long. Normally an interface needs a hand-written implementation class; Spring Data JPA creates the implementation automatically at runtime.

    Do we need @Repository? For Spring Data JPA repositories, usually not. Spring Data JPA automatically detects interfaces that extend JpaRepository, so the annotation is optional.

    Golden rule: for a JpaRepository you define the interface and Spring Data JPA provides the implementation. You never write the class.

    12. JpaRepository Methods and Their SQL Effect

    JpaRepository gives ready-made CRUD methods. For this project the important five are:

    Method What it does SQL effect
    save(student) Saves the object; inserts if new, updates if it already exists INSERT (no ID) or UPDATE (existing ID)
    findAll() Fetches all rows from the table SELECT * FROM students
    findById(id) Fetches one student by ID as Optional<Student> SELECT ... WHERE id = ?
    deleteById(id) Removes the row permanently (hard delete) DELETE FROM students WHERE id = ?
    existsById(id) Checks whether a row with that ID exists SELECT ... WHERE id = ? (existence check)

    Each one in context:

    1. studentRepository.save(student); - if the student has no ID, JPA treats it as new and inserts; if it already has an ID, it updates the existing row.
    2. studentRepository.findAll(); - fetches all rows. Because this project uses soft delete (the isDeleted flag), findAll() may return both active and soft-deleted students. To fetch only active students we add a custom method: List<Student> findByIsDeletedFalse();.
    3. studentRepository.findById(1L); - returns Optional<Student>. It exists because the student may or may not be present: if found we get the object, if not the Optional is empty. This forces us to handle the "not found" case.
    4. studentRepository.deleteById(1L); - performs a hard delete and removes the row permanently. It backs an API such as DELETE /api/students/{id}.
    5. studentRepository.existsById(1L); - returns a boolean, useful before a hard delete so we do not try to delete a record that does not exist:
    public boolean deleteStudent(Long id) {
    if (!studentRepository.existsById(id)) {
        return false;
    }
    studentRepository.deleteById(id);
    return true;
}

    Mnemonic for the five: S-F-F-D-E - Save, FindAll, FindById, DeleteById, ExistsById.

    13. Service Layer

    The controller should not contain all business logic; the service layer holds the application logic while the controller handles HTTP requests and responses. Service responsibilities in this project include create student, update student, fetch active students, soft delete, hard delete, and check whether a student exists.

    package com.example.crudSpringBootDemo.service;

import com.example.crudSpringBootDemo.entity.Student;
import com.example.crudSpringBootDemo.repository.StudentRepository;
import org.springframework.stereotype.Service;

@Service
public class StudentService {
    private final StudentRepository studentRepository;

    public StudentService(StudentRepository studentRepository) {
        this.studentRepository = studentRepository;
    }

    public Student createStudent(Student student) {
        return studentRepository.save(student);
    }
}

    @Service tells Spring that this class belongs to the service layer and that Spring should create its object as a bean. It is similar to @Component but more specific:

    Annotation Meaning
    @Component Generic Spring-managed class
    @Service Spring-managed class that contains business logic

    Using @Service makes the responsibility of the class explicit and the code more readable.

    14. Controller Layer and HTTP Responses

    The repository talks to the database and the service holds business logic, but an external client (Postman, a browser, a frontend, a mobile app) cannot call them directly. The controller receives HTTP requests and sends HTTP responses:

    GET    /api/students
POST   /api/students
PUT    /api/students/{id}
DELETE /api/students/{id}

    @RestController tells Spring this class handles REST API requests and returns data directly (usually JSON). When a method returns a Student, Spring converts it to JSON automatically using Jackson, which arrives with the Spring Boot web dependency:

    {
  "id": 1,
  "name": "Rahul Sharma",
  "email": "rahul@example.com",
  "age": 22,
  "mobile": "9876543210",
  "isDeleted": false
}

    @RequestMapping("/api/students") defines the base URL for every API inside the controller, so each method does not repeat /api/students:

    @RestController
@RequestMapping("/api/students")
public class StudentController {
    // @GetMapping, @PostMapping, @PutMapping, @DeleteMapping methods
}

    Why ResponseEntity? A plain return like return studentService.getStudentById(id).get(); works only when the student exists. Proper APIs return meaningful status codes: found -> 200 OK, not found -> 404 Not Found, created -> 201 Created. ResponseEntity controls the response body, the HTTP status code, and headers:

    Return Result
    ResponseEntity.ok(student) 200 OK with the student body
    ResponseEntity.notFound().build() 404 Not Found with an empty body
    ResponseEntity.status(HttpStatus.CREATED).body(createdStudent) 201 Created with the created student body

    Interviewer's perspective: "Why not just return the object?" Because a bare return cannot express not-found or created. ResponseEntity is how the controller speaks correct HTTP instead of always saying 200 OK.

    15. Running Against MySQL: The Complete Request Flow

    When a client sends a request:

    POST /api/students

    the flow goes down through the layers and back up:

    Client/Postman
      |
      v
Controller        (HTTP request/response)
      |
      v
Service           (business logic)
      |
      v
Repository        (database operations)
      |
      v
Database          (stores actual data)
      |
      v
Repository --> Service --> Controller --> Client/Postman

    The layer responsibilities are fixed:

    Layer Responsibility
    Controller Handles HTTP requests and responses
    Service Contains business logic
    Repository Talks to the database
    Entity Represents database table structure
    Database Stores actual data

    Running against MySQL means the app reads application.properties, connects to student_crud_db at localhost:3306, and Hibernate adjusts the students table from the entity on startup. Save, fetch, find, delete, and exists calls then travel this exact path.

    16. Myth vs Reality

    Myth Reality
    "Hibernate creates the database too" Hibernate creates and updates tables; the database itself must already exist (CREATE DATABASE student_crud_db)
    "We must write CREATE TABLE students first" The entity plus ddl-auto lets Hibernate derive the table; no manual DDL is needed
    "The MySQL driver class must always be written" Spring Boot detects the driver from the dependency and JDBC URL; the explicit class is a fallback
    "save() only inserts" save() inserts when the ID is absent and updates when the ID exists
    "findAll() gives only active students" It returns all rows; soft-deleted rows are included unless you use findByIsDeletedFalse()
    "deleteById() respects the soft-delete flag" deleteById() is a hard delete; it removes the row permanently
    "ddl-auto=update is a production strategy" Production uses controlled migration tools such as Flyway or Liquibase
    "@Repository is required on a JpaRepository" Spring Data JPA detects interfaces that extend JpaRepository automatically

    17. Common Trap Questions

    Trap 1 - "Does Hibernate create the database for us?" Verdict: No. Hibernate can create or update tables inside an existing database, but the database (student_crud_db) is created once by you with CREATE DATABASE.

    Trap 2 - "We still need to write the students table by hand, right?" Verdict: No. With JPA + Hibernate and ddl-auto=update, the @Entity and @Table definitions let Hibernate create or update the table. Manual DDL is what we are avoiding.

    Trap 3 - "spring.datasource.url and the JDBC URL are unrelated." Verdict: False. spring.datasource.url holds the JDBC URL; its parts (jdbc, mysql, localhost, 3306, student_crud_db) each name a piece of the connection target.

    Trap 4 - "save() always inserts a new row." Verdict: False. save() inserts when there is no ID and updates the existing row when the ID is already present.

    Trap 5 - "findById() returns a Student directly." Verdict: False. It returns an Optional<Student>, because the student may not exist; you must handle the empty case.

    Trap 6 - "findAll() and findByIsDeletedFalse() are interchangeable." Verdict: False. In a soft-delete project findAll() can return soft-deleted students too, while findByIsDeletedFalse() returns only active ones.

    Trap 7 - "deleteById() performs a soft delete." Verdict: False. deleteById() is a hard delete and removes the row permanently; guard it with existsById() if needed.

    18. Points to Remember

    1. Hibernate manages tables from the entity; you create the database itself once with CREATE DATABASE student_crud_db.
    2. application.properties is where the datasource URL, username, password, and JPA settings connect Spring Boot to MySQL.
    3. The JDBC URL jdbc:mysql://localhost:3306/student_crud_db breaks into jdbc, mysql, localhost, 3306, and the database name.
    4. Spring Boot usually detects the MySQL driver from the dependency and URL; com.mysql.cj.jdbc.Driver is the optional explicit class.
    5. JPA is ORM: a class maps to a table, an object to a row, and fields to columns.
    6. @Entity, @Table, @Id, and @GeneratedValue mark the class as an entity, name the table, set the primary key, and auto-generate the ID.
    7. ddl-auto=update lets Hibernate create or update tables; none, validate, create, and create-drop are the other common values.
    8. JpaRepository<Student, Long> needs the entity type and the primary key type, and Spring Data JPA writes the implementation at runtime.
    9. The five key methods are save, findAll, findById, deleteById, and existsById (remember S-F-F-D-E).
    10. The request flow is Controller -> Service -> Repository -> Database, and ResponseEntity returns proper status codes (200, 201, 404).

    19. Likely Interview Questions

    Question Crisp Answer
    Why do we not create the table manually? JPA + Hibernate map the entity to the table, so ddl-auto lets Hibernate create or update it from the class.
    Does Hibernate create the database too? No. Create the database once (CREATE DATABASE student_crud_db); Hibernate manages tables inside it.
    What does spring.datasource.url do? It gives the JDBC URL that tells Spring Boot where the database is and how to connect.
    Explain jdbc:mysql://localhost:3306/student_crud_db. JDBC format, MySQL driver, local machine, default MySQL port 3306, database name student_crud_db.
    What does ddl-auto=update do? Hibernate checks the entity and updates the table structure, creating it if absent and adding new columns.
    What is @Entity for? It marks the class as a JPA entity that maps to a database table and whose objects become rows.
    What do @Id and @GeneratedValue do? @Id marks the primary key; @GeneratedValue auto-generates it (IDENTITY = database auto-increment).
    What does JpaRepository<Student, Long> mean? It provides CRUD operations for the Student entity whose primary key type is Long.
    What does findById() return and why? An Optional<Student>, because the record may or may not exist, forcing explicit not-found handling.
    Difference between findAll() and findByIsDeletedFalse()? findAll() returns all rows including soft-deleted ones; the custom method returns only active students.
    What is the request flow in this project? Controller -> Service -> Repository -> Database, and back up the same path.
    Why use ResponseEntity? To control the response body and the HTTP status code, returning 200, 201, or 404 correctly.
