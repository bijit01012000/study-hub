    Load Balancing

    6 sections · 604 words

    Spreading requests across servers while keeping the system available.

    1. What a Load Balancer Does

    A load balancer (LB) sits between the client and a pool of servers. It receives requests, tracks availability and response time, and forwards work to a server.

    Applications of LB (smart LB):

    • Scalability - works with auto scaling.
    • Availability - routes around failed servers.
    • Security - protection against DoS and DDoS, plus firewall calls.
    • Responsiveness - manages a thread pool so no server is overwhelmed.

    2. Two Families of Algorithms

    • Static LB - decides without looking at the current state of the servers.
    • Dynamic LB - decides using live information about the servers.

    3. Static LB Algorithms

    3.1 Round Robin

    Requests r1, r2, r3, r4, r5, r6 are handed out in turn to s1, s2, s3, then repeat.

    • Limitation: does not consider the load on any server.

    3.2 Weighted Round Robin

    Each server gets a weight based on its capacity (for example RAM or CPU): wt: 1, wt: 5, wt: 10 (a server with wt: 32 GB). Requests are distributed in proportion to the weights, so a heavier server gets more requests (r1, r18, and so on).

    • Limitation: still does not manage the live load on a server.

    3.3 IP Hashing

    hash(X) % n on the client IP (for example r1: IP: hash(X) = ? (MOD)) sends each client to a fixed server.

    • This makes the setup tightly coupled (stateful architecture).
    • Limitation: each user will always get the same server. Two users behind a proxy (VPN) may share an IP and therefore the same server.

    4. Dynamic LB Algorithms

    4.1 Least Connection Method

    The LB tracks the number of open connections per server and sends the next request to the one with the fewest (for example 5 conn, 5 conn, 6 conn). HTTP itself is stateless; the connection count is the live signal.

    4.2 Weighted Least Connection Method

    Each server has a weight and a connection count: wt: 1, wt: 5, wt: 10 with conn: 3, conn: 5, conn: 5. The LB picks the server with the lowest number of connections / weight.

    4.3 Least Response Time Method

    The LB compares number of active connections * response time. Example:

    Server Response time Active connections Score
    s1 12 ms 4 30
    s2 11 ms 4 44
    s3 15 ms 5 75

    The lowest score wins. An /health/check endpoint (returning an empty HTTP 200) is used to probe servers.

    4.4 Resources Method

    Each server runs an agent that reports its capacity/load. The agent has two jobs:

    1. To check if the server is up.
    2. To report, at a particular moment, the capacity or load on that server.

    The LB uses health checks (200 OK) plus signals such as active connections, response time, and latency.

    5. Layers of Load Balancing

    1. Application level LB - HTTP/HTTPS.
    2. Network layer LB - IP addresses.
    3. Global server load balancing - across data centres, using Geo-DNS.
    4. DNS load balancer - maps paths/hosts to different IPs, for example www.example.com/contact -> 123.23.23.35 (home/contact) and www.example.com/email -> 123.23.23.36 (email).

    6. Types of LB

    • Hardware LB - a dedicated appliance; used at data-centre scale (GBs of requests).
    • Software (cloud based) LB - runs on ordinary servers; Amazon's offering is the Elastic Load Balancer (AWS), which fits serverless architectures too.
