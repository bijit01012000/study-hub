    Design a Logging Framework

    15 sections · 2,008 words

    LLD Design Problems, problem 18 of 20.

    The Ask

    Build

    • log(Level, msg) plus debug / info / warn / error shortcuts.
    • Levels ordered: TRACE < DEBUG < INFO < WARN < ERROR < FATAL.
    • A call below the logger's effective level is dropped early, before the message string is built.
    • Loggers named by dotted path, com.app.svc; each may set a level, else it inherits its parent's, up to the root.
    • A record goes to the appenders on the logger and all its ancestors (additivity), unless a logger sets additive = false.
    • Appenders are pluggable sinks: console, file, rolling file, network — each with its own level.
    • Output format is swappable: plain text, JSON, or a pattern string.
    • One LogManager owns the tree and builds appenders from config.

    Skip

    • Async logging internals (name it).
    • Rotation-policy math.
    • MDC / thread-local context.
    • Distributed aggregation and search.
    • Real file IO, buffering, fsync.

    Our Model

    Named nodes, levels, additivity. A LogManager owns a tree of Loggers rooted at a RootLogger; every call gates on the effective level, makes one LogRecord, and walks the same chain calling each Appender.

    Actors and classes

    • Caller — log: Logger; log.info("started up") or log.debug(() -> heavyDump()), resolved through LogManager.getLogger("com.app.svc").
    • LogManager (singleton, factory) — root: RootLogger, loggers: Map<String, Logger>; getLogger(String name): Logger, configure(Config c): void, buildAppender(Spec s): Appender. One instance; creates missing parents down the name.
    • RootLogger — level = INFO at construction, parent = null. Level can be changed, never cleared to null; effectiveLevel() always terminates here.
    • Logger — name: String (e.g. "com.app.svc"), level: Level (null means inherit), parent: Logger, additive: boolean = true, appenders: List<Appender>; log(Level level, String msg): void, debug / info / warn / error(String msg), effectiveLevel(): Level, callAppenders(LogRecord r): void, addAppender(Appender a), setLevel(Level l). Gate: level < effectiveLevel() -> drop, build nothing.
    • Level (enum) — TRACE 10, DEBUG 20, INFO 30, WARN 40, ERROR 50, FATAL 60; toInt(): int. The gate is one int compare.
    • LogRecord — logger: String, level: Level, message: String, timestamp: Instant, thread: String, throwable: Throwable. Immutable; created only after the gate passes.
    • Appender (interface) — level: Level, layout: Formatter, filters: List<Filter>; doAppend(LogRecord r): void. Checks its own level, runs filters, then layout.format(r). Four sinks: ConsoleAppender, FileAppender, RollingFileAppender, SocketAppender. doAppend: r.level >= level && filters pass -> write(layout.format(r)). One lock or a queue per appender when many threads log.
    • Formatter (interface) — format(LogRecord r): String. The Layout strategy; each appender owns one. PlainLayout, JsonLayout, PatternLayout("%d %-5level %logger - %msg%n").
    • Filter (interface) — decide(LogRecord r): ACCEPT | DENY | NEUTRAL. LevelRangeFilter, RegexFilter, RateLimitFilter. A per-record predicate the level gate cannot express.

    Relationships

    LogManager owns 1..* loggers; each logger links to its parent up to the root. A logger owns appenders; each appender owns a formatter and filters.

    Key operations

    1. log(Level level, String msg): void — compares level against effectiveLevel() and returns at once when it is lower, before a LogRecord or a format string exists. Only then builds the record and calls callAppenders.
    2. effectiveLevel(): Level — walks parent links until a logger has a level set. The root always has one, so it never returns null. O(depth), and depth is tiny.
    3. callAppenders(LogRecord r): void — climbs the same parent chain, calling doAppend on every appender it passes. Stops the climb at the first logger with additive = false.
    4. format(LogRecord r): String — the Layout strategy — plain, JSON, or a pattern like %d %-5level %logger - %msg%n. Each appender owns its own, so one sink is JSON while another is plain.

    The walk

    • effectiveLevel(svc): svc unset -> com.app = DEBUG -> DEBUG.
    • Gate: DEBUG 20 >= DEBUG 20 yes -> pass.
    • callAppenders: svc, com.app, com, root.
    • Additive all true -> four loggers' appenders; each sink re-checks r.level >= sink.level.

    Recall drill: cover the operations column, write the four with their guarantee. Most people forget the gate reads effectiveLevel() before the message string is built.

    The One Run to Hold in Your Head

    com.app.svc has no level of its own. The root is INFO, com.app is DEBUG. Code calls svc.debug("loaded"). Does the line survive the gate? Which appenders write it, and what did the call touch on the way?

    effectiveLevel(svc) climbs to com.app = DEBUG, so 20 >= 20 passes. The record goes to appenders on svc, com.app, com and root. Nothing is built if the gate fails.

    The Change

    A SocketAppender blocks the caller thread on every flush. Wrap it in an AsyncAppender: a bounded queue plus one worker thread that drains to the real appender. On overflow, drop the oldest record or block the caller. The Logger and the real appenders never change. The dispatch chain gains a buffering link.

    What the Picture Can't Show

    The early gate. The level check runs inside log() before the LogRecord exists and before any Layout runs, so a dropped debug still pays for a "x=" + dump() argument you already built. Guard it, or hand log() a lambda.

    If They Make You Code It

    Log, effectiveLevel and callAppenders:

    class Logger {
    final String name; Level level;                // level may be null
    Logger parent; boolean additive = true;
    List<Appender> appenders = new CopyOnWriteArrayList<>();

    void log(Level level, String msg) {
        if (level.toInt() < effectiveLevel().toInt()) return; // gate
        LogRecord r = new LogRecord(name, level, msg, now());
        callAppenders(r);
    }
    void info(String m) { log(Level.INFO, m); }
    void debug(String m) { log(Level.DEBUG, m); }
    void debug(Supplier<String> m) {               // lazy: no eager concat
        if (enabled(Level.DEBUG)) log(Level.DEBUG, m.get());
    }
    boolean enabled(Level l) {                      // isXxxEnabled()
        return l.toInt() >= effectiveLevel().toInt();
    }
    Level effectiveLevel() {                        // climb to a set level
        for (Logger l = this; l != null; l = l.parent)
            if (l.level != null) return l.level;
        throw new IllegalStateException("root has no level");
    }
    void callAppenders(LogRecord r) {
        for (Logger l = this; l != null; l = l.parent) {
            for (Appender a : l.appenders) a.doAppend(r);
            if (!l.additive) break;                 // additivity stops here
        }
    }
}

    The Four Hazards

    1. Message built before the level check. log.debug("state=" + expensiveDump()) builds the string and the dump, then the gate drops them. Guard with enabled(DEBUG), or take a Supplier<String> / a "{}" placeholder so the arg is lazy.
    2. No level anywhere on the walk. A logger and every ancestor have level == null. effectiveLevel() runs off the end of the chain and NPEs, or you default to logging everything. The RootLogger is built with a non-null level and it can never be cleared.
    3. Additivity double-logging. The same ConsoleAppender is attached to com.app and to the root. A record from com.app.svc is written twice. Attach the appender once, at the root; or set additive = false on the lower logger.
    4. A slow appender stalls the caller. A SocketAppender does a blocking write on the calling thread — one slow flush freezes every request that logs. Hand off to an AsyncAppender: bounded queue + a worker thread, drop-oldest or block on overflow; a shutdown hook flushes and closes every sink.

    Name them before they are asked.

    The Three Lines They Are Watching

    1. effectiveLevel().toInt() is read before the LogRecord exists — a dropped call allocates nothing.
    2. if (!l.additive) break; — one flag ends the climb, so a root appender never double-logs.
    3. The Supplier<String> overload — "x=" + dump() only runs when the level passes.

    How the Level Gate Works

    Approach Cost when disabled Silence one package Per-record rules Where it runs Allocations, hot path
    Int threshold + return (the default) about 1 ns int compare set that logger's level not possible in log(), before the record none
    Chain of filter objects a call + a few allocations a Filter on that logger regex, rate, MDC match after the record is built a decision per record
    Per-appender level only int compare, but once per sink edit every appender not possible inside each doAppend none

    An int threshold with an early return. Cheapest possible check on the hot path, and one number silences a whole package. Add a Filter chain only for per-record predicates — a regex, a rate limit, an MDC match. Second axis: doAppend runs on the caller, or hands off to an async queue with a worker that drops or blocks when full.

    Rejection Signals

    These end the interview:

    • Building the message before the level check — a disabled debug still runs the concat and every toString().
    • A root logger with no level — effectiveLevel() walks off the chain and NPEs, or nothing is ever filtered.
    • The same appender on a logger and an ancestor with additive still true — every line lands twice.
    • A switch or instanceof on the appender type to choose a format — the Layout is not pluggable.
    • Socket or file writes on the calling thread — one slow sink stalls every thread that logs.
    • Filtering on the level of the logger that holds the appender, not the effective level of the logger that was called.

    Patterns Used

    Chain of Responsibility — the walk logger to parent to root, for the effective level and for collecting appenders. Strategy — the Formatter, and a Filter. Factory — LogManager builds appenders and layouts from config. Composite — the logger tree, named nodes each with a parent.

    Say It Like This

    "One Logger per dotted name, kept in a map by a LogManager, each linked to its parent up to a Root that always has a level. A call checks its effective level — the nearest set level up the chain — and returns before building anything if it is too low. Otherwise it makes one LogRecord and walks the same chain, handing it to every Appender it passes, stopping if a logger sets additive false. Each appender has its own level and a Formatter."

    The Follow-ups That Decide It

    1. svc unset, com.app = DEBUG, root = INFO. Walk svc.debug. effectiveLevel climbs to com.app = DEBUG, 20 >= 20 passes; appenders from svc, com.app, com, root.
    2. log.debug("s=" + dump()) when DEBUG is off. The gate reads effectiveLevel().toInt() first; or a Supplier / "{}" so dump() never runs.
    3. Same appender on two loggers in one chain. additive = false on the lower, or attach it once at the root.
    4. Silence com.noisy only. Set that logger's level to WARN; the int gate does the rest.
    5. One sink JSON, another plain text. Two appenders, each with its own Formatter; the record is unchanged.
    6. A network appender is slow. Wrap it in an AsyncAppender: bounded queue + worker, drop-oldest or block.
    7. Logs lost when the process is killed. A shutdown hook that flushes and closes every appender in the tree.
    8. Rate-limit a repeating line to 1 in 100. A RateLimitFilter on that logger or appender; Strategy, no core change.

    Deliberately Not Built

    • Async logging internals — a ring buffer, batching, back-pressure tuning. Named as AsyncAppender, one worker, not built out.
    • Rotation-policy math — size and time rollover, compression, retention counts. A RollingPolicy seam only.
    • MDC / thread context — a per-thread map folded into every record. One more LogRecord field later.
    • Distributed aggregation — shipping to a log store, indexing, query. That is the HLD version.
    • Real IO — buffered writers, fsync, file handles. Appenders write to an abstract sink.
