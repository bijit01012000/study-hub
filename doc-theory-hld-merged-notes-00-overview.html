    HLD Merged Notes

    1 sections · 363 words

    These notes are a merged set of high-level design (HLD) slides that walk from the raw building blocks of a web system all the way to full design questions. They start with the client-server model and the tiers that grow around it, then move into the classic trade-offs (CAP, availability, back-of-the-envelope math), architecture styles (monolith vs microservice), and the core infrastructure tools (sharding, consistent hashing, load balancing, rate limiting, queues, and caching). After that comes a run of end-to-end design walkthroughs, including a URL shortener, a notification system, an autocomplete engine, and an Instagram-style feed. Everything in HLD has one underlying goal: making the application scale better.

    Topics

    Foundations

    • Scalability and System Evolution - client-server tiers, DNS, HTTP, load balancers, DB scaling, cache, CDN, proxies, statelessness, data centres, queues, and sharding.
    • CAP Theorem - consistency, availability, partition tolerance, and the availability numbers behind "number of nines".
    • Back-of-the-Envelope Estimation - QPS, storage, peak traffic, and the power-of-two scale for an Instagram-sized workload.

    Architecture

    • Monolith vs Microservices - decomposition, DB phase, communication, and DevOps phases, plus CQRS, SAGA, and the strangler pattern.

    Core Infrastructure

    • Sharding and Consistent Hashing - sharding keys, modulo hashing, the hash ring, virtual nodes, and the celebrity/hotspot problem.
    • Load Balancing - static and dynamic algorithms, health checks, layers, and hardware vs software load balancers.
    • Rate Limiting - what to limit on, response codes, headers, and the five main algorithms.
    • Messaging Queues and Kafka - queues vs pub/sub, throughput, brokers/topics/partitions, consumer groups, and RabbitMQ exchanges.
    • Caching - cache-aside, read-through, write-through, write-back, write-around, and eviction policies.

    Design Walkthroughs

    • Design a URL Shortener (Bit.Ly clone) - hashing vs base62, collision handling, redirects, and the distributed ID generator.
    • Notification System - notification types, core entities, estimation, APIs, and the async redesign.
    • Authentication and Authorization - sessions vs JWT, access and refresh tokens, password storage, and RBAC/PBAC/ACL.
    • OAuth 2.0 - signing in with a third-party provider.
    • Autocomplete Engine - top-k queries, tries, caching, and the aggregation pipeline.
    • Instagram Feed - graph data, idempotent APIs, pull vs push feeds, and the hybrid approach.
